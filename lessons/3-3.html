Cortex Code (CoCo)

Meet Snowflake’s AI coding agent: it knows your account, writes and fixes SQL for you, and explains what it did. Learn how to ask it well and how to check its work before you trust it with bank data.

40 min Intermediate Practice worksheet + 3 challenges 1 lab

Definition

Key definition

Snowflake CoCo, formerly called Cortex Code, is Snowflake’s AI coding agent. You describe what you want in plain English and it explores your account, writes the SQL or Python, runs it if you allow, explains the result and fixes errors.

The name changed in June 2026: the product launched as Cortex Code and was renamed CoCo at Snowflake Summit 2026. Docs, blogs and your project team will use both names for the same thing. The command-line tool is still called cortex.

The word agent matters. A plain chatbot answers one message at a time. An agent takes a goal such as “find the revenue by nation and show me the top five”, makes a plan, looks up which tables exist, writes the query, runs it, reads the error if there is one, corrects itself and comes back with the answer. CoCo does that, inside Snowflake, using your role.

  • Who uses it: data analysts, data engineers, ML engineers and account admins. On your project, anyone who writes SQL.
  • Status: generally available in Snowsight, in the CLI and as a desktop app; the VS Code extension went GA in August 2026. Some add-ons (MCP support, plugins, automations, the Agent SDK) are still in preview.
  • Where it lives: a panel inside Snowsight, or a terminal tool on your own laptop that connects to the account.

Think of it like a robot assistant in the library

The sky library now lends you a robot assistant. It has memorised the whole library map: every room, shelf and book title. It looks at your ID badge, so it only ever walks into rooms your badge opens. Tell it “I need last month’s deposits by city” and it writes the request slip (the SQL), hands it to the librarians, reads their answer, and explains it back to you. If a slip comes back with a mistake, it rewrites it. But it is still a robot: it sometimes picks the wrong shelf or mis-hears you, so you read every slip before it is handed in.

In the libraryRobot assistantIn Snowflake: CoCo, which knows your databases, schemas, tables and columns (the metadata)
In the libraryReads your badgeIn Snowflake: it works under your role and RBAC, so it can only see and touch what you can
In the libraryWrites the request slipsIn Snowflake: it writes SQL, Python, notebooks and Streamlit apps for you to review

Compare it with lesson 3.2’s smart reader. The smart reader (AI functions) reads books for you inside a query. The robot (CoCo) writes the queries. You will often use both: ask CoCo to write a query that calls AI_CLASSIFY.

On a bank project

Prompting CoCo well

CoCo is only as good as your instruction. A vague ask makes it guess the table, the columns and the meaning of words like “revenue”. A specific ask gets a correct query first time. The recipe: name the object, say what you want back, add the rules.

Weak promptGood promptWhy it is better
“Show me sales.”“In snowflake_sample_data.tpch_sf1, write a query that returns total l_extendedprice per n_name from lineitem, joined through orders, customer and nation. Order by total descending, top 5.”Names the database, schema, tables, columns, join path, sort and row limit. Nothing left to guess.
“Fix this.”“This query fails with ‘invalid identifier CUST_ID’. The customer table is tpch_sf1.customer. Fix the column name only; do not change the logic.”Gives the error text, the right object and a boundary on what may change.
“Explain the table.”“Explain learn_db.public.loans: list each column, its type and what it probably holds, then write a one-paragraph description I can paste into a comment.”Says the exact output format you want back.
“Make it faster.”“Suggest changes to make this query cheaper on an X-Small warehouse. Keep the result identical. Explain each change in one line.”Adds constraints: same result, small warehouse, short explanations.
“Delete old rows.”“Write, but do not run, a DELETE for rows in learn_db.public.loans with status ‘Closed’ and start_date before 2023-01-01. Show me the matching COUNT first.”Forbids running, asks for a count first. Never let it run destructive SQL unreviewed.

Extra habits that help: give one task per message; paste the exact error text; tell it which role or warehouse to use; ask it to “explain in plain English” when you do not follow the SQL; say “SQL only, no explanation” when you just want code to paste.

Review before you run

CoCo can be wrong, and on bank data a wrong query can leak, delete or mis-state money. Read every slip. Use this checklist before running or committing anything it wrote:

CheckAsk yourself
Right objectsDoes it read the exact database.schema.table you meant, not a similarly named one in dev, or a stale copy?
Right meaningDoes “revenue” or “active customer” match the bank’s definition? Are filters (status, dates, currency) what the business asked for?
Joins and duplicatesCould a join multiply rows? Sanity-check with a COUNT before and after the join.
SafetyAny DELETE, UPDATE, DROP, TRUNCATE, GRANT or ALTER? Run those only after a second person has looked, and never on production from a chat.
Data leavingDoes it copy data to a stage, file, email or external service? Bank data stays in Snowflake unless the project allows otherwise.
Test on small dataRun with LIMIT or on a small clone first, compare a few rows by hand, then run in full.
CostWill it scan a huge table with no filter, or use a large warehouse? Check the warehouse it will run on.
Own itOnce you commit it, it is your code. If you cannot explain a line, ask CoCo to explain it, then decide.
Limitations to keep in mind

It can invent a column that does not exist, choose the wrong join, or misread a vague word. It only sees what your role can see, so “no such table” may just mean “not granted to you”. It costs credits per token, so long chats and huge pasted outputs add up; admins can cap this with the daily limit parameters CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER and CORTEX_CODE_CLI_DAILY_EST_CREDIT_LIMIT_PER_USER, and usage shows in CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY and CORTEX_CODE_CLI_USAGE_HISTORY. Any query it runs also uses normal warehouse credits.

Practice worksheet

Practise being the reviewer. The loans table is a small slice of what a bank holds. Each challenge is written as a prompt you gave CoCo; write the SQL it should produce, then check it. This is exactly the habit you need: know what right looks like before you accept the robot’s slip. Open the Schema tab to see the columns.

Lab: your first session with CoCo

Explore, write, explain, break and fix, then review

About 25 minFree trial (Enterprise)

  1. Sign in to Snowsight on your trial. Look for the CoCo icon in the lower-right corner and select it; a panel opens on the right. If there is no icon or it says the feature is not enabled, ask the admin (on a trial, you) to check three things: the roles SNOWFLAKE.COPILOT_USER and SNOWFLAKE.CORTEX_USER are granted to your role, cross-region inference is enabled (see lesson 3.2, lab step 3), and a credit card is on the trial account. If it still does not appear, availability may vary by account; check the CoCo docs or your project team.

  2. Explore. Type this prompt into the CoCo panel:

    Prompt 1
List the tables in snowflake_sample_data.tpch_sf1 with a one-line description of each
and tell me how nation, customer, orders and lineitem join together.

    Expected: a list of 8 tables (customer, lineitem, nation, orders, part, partsupp, region, supplier) and a join path such as nation.n_nationkey = customer.c_nationkey, customer.c_custkey = orders.o_custkey, orders.o_orderkey = lineitem.l_orderkey. Check it against the Schema you can browse under Data » Databases.

  3. Write. Ask for a specific query and let CoCo run it (approve when it asks).

    Prompt 2
In snowflake_sample_data.tpch_sf1, write and run a query that returns n_name and
SUM(l_extendedprice) as revenue, joining nation, customer, orders and lineitem.
Order by revenue descending and return the top 5 nations. Use warehouse COMPUTE_WH.

    Expected: 5 rows, each nation with a revenue in the billions. Before accepting it, run the review checklist: the four joins use the keys from step 2, there is no accidental filter, and the ORDER BY is DESC.

  4. Explain. Ask CoCo to explain its own query so you could defend it in a review.

    Prompt 3
Explain that query line by line in plain English for a beginner. Then tell me one
way the result could be misleading.

    Expected: a line-by-line walk-through. A good answer mentions that l_extendedprice ignores discounts (l_discount), so “revenue” here is gross, not net. If CoCo does not mention it, ask “does this include discounts?” and see it correct itself.

  5. Break and fix. Open a new SQL worksheet, paste the query CoCo wrote, and change n_name to nation_name in the SELECT. Run it; it fails with “invalid identifier”. Now use the Fix button next to the error (or paste the error into the panel with “fix only the cause of this error”).

    Expected: CoCo changes nation_name back to n_name and nothing else. Read the diff: if it also rewrote joins or added filters, reject it and ask again with “change the column name only”.

  6. Review with the checklist. Ask CoCo for a safe DELETE and refuse to let it run:

    Prompt 4
Write, but do not run, a DELETE that removes rows from learn_db.public.customer_feedback
where city = 'Delhi'. Show me the COUNT of matching rows first.

    Expected: a SELECT COUNT(*) and a DELETE, both unexecuted. (The table may not exist if you dropped it in lesson 3.2; CoCo should tell you so rather than invent it.) Tick the checklist: right table, right filter, destructive, so a second person reviews before anyone runs it.

  7. Optional, only on your own laptop and your own trial: install the CLI and open a session. Type /model inside the session to see the models on offer, and exit or Ctrl+C to leave.

    curl -LsS https://ai.snowflake.com/static/cc-scripts/install.sh | sh
cortex

    Expected: a setup wizard asking you to pick or create a connection (account, user, password or key). Skip this step on any client machine.

  8. Clean up: close the CoCo panel, delete the scratch worksheet, and drop the learning database if you are done with the module.

    DROP DATABASE IF EXISTS learn_db;

    Expected: “LEARN_DB successfully dropped.” Later the usage view snowflake.account_usage.cortex_code_snowsight_usage_history will show what this session cost.

Key takeaway

Remember

CoCo is a robot assistant that knows the library map and your badge, and writes the SQL for you. Ask it specifically, let it explain, and read every slip before it is handed in. On bank data, you are the reviewer, always.

Glossary

CoCo
Snowflake’s AI coding agent, formerly Cortex Code. Runs in Snowsight, a CLI, a desktop app and VS Code.
Agent
An AI that plans and carries out several steps toward a goal, not just one reply.
Metadata
Information about the data: names of databases, schemas, tables and columns. CoCo reads it to write correct SQL.
Prompt
Your instruction to CoCo. Specific prompts name the objects, the output and the rules.
Plan Mode
A CoCo mode that plans a multi-step task read-only and waits for your approval before doing anything.
Diff
A side-by-side view of what CoCo wants to change in your file. Read it before accepting.
Snowflake Copilot
The earlier chat assistant in Snowsight. It is being replaced by CoCo.
connections.toml
The file at ~/.snowflake/connections.toml that stores named connections for the CLI tools.
