Definition

Key definition

Snowflake Cortex is the set of AI features built into Snowflake. Cortex AI functions are SQL functions that send text to a large language model (LLM) running inside Snowflake and return the answer as a column.

An LLM (large language model) is the kind of AI behind chat assistants. It can read a sentence and tell you what it means, how the writer feels, which category it belongs to, or say it again in another language. Normally you would copy your data into a separate AI tool to get that. With Cortex you do not: the model runs inside Snowflake, next to your tables.

That matters enormously for a bank. Customer complaints, call notes and emails are private data. With Cortex they stay under the same roles, masking policies and audit logs as every other table. Nothing is copied to an outside service, and Snowflake states that your data is not used to train the models.

  • Call it like any function: SELECT AI_SENTIMENT(feedback_text) FROM complaints, one result per row.
  • No setup: no API keys, no servers, no model to download. You need a role with the right database role granted (see the lab).
  • Pay by tokens: you pay for the amount of text read and written, not per user.

Think of it like a smart reader in the library

Our sky library now has a new member of staff: a smart reader librarian. Hand her any book from any shelf and she reads it on the spot. Ask her “Is this reader angry or happy?”, “Which topic is this about: fees, cards, loans or service?”, “Give me the short version”, or “Say this in Hindi”. She answers in seconds, and the book never leaves the building. Your ID badge still decides which shelves you may bring her books from.

In the librarySmart reader librarianIn Snowflake: the Cortex AI functions (AI_SENTIMENT, AI_CLASSIFY, AI_SUMMARIZE_AGG, AI_TRANSLATE, AI_COMPLETE)
In the libraryHer reading timeIn Snowflake: tokens. Longer text costs more; you pay per million tokens, by model
In the libraryThe book stays insideIn Snowflake: data is governed by your roles, masking and audit logs as usual

Two helpers work beside her and we meet them later in this lesson: Cortex Analyst, who turns a plain-English question into a proper request slip using the official catalogue, and Cortex Search, a super index that finds passages by meaning, not just exact words.

The AI functions you will use

Snowflake calls this family Cortex AI Functions (older docs say AISQL or LLM functions). Their names start with AI_. The most useful ones for a bank project:

FunctionWhat it doesShape of the callReturns
AI_SENTIMENTJudges the mood of text, overall and per topic if you list topicsAI_SENTIMENT(text [, categories])Object: positive, negative, neutral, mixed or unknown per category
AI_CLASSIFYPuts text (or an image) into categories you nameAI_CLASSIFY(text, ['A','B','C'])Object with a labels array
AI_FILTERAnswers a yes/no question about text, for use in WHEREAI_FILTER(PROMPT('… {0}', col))BOOLEAN
AI_SUMMARIZE_AGGSummarises a whole column across many rowsAI_SUMMARIZE_AGG(text) with GROUP BYOne summary string per group
AI_AGGLike SUMMARIZE_AGG but you give the instructionAI_AGG(text, 'instruction')String
AI_TRANSLATETranslates text; empty source code means auto-detectAI_TRANSLATE(text, 'en', 'hi')String

Other members of the family: AI_SUMMARIZE (one row at a time, preview), AI_EMBED and AI_SIMILARITY (compare meaning), AI_PARSE_DOCUMENT (read PDFs), AI_TRANSCRIBE (audio), AI_REDACT (remove personal data) and AI_COUNT_TOKENS (estimate cost before you run).

Older names you will see in existing code

The first generation lived in the SNOWFLAKE.CORTEX schema: SNOWFLAKE.CORTEX.COMPLETE, SUMMARIZE, SENTIMENT, TRANSLATE, CLASSIFY_TEXT, EXTRACT_ANSWER. They still run, but the docs say to start new work with the AI_ versions, and the legacy COMPLETE is due to be deprecated by the end of 2026. One difference to remember: SNOWFLAKE.CORTEX.SENTIMENT returns a number from −1 to 1, while AI_SENTIMENT returns labels such as positive or negative.

Real syntax

Read these like sentences to the smart reader. Each runs on one row at a time unless it ends in _AGG.

-- 1. Mood of each complaint (overall label lives at categories[0].sentiment)
SELECT feedback_text,
       AI_SENTIMENT(feedback_text):categories[0]:sentiment::STRING AS mood
FROM learn_db.public.customer_feedback;

-- 2. Sort into bank topics you choose
SELECT feedback_text,
       AI_CLASSIFY(feedback_text, ['Fees','Card','Loan','Service']):labels[0]::STRING AS topic
FROM learn_db.public.customer_feedback;

-- 3. Keep only rows where the AI says yes
SELECT * FROM learn_db.public.customer_feedback
WHERE AI_FILTER(PROMPT('The customer is asking for a refund: {0}', feedback_text));

-- 4. One summary per city
SELECT city, AI_SUMMARIZE_AGG(feedback_text) AS city_summary
FROM learn_db.public.customer_feedback
GROUP BY city;

-- 5. Translate, and free-form chat with a model you name
SELECT AI_TRANSLATE(feedback_text, 'en', 'hi') AS hindi,
       AI_COMPLETE('llama3.1-8b', 'Reply in one polite sentence to: ' || feedback_text) AS draft_reply
FROM learn_db.public.customer_feedback;

Notice the :categories[0]:sentiment::STRING and :labels[0]::STRING parts. AI_SENTIMENT and AI_CLASSIFY return a small JSON object, and this is how Snowflake reaches inside it to pull out one plain value. || joins text together, so the prompt in query 5 changes for every row.

The wider Cortex family

AI functions are the part you call from SQL. Snowflake Cortex also includes bigger building blocks. You will mostly hear their names on the project rather than build them yourself, so recognise what each one is for.

Cortex AnalystLets a business user ask “What were total deposits in Mumbai last month?” in plain English. It writes the SQL using a semantic view, a catalogue that explains what each table and column means, then runs it and returns the answer. Billed per message when used on its own.The helper with the official catalogue
Cortex SearchA managed search service over text columns. It finds passages by meaning (vector search) and by keywords together, so “card stuck in machine” also finds “ATM kept my debit card”. Created with CREATE CORTEX SEARCH SERVICE; billed by indexed size and tokens.The super index
Cortex AgentsAn agent combines Analyst, Search and custom tools, plans several steps and answers a complex question. Cost is the sum of the tools it calls.A helper who sends other helpers
Snowflake CoWorkThe ready-made chat screen where business users talk to agents. It was called Snowflake Intelligence until 2026, and you will hear both names.The front desk where the public asks

Cost, roles and regions

TopicWhat to know
TokensA token is roughly four characters. AI functions are billed in credits per million tokens, and the rate depends on the model. For functions that write text back (COMPLETE, CLASSIFY, SUMMARIZE, TRANSLATE) both input and output tokens count.
Warehouse still runsThe query still needs a virtual warehouse, so the librarians’ wages apply as usual. Snowflake advises a warehouse no larger than Medium: bigger ones do not speed the AI up.
Who may call themYour role needs the SNOWFLAKE.CORTEX_USER database role (or AI_FUNCTIONS_USER). Admins grant it; on a bank project ask your team lead which roles have it.
Where to see the billThe view SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY shows credits per function, model and query (usage from January 2026 on). Older accounts may also show the earlier CORTEX_FUNCTIONS_USAGE_HISTORY view.
RegionsEach model is hosted in certain cloud regions. If your account’s region does not host the model you asked for, the call fails unless cross-region inference is switched on.
Cross-region inference

An ACCOUNTADMIN can run ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION'; (or a narrower value such as 'AWS_EU' or 'AWS_US'; 'DISABLED' turns it off). The request is then processed in another region while your data stays stored in your home region. A bank may forbid this for data-residency reasons, so never change it yourself on a client account: check with the project team.

In practice: a bank

A global bank receives thousands of pieces of free text every day. Before Cortex, a team read samples by hand. Now one SQL query does the first pass over every row:

Text arrivingFunctionWhat the bank gets
Complaints from app, phone, email and branchAI_CLASSIFY into Fees, Card, Loan, ServiceA complaint count per topic per week, so the right team owns each pile
Survey answers after a branch visitAI_SENTIMENTA mood score per branch and city; falling scores trigger a visit
Call-centre notes, thousands per dayAI_SUMMARIZE_AGG grouped by productOne paragraph per product for the Monday management pack
Feedback in Hindi, Tamil, SpanishAI_TRANSLATEEverything in English for the central quality team
“Which customers threatened to close their account?”AI_FILTER in WHEREA short list for the retention team, same morning

Because the text never leaves Snowflake, the compliance team approves this far more easily than a plan to send complaints to an outside AI service. The usual masking policies still apply, so a role that cannot see the customer name still cannot see it here.

Lab: run real AI functions on your own table

Sentiment, classification, summary and translation in Snowsight

About 20 minFree trial (Enterprise)

  1. Sign in to your trial and open a SQL worksheet. Check you have the right role and that AI functions are allowed in your region. Trial accounts may need a credit card added by the admin before AI features are switched on; if step 4 fails with a permission or region error, that is the first thing to check.

    USE ROLE ACCOUNTADMIN;
USE WAREHOUSE COMPUTE_WH;
SELECT CURRENT_REGION();

    Expected: one row naming your region, for example AWS_AP_SOUTHEAST_1.

  2. Create a small learning database and a feedback table, then insert a few rows of fictional bank feedback.

    CREATE DATABASE IF NOT EXISTS learn_db;
CREATE OR REPLACE TABLE learn_db.public.customer_feedback (
  feedback_id NUMBER, city VARCHAR, feedback_text VARCHAR);

INSERT INTO learn_db.public.customer_feedback VALUES
  (1, 'Mumbai',  'The app crashed twice while I was paying my credit card bill'),
  (2, 'Delhi',   'Staff at the branch were friendly and sorted my loan papers quickly'),
  (3, 'Chennai', 'I was charged an annual fee I was never told about'),
  (4, 'Mumbai',  'Transfers are instant now, great update'),
  (5, 'Delhi',   'Waited 40 minutes on hold to block my lost card');

    Expected: “Table CUSTOMER_FEEDBACK successfully created” then “number of rows inserted: 5”.

  3. Optional, only on your own trial: if your region does not host the models, allow cross-region inference. Never run this on a client account without approval.

    ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

    Expected: “Statement executed successfully.” Requires ACCOUNTADMIN.

  4. Ask the smart reader for the mood and the topic of every row.

    SELECT feedback_id, feedback_text,
       AI_SENTIMENT(feedback_text):categories[0]:sentiment::STRING AS mood,
       AI_CLASSIFY(feedback_text, ['Fees','Card','Loan','Service']):labels[0]::STRING AS topic
FROM learn_db.public.customer_feedback
ORDER BY feedback_id;

    Expected: 5 rows. Rows 2 and 4 should be positive, the rest negative; row 3 should be Fees and rows 1 and 5 Card. AI answers can vary slightly between runs, which is normal. If you see “Unknown function AI_SENTIMENT” or a region message, re-check step 1 and step 3, or ask an admin.

  5. Summarise per city and translate one row. Then chat with a named model.

    SELECT city, AI_SUMMARIZE_AGG(feedback_text) AS city_summary
FROM learn_db.public.customer_feedback
GROUP BY city;

SELECT AI_TRANSLATE(feedback_text, 'en', 'hi') AS hindi
FROM learn_db.public.customer_feedback WHERE feedback_id = 4;

SELECT AI_COMPLETE('llama3.1-8b',
  'In one sentence, explain to a new bank analyst what a token is in Snowflake Cortex.') AS answer;

    Expected: 3 city rows with a short paragraph each; one row of Hindi text; one plain-English sentence. If llama3.1-8b is not offered in your region, try claude-sonnet-4-5 with cross-region inference on, or check the model availability page in the docs.

  6. See what it cost. Usage appears in the account usage view after a delay of up to a few hours, so come back later if it is empty.

    SELECT function_name, model_name, token_credits, tokens
FROM snowflake.account_usage.cortex_functions_usage_history
ORDER BY start_time DESC
LIMIT 20;

    Expected: one row per function and model you called, with tiny credit amounts. This is the view a bank’s FinOps team watches.

  7. Clean up so the trial does not keep anything you no longer need.

    DROP TABLE IF EXISTS learn_db.public.customer_feedback;

    Expected: “CUSTOMER_FEEDBACK successfully dropped.” Keep learn_db; the next lesson uses it.

Key takeaway

Remember

Cortex AI functions are a smart reader inside the library: call AI_SENTIMENT, AI_CLASSIFY, AI_SUMMARIZE_AGG, AI_TRANSLATE or AI_COMPLETE from plain SQL, the data never leaves Snowflake, and you pay by the tokens read and written.

Glossary

Snowflake Cortex
The umbrella name for AI features inside Snowflake: AI functions, Analyst, Search, Agents and CoCo.
LLM
Large language model: an AI that reads and writes text. Cortex hosts several, from Snowflake, Meta, Mistral, Anthropic, OpenAI and others.
AI function
A SQL function whose name starts with AI_ and whose answer comes from an LLM.
Token
The unit AI is billed in, roughly four characters of text.
Prompt
The instruction you give the model, for example the text after AI_COMPLETE’s model name.
Semantic view
A catalogue that explains tables and columns in business words so Cortex Analyst can write correct SQL.
Cross-region inference
Letting Snowflake process an AI request in another region when your own region lacks the model. Set by ACCOUNTADMIN.
CORTEX_USER
The database role a user needs before AI functions will run for them.
