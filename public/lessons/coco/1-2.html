Where CoCo runs and setup

CoCo lives in four places: Snowsight, a desktop app, a command-line tool and VS Code. Learn which one to use, switch CoCo on in your trial, and build the database for the course project, the Bank Churn Predictor.

30 min Beginner Practice worksheet + 3 challenges 1 lab + project step P1

By the end of this lesson you can

  • Name the four places CoCo runs and pick the right one
  • List the roles and settings CoCo needs, so you know what to ask an admin
  • Switch CoCo on in your own trial account
  • Create BANK_DS and load the project data, with CoCo and with a vetted script

Definition

Key definition

A CoCo surface is a place where you talk to CoCo. There are four: Snowsight (in the browser), CoCo Desktop (an app), the CoCo CLI (a terminal tool) and the Snowflake extension for VS Code. All of them talk to the same Snowflake account under your role.

Setup means two things: the account must allow CoCo (region and AI settings), and your role must hold the right database roles. Get both right once, and every surface works.

Think of it like doors into the library

The robot assistant lives in the library, but you can call it from different doors. The front desk (Snowsight) is easiest: walk in and it is there. The robot can also visit your home office (Desktop or CLI), where it sees your own papers (local files) as well as the library. Or it can sit next to you in your favourite workshop (VS Code).

On a bank project

Client laptops are locked down, and the client decides which surfaces are approved. Do not install the CLI or Desktop on a client machine, or connect them to a client account, until your project lead says yes. Snowsight needs no install, so it is usually the approved choice.

If CoCo returns a permissions error, the docs say to check your default role: CoCo starts each session with it. You can ask CoCo to switch roles inside a chat.

In practice: a bank

On day one at a bank, you will not be ACCOUNTADMIN. You will get a project role, for example DS_CHURN_ROLE. Send your admin a short, precise request rather than "CoCo does not work":

Hi, I am on the churn project. To use CoCo in Snowsight, could you confirm that:
1. my default role DS_CHURN_ROLE has SNOWFLAKE.CORTEX_USER (or CORTEX_AGENT_USER),
2. it has SNOWFLAKE.COPILOT_USER, if our account still needs it,
3. cross-region inference is allowed for our account, and
4. CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER is not 0 for me.
Thank you!

Some banks deliberately turn cross-region inference off, because data must not leave a region. If so, CoCo may only offer the models hosted in your region, or may not be available. That is a policy decision; respect it.

Lab: switch CoCo on in your trial

Enable AI, grant the roles, open the panel

About 10 minYour Snowflake trial

  1. In Snowsight, open Admin » Billing (on some accounts, Admin » Billing & Terms) and add a payment card. This turns on AI features in a self-service trial. It does not upgrade the trial or end your free credits.

    Expected: the card is saved. If your menu looks different, search the Snowsight help for "payment method"; menu names may vary by account.

  2. Open a new SQL file in Projects » Workspaces and run this as ACCOUNTADMIN:

    USE ROLE ACCOUNTADMIN;
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE ACCOUNTADMIN;
GRANT DATABASE ROLE SNOWFLAKE.COPILOT_USER TO ROLE ACCOUNTADMIN;
SHOW PARAMETERS LIKE 'CORTEX_CODE%' IN ACCOUNT;

    Expected: "Statement executed successfully" for the first four, then a list of CORTEX_CODE parameters. The daily limits should show -1 (no limit). If a GRANT says the role is already granted, that is fine.

  3. Refresh the page and select the CoCo icon in the lower-right corner. Ask: "Am I set up correctly to use you? Check my role and grants."

    Expected: the panel opens and CoCo answers, maybe after running SELECT CURRENT_ROLE() or SHOW GRANTS. If the icon is still missing, sign out and in again; if it is still missing, availability may vary by account, so check the CoCo docs.

  4. Find the model selector at the lower right of the message box. Leave it on Auto for this course.

    Expected: a list such as Auto, Auto Intelligent, Auto Efficient and named models. The list depends on your role and region.

Project step P1: create the project database and load data

What we build and why

The Bank Churn Predictor needs a home. In P1 you create warehouse LEARN_WH, database BANK_DS with five schemas (RAW, CLEAN, FEATURES, ML, APP), and load three synthetic bank tables into RAW. Every later step reads from here: P2 explores RAW, P3 cleans it into CLEAN, P4 builds FEATURES, P5 and P6 train and score in ML, P7 builds a dashboard in APP.

The data is fake but realistic, and it has the problems real bank data has: about 2% of ages are missing and 30 customers were loaded twice. Churn is not random: it is higher for inactive members, short tenure, customers with one product and customers who raise many support tickets. That is what lets a model learn it in P5.

Path A: ask CoCo to write it

Open a new SQL file in Workspaces, open the CoCo panel, and paste this prompt:

Write, but do not run, one Snowflake SQL script that:
1. Creates warehouse LEARN_WH (XSMALL, AUTO_SUSPEND = 60, AUTO_RESUME = TRUE) if missing,
   database BANK_DS and schemas RAW, CLEAN, FEATURES, ML, APP.
2. Creates BANK_DS.RAW.CUSTOMERS with 5,000 synthetic rows using TABLE(GENERATOR(ROWCOUNT => 5000))
   and UNIFORM with RANDOM(seed), a different fixed seed per column. Columns: CUSTOMER_ID NUMBER,
   AGE NUMBER, CITY VARCHAR, SEGMENT VARCHAR ('RETAIL','PRIORITY','BUSINESS'), TENURE_MONTHS NUMBER,
   NUM_PRODUCTS NUMBER, HAS_CREDIT_CARD BOOLEAN, IS_ACTIVE_MEMBER BOOLEAN,
   ESTIMATED_SALARY NUMBER(12,2), BALANCE NUMBER(12,2), JOINED_ON DATE, CHURNED BOOLEAN.
   CHURNED must be more likely when inactive, tenure under 12 months, 1 product, or many tickets.
   Set AGE to NULL for about 2% of rows and append 30 duplicate CUSTOMER_ID rows.
3. Creates RAW.TRANSACTIONS (about 100,000 rows in the 12 months up to 2026-09-30; TXN_TYPE in
   DEPOSIT, WITHDRAWAL, TRANSFER, UPI, CARD) and RAW.SUPPORT_TICKETS (about 8,000 rows; CATEGORY in
   FEES, CARD, LOAN, APP, SERVICE; RESOLVED BOOLEAN).
4. Ends with row-count checks. Explain each step in one comment line.

Path B: the vetted script

CoCo's script will differ from person to person. So that everyone on this course has the same tables with the same columns and the same data problems, run this vetted script. If CoCo wrote something different, keep its script for comparison, but load the data with this one. It is safe to re-run.

-- Bank Churn Predictor, project step P1: setup and synthetic data
-- Safe to re-run: every object uses IF NOT EXISTS or CREATE OR REPLACE.
USE ROLE ACCOUNTADMIN;

-- 0. Warehouse, database and the five schemas
CREATE WAREHOUSE IF NOT EXISTS LEARN_WH
  WAREHOUSE_SIZE = 'XSMALL' AUTO_SUSPEND = 60 AUTO_RESUME = TRUE INITIALLY_SUSPENDED = TRUE;
USE WAREHOUSE LEARN_WH;
CREATE DATABASE IF NOT EXISTS BANK_DS;
CREATE SCHEMA IF NOT EXISTS BANK_DS.RAW;
CREATE SCHEMA IF NOT EXISTS BANK_DS.CLEAN;
CREATE SCHEMA IF NOT EXISTS BANK_DS.FEATURES;
CREATE SCHEMA IF NOT EXISTS BANK_DS.ML;
CREATE SCHEMA IF NOT EXISTS BANK_DS.APP;
USE SCHEMA BANK_DS.RAW;

-- 1. One random draw per column, each with its own fixed seed
CREATE OR REPLACE TEMPORARY TABLE CUST_DRAWS AS
SELECT
  ROW_NUMBER() OVER (ORDER BY SEQ4())       AS CUSTOMER_ID,
  UNIFORM(18, 75, RANDOM(101))              AS AGE,
  UNIFORM(1, 6, RANDOM(102))                AS CITY_N,
  UNIFORM(1, 100, RANDOM(103))              AS SEGMENT_N,
  UNIFORM(1, 120, RANDOM(104))              AS TENURE_MONTHS,
  UNIFORM(1, 100, RANDOM(105))              AS PRODUCTS_N,
  UNIFORM(1, 100, RANDOM(106))              AS CARD_N,
  UNIFORM(1, 100, RANDOM(107))              AS ACTIVE_N,
  UNIFORM(15000, 250000, RANDOM(108))       AS SALARY_N,
  UNIFORM(1, 100, RANDOM(109))              AS BALANCE_N,
  UNIFORM(1000, 900000, RANDOM(110))        AS BALANCE_AMT,
  UNIFORM(0, 99, RANDOM(111))               AS PAISE,
  UNIFORM(0::FLOAT, 1::FLOAT, RANDOM(112))  AS CHURN_DRAW,
  UNIFORM(1, 100, RANDOM(113))              AS TICKETS_N
FROM TABLE(GENERATOR(ROWCOUNT => 5000));

-- 2. Turn the draws into customer features (plus a hidden ticket count)
CREATE OR REPLACE TEMPORARY TABLE CUST_FEATURES AS
SELECT
  CUSTOMER_ID,
  IFF(MOD(CUSTOMER_ID, 50) = 7, NULL, AGE) AS AGE,          -- exactly 100 NULL ages (2%)
  DECODE(CITY_N, 1, 'Mumbai', 2, 'Delhi', 3, 'Bengaluru', 4, 'Chennai', 5, 'Hyderabad', 'Pune') AS CITY,
  CASE WHEN SEGMENT_N <= 70 THEN 'RETAIL' WHEN SEGMENT_N <= 88 THEN 'PRIORITY' ELSE 'BUSINESS' END AS SEGMENT,
  TENURE_MONTHS,
  CASE WHEN PRODUCTS_N <= 45 THEN 1 WHEN PRODUCTS_N <= 85 THEN 2 WHEN PRODUCTS_N <= 96 THEN 3 ELSE 4 END AS NUM_PRODUCTS,
  CARD_N <= 70   AS HAS_CREDIT_CARD,
  ACTIVE_N <= 55 AS IS_ACTIVE_MEMBER,
  SALARY_N + PAISE / 100 AS ESTIMATED_SALARY,
  IFF(BALANCE_N <= 25, 0, BALANCE_AMT + PAISE / 100) AS BALANCE,   -- about 25% hold a zero balance
  DATEADD(MONTH, -TENURE_MONTHS, '2026-09-30'::DATE) AS JOINED_ON,
  CASE WHEN TICKETS_N <= 36 THEN 0 WHEN TICKETS_N <= 66 THEN 1 WHEN TICKETS_N <= 86 THEN 2
       WHEN TICKETS_N <= 96 THEN 3 ELSE 4 END
    + IFF(ACTIVE_N <= 55, 0, 1) AS NUM_TICKETS,                  -- inactive customers complain more
  CHURN_DRAW
FROM CUST_DRAWS;

-- 3. Churn label: the chance of leaving rises with each risk factor
CREATE OR REPLACE TEMPORARY TABLE CUST_LABELLED AS
SELECT *,
  CHURN_DRAW < ( 0.05
               + IFF(IS_ACTIVE_MEMBER, 0, 0.15)
               + CASE WHEN TENURE_MONTHS < 12 THEN 0.12 WHEN TENURE_MONTHS < 24 THEN 0.05 ELSE 0 END
               + IFF(NUM_PRODUCTS = 1, 0.08, 0)
               + LEAST(NUM_TICKETS, 4) * 0.04
               + IFF(SEGMENT = 'RETAIL', 0.02, 0) ) AS CHURNED
FROM CUST_FEATURES;

-- 4. RAW.CUSTOMERS: 5,000 customers, then customers 1 to 30 loaded a second time (30 duplicates)
CREATE OR REPLACE TABLE BANK_DS.RAW.CUSTOMERS AS
WITH BASE_ROWS AS (
  SELECT CUSTOMER_ID::NUMBER(38,0)       AS CUSTOMER_ID,
         AGE::NUMBER(38,0)               AS AGE,
         CITY::VARCHAR                   AS CITY,
         SEGMENT::VARCHAR                AS SEGMENT,
         TENURE_MONTHS::NUMBER(38,0)     AS TENURE_MONTHS,
         NUM_PRODUCTS::NUMBER(38,0)      AS NUM_PRODUCTS,
         HAS_CREDIT_CARD,
         IS_ACTIVE_MEMBER,
         ESTIMATED_SALARY::NUMBER(12,2)  AS ESTIMATED_SALARY,
         BALANCE::NUMBER(12,2)           AS BALANCE,
         JOINED_ON,
         CHURNED
  FROM CUST_LABELLED
)
SELECT * FROM BASE_ROWS
UNION ALL
SELECT * FROM BASE_ROWS WHERE CUSTOMER_ID <= 30;

-- 5. RAW.TRANSACTIONS: 100,000 rows in the 12 months up to 2026-09-30.
--    Most customers who churned stopped transacting in the last 4 months.
CREATE OR REPLACE TABLE BANK_DS.RAW.TRANSACTIONS AS
WITH DRAWS AS (
  SELECT ROW_NUMBER() OVER (ORDER BY SEQ4())                      AS TXN_ID,
         UNIFORM(1, 5000, RANDOM(201))                            AS CUSTOMER_ID,
         UNIFORM(0, 364, RANDOM(202))                             AS DAYS_ANY,
         UNIFORM(120, 364, RANDOM(203))                           AS DAYS_OLD,
         UNIFORM(1, 100, RANDOM(204))                             AS SHIFT_N,
         ROUND(UNIFORM(100::FLOAT, 50000::FLOAT, RANDOM(205)), 2) AS AMOUNT,
         UNIFORM(1, 5, RANDOM(206))                               AS TYPE_N,
         UNIFORM(1, 4, RANDOM(207))                               AS CHANNEL_N
  FROM TABLE(GENERATOR(ROWCOUNT => 100000))
)
SELECT d.TXN_ID::NUMBER(38,0)        AS TXN_ID,
       d.CUSTOMER_ID::NUMBER(38,0)   AS CUSTOMER_ID,
       DATEADD(DAY, -IFF(c.CHURNED AND d.SHIFT_N <= 70, d.DAYS_OLD, d.DAYS_ANY), '2026-09-30'::DATE) AS TXN_DATE,
       d.AMOUNT::NUMBER(12,2)        AS AMOUNT,
       DECODE(d.TYPE_N, 1, 'DEPOSIT', 2, 'WITHDRAWAL', 3, 'TRANSFER', 4, 'UPI', 'CARD')::VARCHAR AS TXN_TYPE,
       DECODE(d.CHANNEL_N, 1, 'MOBILE', 2, 'NET_BANKING', 3, 'BRANCH', 'ATM')::VARCHAR AS CHANNEL
FROM DRAWS d
JOIN CUST_LABELLED c ON c.CUSTOMER_ID = d.CUSTOMER_ID;

-- 6. RAW.SUPPORT_TICKETS: NUM_TICKETS rows per customer (about 8,000 in total)
CREATE OR REPLACE TABLE BANK_DS.RAW.SUPPORT_TICKETS AS
WITH SLOTS AS (
  SELECT ROW_NUMBER() OVER (ORDER BY SEQ4()) AS SLOT FROM TABLE(GENERATOR(ROWCOUNT => 5))
),
TICKET_ROWS AS (
  SELECT c.CUSTOMER_ID, c.CHURNED, s.SLOT
  FROM CUST_LABELLED c
  JOIN SLOTS s ON s.SLOT <= c.NUM_TICKETS
)
SELECT ROW_NUMBER() OVER (ORDER BY CUSTOMER_ID, SLOT)::NUMBER(38,0) AS TICKET_ID,
       CUSTOMER_ID::NUMBER(38,0)                                    AS CUSTOMER_ID,
       DATEADD(DAY, -UNIFORM(0, 364, RANDOM(301)), '2026-09-30'::DATE) AS OPENED_ON,
       DECODE(UNIFORM(1, 5, RANDOM(302)), 1, 'FEES', 2, 'CARD', 3, 'LOAN', 4, 'APP', 'SERVICE')::VARCHAR AS CATEGORY,
       UNIFORM(1, 100, RANDOM(303)) <= IFF(CHURNED, 60, 85)         AS RESOLVED
FROM TICKET_ROWS;

-- 7. Tidy up the helper tables
DROP TABLE IF EXISTS CUST_DRAWS;
DROP TABLE IF EXISTS CUST_FEATURES;
DROP TABLE IF EXISTS CUST_LABELLED;

-- 8. Check the load
SELECT 'CUSTOMERS' AS TABLE_NAME, COUNT(*) AS ROW_COUNT FROM BANK_DS.RAW.CUSTOMERS
UNION ALL SELECT 'TRANSACTIONS', COUNT(*) FROM BANK_DS.RAW.TRANSACTIONS
UNION ALL SELECT 'SUPPORT_TICKETS', COUNT(*) FROM BANK_DS.RAW.SUPPORT_TICKETS;

SELECT COUNT(*)                                 AS CUSTOMER_ROWS,
       COUNT(DISTINCT CUSTOMER_ID)              AS DISTINCT_CUSTOMERS,
       COUNT_IF(AGE IS NULL)                    AS NULL_AGE_ROWS,
       ROUND(AVG(IFF(CHURNED, 1, 0)) * 100, 1)  AS CHURN_PCT
FROM BANK_DS.RAW.CUSTOMERS;

If CoCo gives you something different

That is normal. Check its script against the prompt: all 12 columns with the right types, the five schemas, seeds on every RANDOM, the NULL ages and the 30 duplicates, and a churn rule that uses the features. A common miss is CHURNED drawn at random with no link to the features; a model could never learn that. Whatever CoCo wrote, load the data with the vetted script so your numbers match later lessons. Snowflake's docs say RANDOM is not guaranteed to repeat exactly even with a seed, which is why counts are fixed but churn and ticket totals are "about".

Key takeaway

Remember it

Four doors, one robot: Snowsight, Desktop, CLI and VS Code all reach the same account under your role. CoCo needs CORTEX_USER (plus COPILOT_USER in Snowsight for now), cross-region inference and, on a trial, a card on file. Snowsight is the safe default on a bank project.

Glossary

Surface
A place where you use CoCo: Snowsight, Desktop, CLI or VS Code.
Database role
A role that lives inside a database. SNOWFLAKE.CORTEX_USER is one; it is granted to your account role.
Cross-region inference
An account setting that lets Snowflake run AI models in another region.
connections.toml
A file on your laptop that stores named Snowflake connections for the CLI tools.
GENERATOR
A table function that produces a given number of empty rows to fill with generated values.
UNIFORM
A function that returns a random number between a minimum and maximum.
Seed
A fixed starting number for RANDOM, so each column gets its own sequence.
Temporary table
A table that disappears when your session ends. Good for helper steps.
