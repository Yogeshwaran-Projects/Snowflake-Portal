How CoCo works

Look inside the robot: what it reads before answering, how it plans, how it asks your permission, what it remembers, and where its limits are.

Definition

Key definition

CoCo works in a loop: it gathers context (your role, your open file, the catalog), makes a plan, proposes an action, waits for your approval when the action matters, looks at the result, and repeats until the task is done.

That loop is what makes it an agent. A plain chatbot would answer from memory. CoCo looks things up in your account first, so its answer fits your real tables and columns.

Think of it like a robot with a clipboard

Before the robot assistant writes a slip, it checks its clipboard. The clipboard holds the library map, a photo of your ID badge, the page open on your desk, and the last few slips you handed in. For a big job (say, "tidy the whole customer shelf"), it first writes a plan on the clipboard and shows it to you. Only when you nod does it start. Before it changes anything on your desk, it holds up the old page and the new page side by side so you can compare.

In the libraryThe clipboardIn Snowflake: the context CoCo reads (role, open file, catalog, recent queries)
In the libraryThe planIn Snowflake: Plan mode, a list of steps you approve before work starts
In the libraryOld page vs new pageIn Snowflake: the diff view, which shows every change before it is applied

Plan mode, approvals and the diff view

For a bigger job, you want CoCo to think first and act later. Each surface does this a little differently:

SurfaceHow it asks before acting
SnowsightCoCo plans multi-step tasks, and in Workspaces it shows every file change as a diff you accept or reject. A separate Plan mode switch may vary by account; check with your project team.
CoCo CLIType /plan to turn Plan mode on and /plan-off to turn it off, or start with cortex --plan ("require approval before all actions"). Shift+Tab cycles the modes. A three-tier approval system with automatic risk assessment decides what needs your yes.
CoCo DesktopHas a Plan mode for "planning before implementing", plus permission modes that control what the agent may do without asking.
Never on bank data

The CLI has a bypass mode (/bypass or --dangerously-allow-all-tool-calls) that approves every action without asking. The docs warn about it. Never use it on a client account. Keep approvals on, so you read every slip.

What CoCo remembers, and its limits

WhereWhat is kept
SnowsightContext is kept across one chat session. The model and effort level are saved per chat. A new chat starts fresh.
CLIConversations are saved in ~/.snowflake/cortex/conversations/. /resume lists old sessions; cortex --continue resumes the latest. --private skips saving.
DesktopA Memory feature remembers context across conversations.
EverywhereAGENTS.md is the reliable way to give CoCo the same project rules every time.

Limits to keep in mind:

  • It can be wrong. The docs say suggestions "can occasionally be incorrect or not match your intent".
  • Badge-limited. A permissions error usually means your default role lacks a grant.
  • Guardrails are one-way. Once a restricted session scope (a read-only guardrail) is active in a chat, you cannot relax it in that chat. Start a new chat instead.
  • No web by default. Web search needs an ACCOUNTADMIN to switch it on.
  • Long chats cost more. Every message re-reads context, which uses tokens. Start a new chat for a new task.

In practice: a bank

A bank team keeps an AGENTS.md in its churn workspace so every analyst's CoCo follows the same rules:

# AGENTS.md for the churn workspace
- Use role DS_CHURN_ROLE and warehouse LEARN_WH.
- Read from BANK_DS.CLEAN, never write to BANK_DS.RAW.
- A churned customer = account closed or no transaction for 90 days.
- Never SELECT raw names, phone numbers or account numbers; use CUSTOMER_ID.
- Write DELETE, UPDATE, DROP or GRANT statements, but never run them.

Now every prompt starts with the team's definitions and safety rules already on the robot's clipboard. Check with your project team whether AGENTS.md is used on your account; it is the cheapest way to make CoCo consistent.

Lab: watch CoCo use its context

Mentions, quick actions, Fix and a fresh chat

About 15 minYour trial + BANK_DS from P1

  1. In Workspaces, open a new SQL file. In the CoCo panel type @ and then CUSTOMERS. Pick BANK_DS.RAW.CUSTOMERS from the list, then ask:

    Describe @BANK_DS.RAW.CUSTOMERS: list each column with its type.

    Expected: twelve columns, from CUSTOMER_ID to CHURNED, with types such as NUMBER, VARCHAR, BOOLEAN and DATE. If the table is missing, finish project step P1 in lesson 1.2 first.

  2. Paste this into the SQL file, highlight it, and choose Explain from the quick actions.

    SELECT SEGMENT, COUNT(*) AS CUSTOMERS FROM BANK_DS.RAW.CUSTOMERS GROUP BY SEGMENT ORDER BY CUSTOMERS DESC;

    Expected: a short plain-English explanation: count of customer rows per segment, biggest first. A sharp answer notes these are rows, not distinct customers.

  3. Break it on purpose: change SEGMENT to SEGMENTS in both places and run it. Select Fix in the results grid.

    Expected: a diff changing SEGMENTS back to SEGMENT and nothing else. Accept it only if the diff is that small.

  4. Start a new chat and ask: "What table were we just talking about?"

    Expected: CoCo may not know, or may guess from the open file or query history. Chat context does not carry over; that is why AGENTS.md exists.

  5. Optional, own laptop only: in the CLI, type /plan, then ask for a plan to profile BANK_DS.RAW.CUSTOMERS. Read the plan and type /plan-off.

    Expected: a numbered plan, and a request for approval before anything runs. Skip on any client machine.

Key takeaway

Remember it

CoCo checks its clipboard (role, open file, catalog, recent queries), plans, asks before acting and shows a diff. It remembers within a chat, not reliably across chats: put lasting rules in AGENTS.md. Keep approvals on; never use bypass mode on bank data.

Glossary

Context
Everything CoCo reads before it answers.
@-mention
Typing @ to attach an exact catalog object (Snowsight) or file (CLI) to your prompt.
Quick actions
Quick Edit, Format, Add to Chat and Explain on highlighted SQL.
Plan mode
A mode where CoCo plans first and needs your approval before acting.
Diff view
A side-by-side view of old and new code before a change is applied.
Bypass mode
A CLI mode that approves every action without asking. Not for bank data.
AGENTS.md
A file of project rules CoCo follows in Workspaces and the CLI.
Default role
The role your user starts with. CoCo starts each session with it.
