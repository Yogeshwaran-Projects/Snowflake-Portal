Definition

Key definition

A Snowflake Notebook is a page of cells (Python, SQL and Markdown) that runs inside Snowflake. Snowpark Python is the library you use in those cells: you describe work as a DataFrame, and Snowpark turns it into SQL that a warehouse runs next to the data.

You met Snowpark in the Fundamentals course. Here we use it the way a data scientist does every day: in a notebook, with CoCo writing much of the code. Three ideas carry the whole lesson:

  • Session: your open line to Snowflake. In a notebook you do not log in again; you ask for the session that is already there.
  • Lazy: building a DataFrame sends nothing. Only an action such as show(), collect(), count(), to_pandas() or save_as_table() runs SQL.
  • Pushdown: the work runs in the warehouse. Your Python only receives the small result, unless you pull the data out on purpose.

Think of it like librarians who also speak Python

So far you spoke to the librarians in SQL. Now they also understand Python. A notebook is your lab notebook on the reading-room desk: you write a step, try it, see the answer, write the next step. A DataFrame is a to-do list you hand the librarians: “take the transactions shelf, keep the last 90 days, total per customer”. They do nothing until you say “go”. And the robot assistant sits beside you: you say “turn this SQL into Python”, it writes the list, and you read it before saying “go”.

Two habits to check CoCo’s Python: call df.explain() to print the SQL Snowpark will send, and compare a count() from the DataFrame with a COUNT(*) from your SQL. Same number, same logic.

In practice: a bank

A bank’s analytics team holds two years of card transactions: hundreds of millions of rows. A data scientist who runs to_pandas() on that table would wait a long time, could crash the notebook’s memory, and would copy customer data into a place that is harder to govern. With Snowpark, she filters and aggregates in the warehouse, so only a few thousand summary rows reach Python, and the masking policies on columns such as card numbers still apply because the query runs in Snowflake under her role. Pull data into pandas only when it is already small, for example a sample for a chart.

Lab: your first notebook with CoCo

Open a notebook, get a session, translate SQL with CoCo

About 20 minYour trial, BANK_DS from P1 to P3

  1. In Snowsight, create a notebook. In newer accounts: Projects » Workspaces, then add a new notebook file. In older accounts: Projects » Notebooks » + Notebook, location BANK_DS.ML, warehouse LEARN_WH.

    Expected: an empty notebook. If it asks for a runtime or compute pool, take the default offered on your trial.

  2. Paste this into the first Python cell and run it:

    from snowflake.snowpark.context import get_active_session
from snowflake.snowpark import functions as F

session = get_active_session()
session.use_warehouse("LEARN_WH")
customers = session.table("BANK_DS.CLEAN.CUSTOMERS")
customers.show(5)
print(customers.count())

    Expected: 5 customer rows, then about 5000. Nothing ran until show(); that was the lazy DataFrame at work.

  3. Open the CoCo panel and ask for a conversion:

    Convert this SQL to a Snowpark DataFrame in my notebook, using F for functions:
SELECT SEGMENT, COUNT(*) AS CUSTOMERS, AVG(IFF(CHURNED, 1, 0)) AS CHURN_RATE
FROM BANK_DS.CLEAN.CUSTOMERS GROUP BY SEGMENT ORDER BY CHURN_RATE DESC;
Then call explain() so I can see the SQL it generates.

    Expected: a chain with group_by("SEGMENT"), F.count and an average of a 0/1 expression (for example F.iff(F.col("CHURNED"), 1, 0)), then a printed SQL plan. Run the SQL version in a SQL cell and confirm the numbers match.

  4. Ask the reverse: “Convert the DataFrame in the cell above back to plain SQL and explain each line.” Then ask: “Is there any to_pandas() call here that could pull too much data?”

    Expected: plain SQL equal to the original, and an answer that the only data leaving Snowflake is the small grouped result.

Key takeaway

Remember

A notebook is your lab book; a DataFrame is a lazy to-do list the warehouse runs. Let CoCo write and translate the code, then check it with explain() and a matching count. Keep big data in Snowflake.

Glossary

Notebook
A page of Python, SQL and Markdown cells that runs inside Snowflake.
Session
Your connection to Snowflake in Python. get_active_session() returns it in a notebook.
DataFrame
A description of a query, built step by step. Lazy until an action.
Action
A call that runs SQL: show, collect, count, to_pandas, save_as_table.
Pushdown
Running the work in the warehouse, next to the data, instead of in your Python.
explain()
Prints the SQL and plan a DataFrame will run. Your best tool for checking CoCo’s code.
Container Runtime
The compute that runs notebook Python on a compute pool, with ML packages preinstalled.
Python worksheet
A Snowsight script with a main(session) handler that returns a result.
