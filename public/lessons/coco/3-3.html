Definition

Key definition

Training a model means showing it many past examples (features plus the known answer) so it learns a rule for guessing the answer on new examples. Snowpark ML (snowflake.ml.modeling) trains familiar models such as XGBoost and logistic regression directly on Snowflake tables.

Our model is a classifier: it answers a yes/no question, “will this customer churn?”. It gives a probability between 0 and 1, and we turn that into yes or no with a threshold (0.5 by default).

  • Train set (80%): the examples the model learns from.
  • Test set (20%): examples it never saw. We grade it only on these.
  • Metric: a score that says how good the guesses are. One score is never enough.

Think of it like training a guesser with flash cards

The library trains a new helper to guess which members will stop coming. You show it 4,000 old clue cards with the answer on the back. It learns patterns: “no visits for months plus unanswered complaints usually means gone”. Then comes the exam: 1,000 cards it has never seen, answers hidden. If you tested it on the cards it practised with, it could just remember them and look like a genius. The robot assistant writes the training and exam code for you, but you decide which exam score matters.

The four metrics, in plain words

Picture a smoke alarm for churn. It can ring correctly, ring for nothing, or stay silent during a real fire.

MetricQuestion it answersSmoke alarm versionFormula
AccuracyOf all guesses, how many were right?How often the alarm was correct, ringing or silent(TP + TN) / all
PrecisionWhen it says “will churn”, how often is it right?When it rings, is there really a fire?TP / (TP + FP)
RecallOf the real churners, how many did it catch?Of all real fires, how many made it ring?TP / (TP + FN)
ROC AUCHow well does it rank churners above stayers?Pick one fire and one non-fire: how often is the fire scored hotter?0.5 = coin flip, 1.0 = perfect

TP = true positive (said churn, did churn). FP = false positive (said churn, stayed). FN = false negative (said stay, churned). TN = true negative.

Class imbalance: the 80% trap

If 20% of customers churn, a lazy model that always says “stays” is 80% accurate and catches nobody: recall 0. That is why we look at recall, precision and ROC AUC, not accuracy alone. Fixes: give churners more weight (scale_pos_weight in XGBoost = stayers / churners), or lower the threshold (for example 0.3) so more customers are flagged. The bank chooses the balance: calling a happy customer costs little, losing an unhappy one costs a lot.

Two models to know

LogisticRegressionsnowflake.ml.modeling.linear_model. A simple, explainable baseline. Needs no missing values, so fill nulls first.Start here as a baseline
XGBClassifiersnowflake.ml.modeling.xgboost. Many small decision trees added together. Strong on tabular bank data, handles missing values itself.Our project model

Both take the same three arguments: input_cols (the feature columns), label_cols (the answer column) and output_cols (the name of the prediction column). fit(train_df) trains in Snowflake; predict(df) adds the 0/1 guess; predict_proba(df) adds probability columns whose names start with predict_proba_.

In practice: a bank

A bank’s retention team can call 200 customers a week. A model with high precision in its top 200 means callers rarely waste time on happy customers. Model risk teams will ask for ROC AUC on held-out data, a comparison with a simple baseline, the threshold chosen and why, and proof that no feature leaks. Many banks also require explainable features, which is why we keep a logistic regression baseline next to XGBoost and look at feature importance.

2. Prompt CoCo in the notebook:

Using snowflake.ml.modeling, train an XGBClassifier on BANK_DS.FEATURES.CUSTOMER_FEATURES.
Label CHURNED. Use every numeric feature except CUSTOMER_ID (no CITY or SEGMENT).
Split 80/20 with random_split seed 42. Weight churners with scale_pos_weight.
Report accuracy, precision, recall and ROC AUC on the test set using

3. The vetted code (one cell, or split it into cells):

from snowflake.snowpark.context import get_active_session
from snowflake.snowpark import functions as F
from snowflake.ml.modeling.xgboost import XGBClassifier
from snowflake.ml.modeling.metrics import accuracy_score, precision_score, recall_score, roc_auc_score

session = get_active_session()
session.use_warehouse("LEARN_WH")
df = session.table("BANK_DS.FEATURES.CUSTOMER_FEATURES")

FEATURES = ["AGE", "AGE_MISSING", "TENURE_MONTHS", "NUM_PRODUCTS", "HAS_CREDIT_CARD",
            "IS_ACTIVE_MEMBER", "ESTIMATED_SALARY", "BALANCE", "TXN_COUNT_90D",
            "TOTAL_AMOUNT_90D", "AVG_TXN_AMOUNT", "DAYS_SINCE_LAST_TXN",
            "TICKET_COUNT", "UNRESOLVED_TICKETS"]
LABEL = "CHURNED"

train_df, test_df = df.random_split([0.8, 0.2], seed=42)
train_df = train_df.cache_result()      # freeze the split so it does not change between actions
test_df = test_df.cache_result()

n_pos = train_df.filter(F.col(LABEL) == 1).count()
n_neg = train_df.count() - n_pos

model = XGBClassifier(
    input_cols=FEATURES, label_cols=[LABEL], output_cols=["PREDICTED_CHURN"],
    n_estimators=200, max_depth=4, learning_rate=0.1,
    scale_pos_weight=n_neg / n_pos, random_state=42,
)
model.fit(train_df)

pred = model.predict(test_df)
proba = model.predict_proba(test_df)
print(proba.columns)                       # see the exact probability column names
P1 = [c for c in proba.columns if "PROBA" in c.upper() and c.strip('"').endswith("1")][0]

print("accuracy ", accuracy_score(df=pred, y_true_col_names=LABEL, y_pred_col_names="PREDICTED_CHURN"))
print("precision", precision_score(df=pred, y_true_col_names=LABEL, y_pred_col_names="PREDICTED_CHURN"))
print("recall   ", recall_score(df=pred, y_true_col_names=LABEL, y_pred_col_names="PREDICTED_CHURN"))
print("roc_auc  ", roc_auc_score(df=proba, y_true_col_names=LABEL, y_score_col_names=P1))

Expected result: train and test counts of about 4,000 and 1,000. Four metrics between 0 and 1. On a dataset like ours, ROC AUC is usually well above 0.5 (a coin flip); recall should be clearly above 0 thanks to scale_pos_weight. Your exact numbers depend on the data built in P1 to P4. Write them down: P6 stores them with the model.

If CoCo gives you something different

It calls to_pandas() and uses sklearn or open-source xgboost: that also works on 5,000 rows inside a notebook, but it pulls the data into memory; ask it to keep snowflake.ml.modeling for this course. It includes CITY or SEGMENT: text columns need encoding first; ask it to drop them or to use OneHotEncoder from snowflake.ml.modeling.preprocessing. It includes CUSTOMER_ID or CHURNED in input_cols: reject that; an ID is not a clue and the label is the answer. ROC AUC above 0.98: suspect leakage from P4 before you celebrate. Probability column name differs: use the name printed by proba.columns.

Key takeaway

Remember

Train on 80%, grade on the 20% the model never saw. Accuracy alone lies when churners are rare: read precision, recall and ROC AUC, weight the rare class, and pick the threshold with the business.

Glossary

Classifier
A model that predicts a category, here churn yes or no.
Train / test split
Dividing rows into a learning set and an exam set. random_split([0.8, 0.2], seed=42).
Threshold
The probability above which we say “will churn”. Default 0.5.
Precision
Of those flagged, the share who really churned.
Recall
Of the real churners, the share we flagged.
ROC AUC
How well the model ranks churners above stayers. 0.5 is random, 1.0 is perfect.
Class imbalance
One answer is much rarer than the other, such as 20% churners.
scale_pos_weight
An XGBoost setting that makes each rare positive example count more. Often stayers divided by churners.
