Definition

Key definition

Streamlit is a Python library that turns a script into a web app. Streamlit in Snowflake runs that app inside your Snowflake account as a STREAMLIT object, so the data never leaves Snowflake and access is controlled by roles.

  • Script: a file, usually streamlit_app.py. Each widget is one line, such as st.metric(...).
  • Reruns: every time a viewer changes a filter, the script runs again from the top. Cache slow queries with @st.cache_data.
  • Owner’s rights: the app runs with the privileges of its owner role, not the viewer’s. Viewers only need USAGE on the app.

Think of it like the library shop window

Most visitors never walk into the back rooms. They look at the shop window at the front: a neat display of the best answers, updated every morning. Streamlit builds that window. The robot assistant arranges the display for you (the code), and the window is lit by the owner’s lamp: visitors see what the owner chose to display, not what their own badge could open. So you choose carefully what goes in the window.

Get the session the portable way

session = st.connection("snowflake").session() works in both runtimes. Older examples use get_active_session(), which works only on the warehouse runtime. If CoCo writes the old form, it still runs on our app, but ask for the portable one.

In practice: a bank

Relationship managers do not open notebooks. A bank builds them a small Streamlit app: pick your branch city, see your top 50 at-risk customers, click through to call notes. Because the app runs with owner’s rights, the bank designs it carefully: the owner role reads only a curated view, the app shows customer IDs and risk, not full names or account numbers, and a viewer role per region controls who can open it. Every app is reviewed like code before it is shared.

Project step P7: build the churn dashboard

Bank Churn Predictor · P7

We build the Streamlit in Snowflake app BANK_DS.APP.CHURN_DASHBOARD: four KPIs, average churn risk by segment, the top 50 at-risk customers, and city and segment filters. It reads ML.CHURN_SCORES from P6 and FEATURES.CUSTOMER_FEATURES from P4, so the P8 pipeline keeps it fresh automatically.

1. Create the app: Projects » Streamlit » + Streamlit App, name CHURN_DASHBOARD, location BANK_DS.APP, Run on warehouse, warehouse LEARN_WH.

2. Prompt CoCo:

Write a Streamlit in Snowflake app for BANK_DS.APP.CHURN_DASHBOARD. Get the session with
st.connection("snowflake").session(). Load BANK_DS.ML.CHURN_SCORES joined to
BANK_DS.FEATURES.CUSTOMER_FEATURES on CUSTOMER_ID (CITY, SEGMENT, BALANCE, TENURE_MONTHS,
NUM_PRODUCTS) once, cached for 10 minutes. Sidebar multiselect filters for CITY and SEGMENT.
Show 4 KPIs (customers, average churn probability, high risk count at 0.5, balance at risk),
a bar chart of average churn probability by SEGMENT, and the top 50 customers by
probability. No names or account numbers. Add a caption with the latest SCORED_AT.

3. The vetted app (paste over the sample script, then Run):

import streamlit as st

st.set_page_config(page_title="Churn dashboard", layout="wide")
st.title("Bank Churn Predictor")
session = st.connection("snowflake").session()

@st.cache_data(ttl=600)                      # one query per 10 minutes, not per click
def load():
    return session.sql("""
        SELECT s.CUSTOMER_ID, f.CITY, f.SEGMENT, f.BALANCE, f.TENURE_MONTHS,
               f.NUM_PRODUCTS, s.CHURN_PROBABILITY, s.SCORED_AT
        FROM BANK_DS.ML.CHURN_SCORES s
        JOIN BANK_DS.FEATURES.CUSTOMER_FEATURES f ON f.CUSTOMER_ID = s.CUSTOMER_ID
    """).to_pandas()                          # about 5,000 rows: small enough

df = load()
cities = st.sidebar.multiselect("City", sorted(df["CITY"].dropna().unique()))
segments = st.sidebar.multiselect("Segment", sorted(df["SEGMENT"].dropna().unique()))
view = df
if cities:
    view = view[view["CITY"].isin(cities)]
if segments:
    view = view[view["SEGMENT"].isin(segments)]

high = view[view["CHURN_PROBABILITY"] >= 0.5]
k1, k2, k3, k4 = st.columns(4)
k1.metric("Customers", f"{len(view):,}")
k2.metric("Avg churn probability", f"{view['CHURN_PROBABILITY'].mean():.1%}" if len(view) else "-")
k3.metric("High risk (0.5+)", f"{len(high):,}")
k4.metric("Balance at risk", f"{high['BALANCE'].sum():,.0f}")

st.subheader("Average churn risk by segment")
by_seg = view.groupby("SEGMENT", as_index=False)["CHURN_PROBABILITY"].mean()
st.bar_chart(by_seg, x="SEGMENT", y="CHURN_PROBABILITY")

st.subheader("Top 50 at-risk customers")
top = view.sort_values("CHURN_PROBABILITY", ascending=False).head(50)
st.dataframe(top.drop(columns=["SCORED_AT"]), hide_index=True)

st.caption(f"Scores from CHURN_MODEL V1, scored at {df['SCORED_AT'].max()}")

Expected result: four KPI tiles (customers about 5,000 with no filter), a bar per segment, a 50-row table sorted by probability, and two sidebar filters. Pick one city: every number and the table change together. The caption shows the time from P6.

4. Share it with a viewer role (run as the owner, or ACCOUNTADMIN on your trial):

CREATE ROLE IF NOT EXISTS CHURN_VIEWER;
GRANT USAGE ON DATABASE BANK_DS TO ROLE CHURN_VIEWER;
GRANT USAGE ON SCHEMA BANK_DS.APP TO ROLE CHURN_VIEWER;
GRANT USAGE ON STREAMLIT BANK_DS.APP.CHURN_DASHBOARD TO ROLE CHURN_VIEWER;
-- No SELECT on tables is needed: the app runs with its owner's rights.
If CoCo gives you something different

It runs a query on every filter change with no cache: fine for 5,000 rows, slow and costly on real data; ask for @st.cache_data. It builds SQL with f-strings from the filter values: ask it to filter in pandas (as above) or to bind parameters, never to paste viewer input into SQL. It uses get_active_session(): works on the warehouse runtime; the portable form is st.connection. It shows customer names: remove them; the window is lit by the owner’s lamp. An unknown argument error on st.bar_chart or st.dataframe: the Streamlit version in your app may be older; ask CoCo to adapt the call to that version.

Key takeaway

Remember

A Streamlit app is the shop window: CoCo arranges it, you check every query behind it, cache the loading, and remember it runs with the owner’s rights, so show only what every viewer may see.

Glossary

Streamlit
A Python library that turns a script into a web app.
STREAMLIT object
The Snowflake object that holds and runs an app, such as BANK_DS.APP.CHURN_DASHBOARD.
Owner’s rights
The app queries with the owner role’s privileges, not the viewer’s.
Rerun
Streamlit runs the script again from the top after every viewer interaction.
st.cache_data
Remembers a function’s result so reruns do not repeat slow queries.
KPI
Key performance indicator: one headline number, shown with st.metric.
Warehouse runtime
The default app runtime; queries run on the app’s query warehouse.
Viewer role
A role given USAGE on the app so people can open it.
