Definition

Key definition

The CoCo CLI is CoCo in a terminal, started with the command cortex. It connects to Snowflake through a named connection, and it can also read and edit files in your project folder, run shell commands, and work with git, always asking permission according to your settings.

Snowsight CoCo sees your account. CLI CoCo sees your account and your laptop folder. That is its power and its risk: it can write a dbt model, a notebook file and a test in one go, and it can also run a command you did not expect. Plan Mode, permissions and diffs keep you in charge.

Think of it like the robot coming to your home office

Until now the robot assistant worked only inside the library. With the CLI, it also comes to your home office: it can read your notes, write new files and use your tools. Before it starts, you tell it which library card to use (the connection). For big jobs you ask it to write the plan on a whiteboard first (Plan Mode) and you tick it. And it never puts anything in the final folder without showing you a before-and-after page (the diff).

Connections, the safe way

The CLI reads the same ~/.snowflake/connections.toml as the Snowflake CLI. One block per connection:

# ~/.snowflake/connections.toml  (your own trial only)
[bank_trial]
account = "myorg-myaccount"
user = "YOUR_USER"
authenticator = "externalbrowser"   # browser sign-in, no password stored
role = "ACCOUNTADMIN"
warehouse = "LEARN_WH"
database = "BANK_DS"
schema = "FEATURES"
chmod 0600 ~/.snowflake/connections.toml   # only you can read it
cortex -c bank_trial                        # start with that connection
cortex -c bank_trial --plan                 # start in Plan Mode
On a client project

Never put a password in this file, never commit it, and never paste a key into a prompt. Use browser sign-in (SSO) or key-pair authentication as the client’s security team specifies. Install the CLI on a client laptop only when the project lead confirms it is approved.

Type these inside a session. This is a selection from the CLI reference; type /help for the full list on your version.

In practice: a bank

A data science team keeps its churn project in a git repository: SQL for features, the notebook, the Streamlit app and a dbt project. Each person works on a branch. They run CoCo in Plan Mode with permissions on “ask”, review its diff with /diff, run tests, then commit and open a pull request that a colleague reviews. A shared project skill describes the team’s rules (“always fully qualify table names; never select PII columns into the app”), so every CoCo session follows them. Bypass mode is banned by policy on any connection that reaches client data.

Lab: Plan Mode and diffs in a repo

Own laptop and own trial only

About 20 minNeeds git

  1. Install, then add the bank_trial block above to ~/.snowflake/connections.toml:

    curl -LsS https://ai.snowflake.com/static/cc-scripts/install.sh | sh
mkdir churn-repo && cd churn-repo && git init
cortex -c bank_trial

    Expected: a session opens. Type /status and check the account, role and warehouse.

  2. Type /plan, then: “Create sql/customer_features.sql with the SELECT that builds BANK_DS.FEATURES.CUSTOMER_FEATURES, reading the live definition from Snowflake. Add a README line about it.”

    Expected: a numbered plan and no file changes yet. Approve it only if it reads the definition (for example with GET_DDL) rather than inventing it.

  3. After it runs, type /diff. Then ! git status.

    Expected: two new files. Read the diff line by line before you git add and git commit yourself.

  4. Try one headless run from your normal terminal:

    cortex -c bank_trial -p "How many rows are in BANK_DS.ML.CHURN_SCORES? Answer with the number only."

    Expected: one number, about 5000. Exit the interactive session with /quit.

Key takeaway

Remember

The CLI brings the robot into your home office. Pick the right card (connection), ask for a plan first, keep permissions on ask, read every diff, and commit yourself. Treat preview features as preview.

Glossary

cortex
The command that starts the CoCo CLI.
connections.toml
File at ~/.snowflake/connections.toml holding named Snowflake connections.
Plan Mode
CoCo writes a plan and waits for approval before changing anything.
Slash command
A session command starting with /, such as /diff or /model.
Diff
The lines added and removed in each file.
Skill
A reusable folder of instructions (SKILL.md) CoCo follows for a kind of task.
MCP
Model Context Protocol: a way to plug extra tools into CoCo. Preview.
Headless
Running one prompt from a script, with no interactive window.
