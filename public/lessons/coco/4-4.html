Cost control and team workflow

Two bills run while you work: CoCo’s own tokens and the warehouses that run your queries. Learn to see both, cap both, size warehouses sensibly, and work as a team so AI-written code is reviewed, shared and documented like any other code.

25 min Advanced Practice worksheet + 3 challenges 1 lab

By the end of this lesson you can

  • Explain the two kinds of cost: CoCo tokens and warehouse credits
  • Read CoCo usage views and set a daily CoCo credit limit
  • Size a warehouse, set auto-suspend and attach a resource monitor
  • Run a team workflow: review, pairing, shared rules and documentation

Definition

Key definition

CoCo is billed by tokens: the words it reads and writes, converted to credits. Separately, every query it or you run uses warehouse credits while the warehouse is running. Cost control means seeing both in the usage views, capping both with limits, and not wasting either.

  • Token: a small piece of text, roughly part of a word. Long chats, big pasted outputs and large files all add tokens.
  • Credit: Snowflake’s unit of billing. An XSMALL warehouse uses 1 credit per running hour; each size up doubles it.
  • Per-second billing: warehouses bill per second, with a 60-second minimum each time they start.

Think of it like paying the robot and the librarians

The library has two wage bills. The robot assistant is paid by the word: every word you say to it and every word it says back. The librarians are paid by the minute while they are working, and a bigger team costs more per minute. A careful manager sets a daily allowance for the robot, sends librarians home as soon as the work is done (auto-suspend), and puts a spending alarm on each team (resource monitor). And the staff work as a team: one writes, another checks, and everyone writes notes for the next person.

Habits that cut tokens: one task per chat, /clear or a new chat when you switch topics, point at objects with @ or full names instead of pasting large outputs, and ask for “SQL only” when you do not need an explanation.

In practice: a bank

A bank’s platform team gives each project its own warehouse with a resource monitor, sets account-wide CoCo daily limits, and reviews the usage views every week in a short FinOps meeting. A project that overspends shows up by name. Data science teams keep a shared prompt library and team rules as skills, review AI-written code in pull requests, and record decisions in the repository. When someone asks “why did credits jump on Tuesday?”, the answer is one query away.

Lab: put guard rails on your trial

Monitor, cap and inspect

About 10 minYour trial, ACCOUNTADMIN

  1. Add a resource monitor and a short auto-suspend to LEARN_WH:

    USE ROLE ACCOUNTADMIN;
CREATE OR REPLACE RESOURCE MONITOR LEARN_RM WITH CREDIT_QUOTA = 20
  FREQUENCY = MONTHLY START_TIMESTAMP = IMMEDIATELY
  TRIGGERS ON 80 PERCENT DO NOTIFY ON 100 PERCENT DO SUSPEND;
ALTER WAREHOUSE LEARN_WH SET RESOURCE_MONITOR = LEARN_RM;
ALTER WAREHOUSE LEARN_WH SET AUTO_SUSPEND = 60;
SHOW WAREHOUSES LIKE 'LEARN_WH';

    Expected: the SHOW row lists LEARN_RM as resource monitor and 60 as auto_suspend. If the monitor ever suspends LEARN_WH, the P8 task fails until next month or until you raise the quota.

  2. Cap your own Snowsight CoCo use, then check it. Replace YOUR_USER with the name from SELECT CURRENT_USER();:

    ALTER USER YOUR_USER SET CORTEX_CODE_SNOWSIGHT_DAILY_EST_CREDIT_LIMIT_PER_USER = 2;
SHOW PARAMETERS LIKE 'CORTEX_CODE%' IN USER YOUR_USER;

    Expected: the Snowsight parameter shows 2 at USER level.

  3. See what CoCo cost you this week (data can lag about an hour):

    SELECT USER_NAME, DATE_TRUNC('day', USAGE_TIME) AS usage_day,
       SUM(TOKENS) AS tokens, ROUND(SUM(TOKEN_CREDITS), 3) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY
WHERE USAGE_TIME >= DATEADD(day, -7, CURRENT_TIMESTAMP())
GROUP BY 1, 2 ORDER BY 2 DESC;

    Expected: one row per day you used CoCo in Snowsight. Swap the view for CORTEX_CODE_CLI_USAGE_HISTORY to see the CLI.

Key takeaway

Remember

Pay the robot by the word and the librarians by the minute: watch both in the usage views, cap CoCo with daily limits, keep warehouses small with auto-suspend and a resource monitor, and let no AI-written change ship without a second reviewer.

Glossary

Token
A small piece of text. CoCo’s cost is based on tokens in and out.
Credit
Snowflake’s billing unit for compute and AI usage.
Daily credit limit
A CoCo parameter capping estimated credits per user over a rolling 24 hours.
Auto-suspend
Seconds of idle time after which a warehouse stops and stops billing.
Resource monitor
A credit quota on warehouses that can notify or suspend them.
Budget
A monthly spending limit with alerts that also covers serverless and AI features.
FinOps
The practice of tracking and managing cloud spending as a team.
Pull request
A request to merge code changes after someone reviews them.
