UNION ALL SELECT 'FEATURES.CUSTOMER_FEATURES', COUNT(*) FROM BANK_DS.FEATURES.CUSTOMER_FEATURES
UNION ALL SELECT 'ML.CHURN_SCORES', COUNT(*) FROM BANK_DS.ML.CHURN_SCORES;

    Expected: three equal counts, about 5,000 each.

    SELECT MAX(SCORED_AT) FROM BANK_DS.ML.CHURN_SCORES;
SHOW TASKS IN SCHEMA BANK_DS.ML;

    Expected: SCORED_AT within the last day if the task is running; task state started (or suspended if you already paused it).

  3. Model: SHOW VERSIONS IN MODEL BANK_DS.ML.CHURN_MODEL; shows V1 as default with your comment, and your model card lists metrics and the recency limitation.

  4. Safety: the app shows no names or account numbers, CHURN_VIEWER has only USAGE grants, no secrets live in any file or prompt, and LEARN_WH has auto-suspend and a resource monitor.

    Expected: a list of findings. Fix the valid ones yourself; argue back with evidence where CoCo is wrong.

Interview Q&A

Select a question to see a strong answer. Say the answers in your own words; interviewers listen for clear reasoning and safety habits more than for buzzwords.

What is CoCo, and how is it different from Cortex AI functions?

CoCo (formerly Cortex Code) is Snowflake’s AI coding agent. It explores the account, writes and runs SQL and Python, explains and fixes code. AI functions such as AI_CLASSIFY run a model on data inside a query. One line: AI functions work on the data; CoCo writes the code.

Where can you use CoCo?

In Snowsight (a panel, including Workspaces and notebooks), in the CLI (cortex), in the Desktop app and in the VS Code extension. Snowsight, Desktop and CLI are generally available; MCP, the Agent SDK, plugins and automations are preview.

How does CoCo respect security?

It runs under your current role, so it can only see and change what that role can. Masking and row access policies apply to its queries like any others. In the CLI, permissions (ask, allow, deny), Plan Mode and managed settings add human control.

How do you review code an AI assistant wrote?

Check the objects (exact database, schema, table), the meaning (filters match the business definition), joins (no fan-out or dropped rows), safety (no unreviewed DROP, DELETE, CREATE OR REPLACE, GRANT), data leaving Snowflake, and cost. Test on a sample or clone, compare counts, read the diff, and only commit what you can explain.

What is Plan Mode and when do you use it?

CoCo writes a step-by-step plan and waits for approval before changing anything. Use it for multi-step or risky work, such as replacing a table with a dynamic table or creating tasks.

What makes a good prompt for CoCo?

Name the objects, say what you want back, add the rules: “In BANK_DS.FEATURES.CUSTOMER_FEATURES, average CHURN by SEGMENT, ordered descending, SQL only, do not run.” Paste the exact error text when fixing. One task per message.

What is Snowpark, and why use it instead of pandas?

Snowpark lets Python describe work as lazy DataFrames that become SQL run in a Snowflake warehouse. The data stays in Snowflake, policies still apply, and it scales to billions of rows. Use pandas only on small results.

What does “lazy” mean for a Snowpark DataFrame?

Building it only records steps. An action such as show(), collect(), count(), to_pandas() or save_as_table() sends the SQL. explain() shows the SQL without running it.

Explain data leakage with an example.

Leakage is using information the model would not have at prediction time. Example: counting “account closure” tickets as a churn feature; the ticket is opened while leaving, so the model sees the answer. Fix with a cut-off date, a label window after it, and by removing post-event columns.

Why one row per customer for the feature table?

The model predicts per customer, so each training example must be one customer with all their clues. Aggregate each detail table first, then LEFT JOIN from customers so nobody is lost.

How did you handle class imbalance?

About 20% churned, so accuracy alone is misleading. I set XGBoost’s scale_pos_weight to stayers divided by churners, judged the model on recall, precision and ROC AUC, and discussed the threshold with the business.

Precision vs recall in a churn project: which matters more?

It depends on cost. If calling a happy customer is cheap and losing one is expensive, favour recall. If the call team is small, favour precision at the top of the list. I show both and let the business choose the threshold.

What does ROC AUC tell you?

How well the model ranks churners above stayers across all thresholds. 0.5 is random, 1.0 is perfect. Suspiciously high values suggest leakage.

How do you train a model in Snowflake?

In a notebook with snowflake.ml.modeling, for example XGBClassifier(input_cols, label_cols, output_cols).fit(train_df) on a Snowpark DataFrame split with random_split([0.8, 0.2], seed=42). Metrics come from snowflake.ml.modeling.metrics.

What is the Snowflake Model Registry for?

It stores models as versioned schema objects with metrics and comments, controlled by roles. You log with Registry.log_model, score with mv.run or SQL MODEL(name, version)!method, set a default version and roll back if needed.

How would you put a model into daily production in Snowflake?

Keep features fresh with a dynamic table (TARGET_LAG), wrap scoring in a stored procedure that uses the registry’s default version, schedule it with a task, monitor TASK_HISTORY and refresh history, and document the off switch and the cost.

Dynamic table or task: how do you choose?

A dynamic table keeps the result of one SELECT fresh within a target lag; Snowflake decides when to refresh. A task runs an action on a schedule, like calling a procedure. Use dbt when you have many models, tests and a team workflow.

How do you share a Streamlit app safely?

Grant USAGE on the database, schema and the STREAMLIT object to a viewer role. Apps run with owner’s rights, so the app must show only what every viewer may see; no PII unless approved.

How do you protect PII on Snowflake?

Least-privilege roles, masking policies on sensitive columns, row access policies for row-level scope, classification and tags to find PII, and ACCESS_HISTORY to audit. Never paste PII or secrets into prompts.

CoCo suggests CREATE OR REPLACE TABLE on a shared table. What do you do?

Stop. It drops and rebuilds the table, losing rows, grants and policies. Check what depends on it, prefer an additive change or a new table, test on a clone, and get a second reviewer.

How do you control CoCo’s cost?

Watch the usage views (for example CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY), set daily credit limit parameters per user or account, keep chats focused, and remember that queries CoCo runs also use warehouse credits.

How do you control warehouse cost?

Start XSMALL, short auto-suspend, a resource monitor with notify and suspend triggers, sensible schedules, and budgets for serverless and AI features that monitors do not cover.

CoCo’s answer is wrong. What do you do?

Prove it with a query, give CoCo the evidence and the exact error, narrow the instruction (“change only the join”), and if it still fails, write that part yourself. The person who commits the code owns it.

Tell me about a time an assistant’s code would have caused a problem.

Use the project: an inner join that silently dropped silent customers (the likely churners), caught because the feature count did not match the customer count. Fixed with a LEFT JOIN and COALESCE, and a row-count check added to the review.
