Setup and your first AI query

Get the access, region setting and warehouse right, load the 60 complaints that power the whole course project, and run your first Cortex AI query on them.

30 min Beginner Practice worksheet + 3 challenges 1 simulator + lab + project step P1

By the end of this lesson you can

  • Name the privilege and database roles a role needs to call AI Functions
  • Check and, on your own trial only, set cross-region inference
  • Create the project warehouse, database, schema and RAW_COMPLAINTS table
  • Run AI_SENTIMENT and AI_COMPLETE on real rows and read the results

Definition

Key definition

To call Cortex AI Functions, your current role needs two things: the USE AI FUNCTIONS account privilege (or a per-function USE AI FUNCTION privilege) and one of the SNOWFLAKE.CORTEX_USER or SNOWFLAKE.AI_FUNCTIONS_USER database roles. The query also needs a running warehouse, and the model must be available in your region or through cross-region inference.

In a fresh account most of this is already true: both USE AI FUNCTIONS and CORTEX_USER are granted to the PUBLIC role by default, so every user can call the functions. Banks usually tighten that: an admin revokes them from PUBLIC and grants them only to project roles. If your first AI query fails on a client account, the cause is almost always one of the four items below.

Think of it like getting into the reading room

To use the smart-reader librarians you need three things. Your ID badge must carry a reading-room stamp (the privilege and database role). The librarians you want must be on shift in your building, or you must allow them to work from a sister library (the region setting). And someone must open a desk for you (the warehouse), because every request is still handled at a desk.

In the libraryReading-room stampIn Snowflake: USE AI FUNCTIONS plus SNOWFLAKE.CORTEX_USER or AI_FUNCTIONS_USER
In the libraryLibrarians on shiftIn Snowflake: models available in your region, or CORTEX_ENABLED_CROSS_REGION
In the libraryAn open deskIn Snowflake: a running warehouse such as LEARN_WH (XSMALL is plenty)

Database roles go to roles, not users

SNOWFLAKE.CORTEX_USER and its siblings cannot be granted straight to a user. Grant them to an account role, then grant that role to the user. One more detail: a user with USE AI FUNCTIONS but without CORTEX_USER can still run AI_AGG and AI_SUMMARIZE_AGG.

-- What an admin runs on a locked-down bank account (do NOT run on a client account yourself)
USE ROLE ACCOUNTADMIN;
CREATE ROLE IF NOT EXISTS COMPLAINTS_ANALYST;
GRANT USE AI FUNCTIONS ON ACCOUNT TO ROLE COMPLAINTS_ANALYST;
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE COMPLAINTS_ANALYST;
GRANT ROLE COMPLAINTS_ANALYST TO USER some_user;

-- What anyone can run to check
SHOW GRANTS TO ROLE PUBLIC;          -- look for SNOWFLAKE.CORTEX_USER and USE AI FUNCTIONS
SHOW PARAMETERS LIKE 'CORTEX_ENABLED_CROSS_REGION' IN ACCOUNT;

In practice: a bank

On a bank project you will rarely be ACCOUNTADMIN. A typical first week looks like this: the platform team creates a project role, grants it USE AI FUNCTIONS and CORTEX_USER (or the narrower AI_FUNCTIONS_USER if agents and search are out of scope), gives it a small warehouse, and decides the cross-region setting with the data-protection officer. Your job is to check those four items with SHOW GRANTS and SHOW PARAMETERS, and to raise a ticket with exact wording if one is missing, for example: “Role COMPLAINTS_ANALYST needs SNOWFLAKE.CORTEX_USER for AI_CLASSIFY on BANK_AI.COMPLAINTS.”

Lab: prove your account is ready

Four checks, one first call

About 10 minFree trial (Enterprise)

  1. Check the default grants. In the output, look for USE AI FUNCTIONS and the database role SNOWFLAKE.CORTEX_USER.

    USE ROLE ACCOUNTADMIN;
SHOW GRANTS TO ROLE PUBLIC;
SHOW GRANTS ON ACCOUNT;

    Expected: a row with privilege USAGE on DATABASE_ROLE SNOWFLAKE.CORTEX_USER, and USE AI FUNCTIONS granted to PUBLIC on the account.

  2. Check the region setting. Only on your own trial, and only if the value is DISABLED and your first call later fails with a model-not-available error, set it wider.

    SHOW PARAMETERS LIKE 'CORTEX_ENABLED_CROSS_REGION' IN ACCOUNT;
-- Trial only, if needed:
-- ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

    Expected: a value such as ANY_REGION or AWS_US.

  3. Run your first AI Function with plain text. No table needed.

    SELECT AI_SENTIMENT('Thank you for processing my home loan top-up so quickly.'):categories[0]:sentiment::STRING AS mood,
       AI_COMPLETE('llama3.1-8b', 'In five words, what is a credit card?') AS answer;

    Expected: positive and a short phrase. An error saying the role is not authorised means a grant is missing; an error about the model means the region setting.

Project step P1: Load the complaints

Complaint Intelligence · P1

We create the project home and load 60 realistic complaints. Every later step (P2 to P8) reads these exact names: warehouse LEARN_WH, database BANK_AI, schema COMPLAINTS, table RAW_COMPLAINTS.

1. Create the warehouse, database, schema and table, then insert the 60 rows. Paste the whole script into one worksheet and select Run All. It is safe to run twice: the table is replaced each time.

USE ROLE ACCOUNTADMIN;   -- your own trial only; on a client account use the project role

CREATE SCHEMA IF NOT EXISTS BANK_AI.COMPLAINTS;

2. Check the load.

SELECT PRODUCT, COUNT(*) AS COMPLAINTS
FROM BANK_AI.COMPLAINTS.RAW_COMPLAINTS
GROUP BY PRODUCT
ORDER BY COMPLAINTS DESC;

Expected: 6 rows adding to 60: CREDIT_CARD 15, SAVINGS 13, then HOME_LOAN, MOBILE_APP, PERSONAL_LOAN and UPI with 8 each. Four complaints (ids 20, 32, 51 and 59) are in Hindi or Hinglish on purpose; we translate them in P3.

3. Your first AI query on project data. Mood for the first ten complaints, plus a one-line summary of the longest one.

SELECT COMPLAINT_ID, PRODUCT,
       AI_SENTIMENT(COMPLAINT_TEXT):categories[0]:sentiment::STRING AS MOOD
FROM BANK_AI.COMPLAINTS.RAW_COMPLAINTS
WHERE COMPLAINT_ID <= 10
ORDER BY COMPLAINT_ID;

SELECT COMPLAINT_ID,
       AI_COMPLETE('llama3.1-8b',
         'Summarise this bank complaint in at most 12 words: ' || COMPLAINT_TEXT) AS ONE_LINER
FROM BANK_AI.COMPLAINTS.RAW_COMPLAINTS
ORDER BY LENGTH(COMPLAINT_TEXT) DESC
LIMIT 1;

Expected: ten rows, mostly negative, with ids 4 and 6 positive; then one short summary. Write down anything that looks wrong: in P2 we turn these one-off calls into a governed table.

Key takeaway

Remember

Before any AI query works you need four things: the USE AI FUNCTIONS privilege, a Cortex database role on your current role, a model available in your region (or cross-region inference) and a running warehouse. Check them; never change them on a client account yourself.

Glossary

USE AI FUNCTIONS
Account-level privilege that allows calling Cortex AI Functions. Granted to PUBLIC by default.
CORTEX_USER
Database role in the SNOWFLAKE database for all Cortex features. Granted to PUBLIC by default.
AI_FUNCTIONS_USER
Narrower database role: scalar AI Functions only, no Search, Analyst or Agents.
Database role
A role that lives inside a database. Granted to account roles, never directly to users.
PUBLIC
The role every user and role automatically has.
LEARN_WH
The course warehouse: XSMALL, suspends after 60 seconds idle, resumes on demand.
RAW_COMPLAINTS
Project table with the 60 original complaints, the input to every later step.
