Extract, summarise and translate

Pull exact facts out of messy text, write one summary for thousands of rows, translate Hindi and Hinglish into English and remove personal data, all from SQL.

35 min Intermediate Practice worksheet + 3 challenges 2 simulators + lab + project step P3

By the end of this lesson you can

  • Extract named fields with AI_EXTRACT and read the response object
  • Summarise many rows with AI_SUMMARIZE_AGG and steer the result with AI_AGG
  • Translate with AI_TRANSLATE, including auto-detect for mixed languages
  • Redact personal data with AI_REDACT and know its limits

Definition

Key definition

AI_EXTRACT pulls the answers to your questions out of text or a document. AI_SUMMARIZE_AGG and AI_AGG are aggregate functions: they read a whole column across many rows and return one text. AI_TRANSLATE translates between supported languages. AI_REDACT finds and masks personal information.

These four change the shape of text. Extract turns a paragraph into columns. The two aggregates turn many rows into one paragraph. Translate keeps the meaning and changes the language. Redact keeps the text and removes the private parts.

Think of it like a team of note-takers

One note-taker reads each letter and fills a small form: amount, product, what the customer wants. Another reads a whole drawer of letters and writes one page: “this month people mostly complained about…”. A translator rewrites Hindi letters in English. A privacy officer blacks out names and phone numbers before letters go to a training class.

AI_EXTRACT in depth

AI_EXTRACT( text => <text>, responseFormat => <format> [, scores => TRUE] )
AI_EXTRACT( file => TO_FILE('@stage', 'file.pdf'), responseFormat => <format> )
-- returns {"error": null, "response": { ...your fields... }}
responseFormat styleExampleUse for
Object of label: question{'amount': 'What amount is mentioned?'}Most cases: you choose the key names
Array of questions['What amount is mentioned?']Quick tests
Array of [label, question][['amount', 'What amount…?']]Same as the object, as a list
JSON schema{'schema': {'type': 'object', 'properties': {…}}}Lists (type: array) and tables (column_ordering)

It runs on the arctic-extract model, reads text or files (PDF, Word, PowerPoint, images, HTML, email and more, under 100 MB) and supports many languages, Hindi included. Both input and output tokens are billed, the responseFormat counts as input, and each document page counts as 970 tokens. Questions can be in natural language or short descriptions such as 'City, street, ZIP'.

AI_SUMMARIZE_AGG and AI_AGG

FunctionSignatureWhen to use
AI_SUMMARIZE_AGGAI_SUMMARIZE_AGG(expr)A general summary of many rows. No instruction needed.
AI_AGGAI_AGG(expr, 'instruction')Your own task across rows: top themes, best quote, list of products named.

Both are aggregates, so use them with GROUP BY like SUM. They are not limited by one context window: the docs describe 128,000 tokens per row that can be used across multiple rows. Write AI_AGG instructions as plain statements that describe the data and the purpose, for example “You are reading complaints to an Indian retail bank. List the three most common problems with a rough count for each, for the operations committee.”

SELECT CATEGORY,
       AI_AGG(TEXT_EN, 'You are reading complaints to an Indian retail bank. List the three most common problems as short bullet points with a rough count for each.') AS TOP_PROBLEMS
FROM BANK_AI.COMPLAINTS.ENRICHED
GROUP BY CATEGORY;

AI_TRANSLATE and AI_REDACT

AI_TRANSLATE( <text>, <source_language>, <target_language> )   -- '' as source = auto-detect
AI_REDACT( <input> [, <categories>] [, <return_error_details>] [, <mode>] )  -- mode 'redact' or 'detect'
AI_TRANSLATEAI_REDACT

SELECT AI_TRANSLATE('Aapka app bahut slow hai', '', 'en') AS EN;

SELECT AI_REDACT('Please call Asha Rao on 98200 12345 about card 4111 1111 1111 1111.') AS SAFE;
-- Please call [NAME] on [PHONE_NUMBER] about card [PAYMENT_CARD_DATA].
Redaction is best effort

The docs say AI_REDACT detects personal data on a best-effort basis and you must review the output against your privacy policy. On a bank project treat it as one layer next to masking policies, never as the only control.

In practice: a bank

A bank’s Monday committee pack used to take an analyst a full day of reading. Now a task runs at 6 a.m.: AI_EXTRACT fills amount, product and requested action; AI_TRANSLATE turns regional-language complaints into English; AI_SUMMARIZE_AGG writes one paragraph per product; AI_REDACT strips names and phone numbers from quotes that go into slides. The analyst spends her morning checking the numbers and adding judgement instead of copying text.

Extract, translate, aggregate, redact

    SELECT AI_EXTRACT(text => COMPLAINT_TEXT,
  responseFormat => {'amount': 'What money amount in rupees is mentioned?', 'wants': 'What does the customer want?'}) AS R

    Expected: four English sentences. Check that the amounts 1,500 and 750 survive.

    Expected: one row per category with three bullet points each.

  4. Redact a made-up sentence with a name and phone number (the AI_REDACT example above).

    Expected: the name and number replaced by [NAME] and [PHONE_NUMBER].

Project step P3: Extract fields and summarise

Complaint Intelligence · P3

We keep ONE table: P3 adds four columns to BANK_AI.COMPLAINTS.ENRICHED (no ENRICHED_V2): AMOUNT_MENTIONED NUMBER(12,2), ACCOUNT_OR_CARD_TYPE VARCHAR, REQUESTED_ACTION VARCHAR and TEXT_EN VARCHAR (English text for every row). It also creates BANK_AI.COMPLAINTS.PRODUCT_SUMMARIES(PRODUCT, COMPLAINT_COUNT, SUMMARY). P5 builds Cortex Search on TEXT_EN.

1. Run the script. It is safe to re-run: the columns are added only if missing, and the updates overwrite.

USE WAREHOUSE LEARN_WH;
USE SCHEMA BANK_AI.COMPLAINTS;

-- 1. Four new columns on the SAME table from P2
ALTER TABLE BANK_AI.COMPLAINTS.ENRICHED ADD COLUMN IF NOT EXISTS AMOUNT_MENTIONED NUMBER(12,2);
ALTER TABLE BANK_AI.COMPLAINTS.ENRICHED ADD COLUMN IF NOT EXISTS ACCOUNT_OR_CARD_TYPE VARCHAR;
ALTER TABLE BANK_AI.COMPLAINTS.ENRICHED ADD COLUMN IF NOT EXISTS REQUESTED_ACTION VARCHAR;
ALTER TABLE BANK_AI.COMPLAINTS.ENRICHED ADD COLUMN IF NOT EXISTS TEXT_EN VARCHAR;

-- 2. Extract three fields in ONE AI_EXTRACT call per row
UPDATE BANK_AI.COMPLAINTS.ENRICHED e
SET AMOUNT_MENTIONED     = TRY_TO_NUMBER(REGEXP_REPLACE(x.R:response:amount::STRING, '[^0-9.]', ''), 12, 2),
    ACCOUNT_OR_CARD_TYPE = NULLIF(x.R:response:account_or_card_type::STRING, 'None'),
    REQUESTED_ACTION     = x.R:response:requested_action::STRING
FROM (
  SELECT COMPLAINT_ID,
         AI_EXTRACT(
           text => COMPLAINT_TEXT,
           responseFormat => {
             'amount': 'What is the main money amount in rupees mentioned? Digits only, no commas. If none, answer None',
             'account_or_card_type': 'Which product is involved, for example Credit card, Debit card, Savings account, Home loan, Personal loan? If none, answer None',
             'requested_action': 'In at most eight English words, what does the customer want the bank to do? If nothing, answer None'
           }) AS R
  FROM BANK_AI.COMPLAINTS.ENRICHED
) x
WHERE e.COMPLAINT_ID = x.COMPLAINT_ID;

-- 3. English text: translate only rows written in Hindi or Hinglish
UPDATE BANK_AI.COMPLAINTS.ENRICHED
SET TEXT_EN = CASE
  WHEN AI_FILTER(PROMPT('Is this text written mainly in Hindi or Hinglish (Hindi in Latin letters) rather than English? {0}', COMPLAINT_TEXT))
  THEN AI_TRANSLATE(COMPLAINT_TEXT, '', 'en')
  ELSE COMPLAINT_TEXT
END;

-- 4. Optional: re-classify translated rows on their English text
UPDATE BANK_AI.COMPLAINTS.ENRICHED
SET CATEGORY = AI_CLASSIFY(TEXT_EN, ['Fees and charges', 'Card issues', 'Loan servicing', 'App and UPI', 'Customer service', 'Fraud']):labels[0]::STRING
WHERE TEXT_EN <> COMPLAINT_TEXT;

-- 5. One summary per product
CREATE OR REPLACE TABLE BANK_AI.COMPLAINTS.PRODUCT_SUMMARIES AS
SELECT PRODUCT,
       COUNT(*)                  AS COMPLAINT_COUNT,
       AI_SUMMARIZE_AGG(TEXT_EN) AS SUMMARY
FROM BANK_AI.COMPLAINTS.ENRICHED
GROUP BY PRODUCT;

2. Check it.

SELECT COMPLAINT_ID, AMOUNT_MENTIONED, ACCOUNT_OR_CARD_TYPE, REQUESTED_ACTION, TEXT_EN
FROM BANK_AI.COMPLAINTS.ENRICHED
WHERE COMPLAINT_ID IN (2, 10, 20, 32)
ORDER BY COMPLAINT_ID;

SELECT * FROM BANK_AI.COMPLAINTS.PRODUCT_SUMMARIES ORDER BY COMPLAINT_COUNT DESC;

Expected: amounts 4500, a figure for row 10 (60000 or 150000: the text mentions both, so decide your rule), 1500 and 750; English TEXT_EN for rows 20 and 32; six summary rows with counts 15, 13, 8, 8, 8, 8. No row should have a NULL TEXT_EN.

Key takeaway

Remember

Extract turns text into columns, the aggregates turn many rows into one paragraph, translate makes every row readable in one language and redact removes private data. Always clean and check what comes back before you trust it in a report.

Glossary

AI_EXTRACT
Answers named questions from text or a file. Returns {"error", "response"}.
responseFormat
The questions or JSON schema that tell AI_EXTRACT what to pull out.
AI_SUMMARIZE_AGG
Aggregate that summarises a text column across many rows.
AI_AGG
Aggregate that follows your own instruction across many rows.
AI_TRANSLATE
Translates text; an empty source language means auto-detect.
AI_REDACT
Replaces personal data such as names and phone numbers with placeholders.
PII
Personally identifiable information: data that can identify a person.
TEXT_EN
Project column with the English version of every complaint.
