Documents with AI_PARSE_DOCUMENT

Turn PDFs and scans on a stage into text you can search and query: choose OCR or LAYOUT, split long documents into chunks and pull fields out of a loan application.

30 min Intermediate Practice worksheet + 3 challenges 2 simulators + 1 lab

By the end of this lesson you can

  • Create a stage for documents and point AI functions at files with TO_FILE
  • Choose between OCR and LAYOUT modes and read the output object
  • Chunk long text with SPLIT_TEXT_RECURSIVE_CHARACTER for search and RAG
  • Extract loan fields from a PDF with AI_EXTRACT and estimate the page cost

Definition

Key definition

AI_PARSE_DOCUMENT reads a document stored on a Snowflake stage and returns its content as text. OCR mode returns plain text; LAYOUT mode also keeps structure such as headings and tables, as Markdown.

Banks run on documents: loan applications, salary slips, KYC forms, account statements, policy manuals. Until now someone typed the important parts into a system. With AI_PARSE_DOCUMENT the PDF becomes text inside Snowflake, and every AI function from the last three lessons can work on it. The file never leaves the stage.

Think of it like a typist and a pair of scissors

Hand a scanned letter to a typist. A quick typist copies only the words (OCR). A careful typist also keeps the headings, the bold lines and the tables in the right place (LAYOUT). If the document is 80 pages long, you then cut the typed copy into index cards of about one paragraph each, overlapping each card a little with the next so no sentence is lost at the cut. Those cards are what the super index (Cortex Search) will file in Lesson 3.1.

How it works

AI_PARSE_DOCUMENT( TO_FILE('@stage', 'path/file.pdf') [, {'mode': 'OCR' | 'LAYOUT', 'page_split': TRUE,
                    'page_filter': [{'start': 0, 'end': 1}], 'extract_images': TRUE}] )
OptionWhat it does
mode: OCR (default)Text only. Fast and good for scanned, text-heavy pages. No layout.
mode: LAYOUTText plus structure (headers, tables) as Markdown. The docs call it the preferred choice for most cases.
page_split: TRUEReturns a pages array, one item per page with content and index (from 0). PDF, PPTX and DOCX only.
page_filterProcess only page ranges; start is inclusive, end exclusive. Implies page_split.
extract_images: TRUELAYOUT only. Adds an images array with base64 image data and positions.
FilesPDF, PPTX, DOCX, JPEG, JPG, PNG, TIFF, TIF, HTML, TXT. Up to 100 MB and 2,000 pages per document.Input limits
StagesInternal or external stages with client-side or server-side encryption. The AI function docs list stages that do NOT work: user and table stages, SNOWFLAKE_FULL internal encryption and double-quoted stage names.Where files live
LanguagesTrained for English, Hindi, Chinese, French, German, Spanish, Portuguese and others in both modes. Handwriting is recognised.Content
CostBilled per page: 3.66 AI Credits per 1,000 pages for LAYOUT and 0.68 for OCR (Service Consumption Table, 12 Oct 2026). HTML and TXT bill per 3,000 characters.Price

The result has a content field (or a pages array when splitting). Reach into it as usual: AI_PARSE_DOCUMENT(…):content::STRING. To get pageCount, pass TRUE as the last argument (return_error_details): the answer then has value, error and metadata at the top.

Chunking long documents

Search and embedding models work best on short passages, and embedding models have small context windows (512 tokens for many of them). So after parsing, you cut the text into chunks.

SNOWFLAKE.CORTEX.SPLIT_TEXT_RECURSIVE_CHARACTER( <text>, <format>, <chunk_size> [, <overlap>] [, <separators>] )
-- format: 'none' or 'markdown'   chunk_size and overlap are in CHARACTERS   returns an ARRAY

It splits on paragraph breaks first, then line breaks, then spaces, until every chunk is no longer than chunk_size. With 'markdown' it also respects headers, code blocks and tables, which pairs well with LAYOUT output. overlap repeats the end of one chunk at the start of the next so a sentence cut in two still appears whole somewhere. Use LATERAL FLATTEN to turn the array into rows.

In practice: a bank

A lending team receives 5,000 personal-loan applications a month as PDFs. Before Cortex, data-entry staff keyed in name, income, loan amount and existing EMIs. Now a task picks up new files from the stage each hour, AI_EXTRACT reads the fields straight from the PDF, and a rule computes the share of income already going to EMIs. Applications with missing fields or an EMI share above 50% go to an underwriter; the rest move to the next check. The same PDFs are parsed in LAYOUT mode and chunked, so a credit officer can later ask a chatbot “what did the applicant say about the purpose?”.

Lab: parse and extract a loan application PDF

From PDF on a stage to fields in a table

About 25 minFree trial (Enterprise)

  1. Make the document. Paste this fictional form into any word processor and save or print it as loan_application_001.pdf.

    PERSONAL LOAN APPLICATION FORM
Application number: PL-2026-004417
Date: 14 September 2026

Section A: Applicant
Full name: Kavya Raghunathan
Date of birth: 12 March 1993
City: Bengaluru
Employer: Northwind Analytics Pvt Ltd
Employment type: Salaried, 4 years in current job
Monthly net income: Rs 1,45,000

Section B: Loan request
Loan amount requested: Rs 6,00,000
Purpose: Home renovation
Preferred tenure: 48 months

Section C: Existing obligations
| Lender         | Product   | Monthly EMI |
| Sample Bank    | Car loan  | Rs 18,500   |
| Sample Bank    | Credit card EMI | Rs 4,200 |

Declaration: I confirm the above details are true.
Signature: Kavya Raghunathan

  2. Create a schema and a stage for documents, with a directory table and server-side encryption.

    USE ROLE ACCOUNTADMIN;
USE WAREHOUSE LEARN_WH;
CREATE SCHEMA IF NOT EXISTS BANK_AI.DOCS;
CREATE STAGE IF NOT EXISTS BANK_AI.DOCS.LOAN_DOCS
  DIRECTORY = (ENABLE = TRUE)
  ENCRYPTION = (TYPE = 'SNOWFLAKE_SSE');

    Expected: Stage area LOAN_DOCS successfully created.

  3. Upload the PDF in Snowsight: open the database browser (Data → Databases, called Catalog in newer menus), go to BANK_AI → DOCS → Stages → LOAN_DOCS and select + Files. Then refresh and list.

    ALTER STAGE BANK_AI.DOCS.LOAN_DOCS REFRESH;
SELECT RELATIVE_PATH, SIZE FROM DIRECTORY(@BANK_AI.DOCS.LOAN_DOCS);

    Expected: one row: loan_application_001.pdf.

  4. Parse it both ways and compare.

    SELECT AI_PARSE_DOCUMENT(TO_FILE('@BANK_AI.DOCS.LOAN_DOCS', 'loan_application_001.pdf'), {'mode': 'OCR'}):content::STRING AS OCR_TEXT,
       AI_PARSE_DOCUMENT(TO_FILE('@BANK_AI.DOCS.LOAN_DOCS', 'loan_application_001.pdf'), {'mode': 'LAYOUT'}):content::STRING AS LAYOUT_MD;

    Expected: OCR gives plain lines; LAYOUT keeps the EMI table as a Markdown table with | separators. If the column is NULL, run the call with TRUE as a third argument to see the error.

  5. Chunk the LAYOUT text into rows.

    CREATE OR REPLACE TABLE BANK_AI.DOCS.LOAN_DOC_CHUNKS AS
WITH parsed AS (
  SELECT RELATIVE_PATH,
         AI_PARSE_DOCUMENT(TO_FILE('@BANK_AI.DOCS.LOAN_DOCS', RELATIVE_PATH), {'mode': 'LAYOUT'}):content::STRING AS DOC_TEXT
  FROM DIRECTORY(@BANK_AI.DOCS.LOAN_DOCS))
SELECT p.RELATIVE_PATH, c.INDEX AS CHUNK_NO, c.VALUE::STRING AS CHUNK
FROM parsed p,
     LATERAL FLATTEN(SNOWFLAKE.CORTEX.SPLIT_TEXT_RECURSIVE_CHARACTER(p.DOC_TEXT, 'markdown', 400, 50)) c;

SELECT * FROM BANK_AI.DOCS.LOAN_DOC_CHUNKS ORDER BY CHUNK_NO;

    Expected: a few chunks of up to 400 characters, split at headings. Real projects use 1,000 to 2,000 characters; 400 just shows the effect on a one-page form.

  6. Extract the underwriting fields straight from the file.

    SELECT RELATIVE_PATH,
       AI_EXTRACT(
         file => TO_FILE('@BANK_AI.DOCS.LOAN_DOCS', RELATIVE_PATH),
         responseFormat => {
           'applicant_name': 'Full name of the applicant',
           'monthly_income': 'Monthly net income in rupees, digits only',
           'loan_amount': 'Loan amount requested in rupees, digits only',
           'tenure_months': 'Preferred tenure in months',
           'employer': 'Name of the employer'
         }):response AS FIELDS
FROM DIRECTORY(@BANK_AI.DOCS.LOAN_DOCS);

    Expected: {"applicant_name":"Kavya Raghunathan","employer":"Northwind Analytics Pvt Ltd","loan_amount":"600000","monthly_income":"145000","tenure_months":"48"} or very close. Check every value against the PDF.

Key takeaway

Remember

Put documents on an encrypted stage with a directory table, read them with AI_PARSE_DOCUMENT (LAYOUT for structure, OCR for speed), cut long text into overlapping chunks, and use AI_EXTRACT when you only need a few fields. You pay per page, so parse once and store the result.

Glossary

Stage
A named location for files in Snowflake, internal or in your cloud storage.
Directory table
A table view of the files on a stage: path, size, last modified. Read with DIRECTORY(@stage).
TO_FILE
Turns a stage and path into a FILE object that AI functions accept.
OCR
Optical character recognition: reading the words in an image or scan.
LAYOUT mode
AI_PARSE_DOCUMENT mode that keeps headings and tables as Markdown.
Chunk
A short passage cut from a long text, used for search and embeddings.
Overlap
Characters repeated between neighbouring chunks so context is not lost.
LATERAL FLATTEN
Turns each element of an array into its own row.
