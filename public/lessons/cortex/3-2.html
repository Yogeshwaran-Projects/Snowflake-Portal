Definition

Key definition

Cortex Analyst is a managed Snowflake feature that turns a plain-English question into SQL and runs it. A semantic view is a schema object that tells it what your tables mean: the business names, how tables join, and how every metric is calculated.

Asking an LLM to write SQL against raw tables is risky. It does not know that “urgent” lives in IS_URGENT, or that your bank counts “share negative” as negative complaints divided by all complaints. The semantic view writes those rules down once, so every answer uses the same official definitions.

  • Semantic views are the recommended way for new work. Older projects used a YAML “semantic model” file on a stage; it still works.
  • Cortex Analyst is offered as a REST API (POST /api/v2/cortex/analyst/message), in a Snowsight playground, and as a tool inside Cortex Agents. Snowflake now recommends using it through Agents (lesson 3.3).
  • It answers SQL-shaped questions: counts, sums, trends, rankings. It does not read free text; that is Cortex Search.

Think of it like a helper with the official catalogue

You walk up to a helper in the sky library and say “How many angry letters about payments came in last month?” The helper does not wander the shelves guessing. She opens the official catalogue, which says “angry means SENTIMENT = negative”, “payments means CATEGORY = App and UPI”, “letters are counted with COUNT(COMPLAINT_ID)”. Then she fills in a precise request slip, hands it to the librarians and brings back the number, with the slip attached so you can check it.

Cost, models and access

Used directly, Cortex Analyst is billed per message (only successful responses count), plus the warehouse that runs the generated SQL. Track it in SNOWFLAKE.ACCOUNT_USAGE.CORTEX_ANALYST_USAGE_HISTORY. It chooses the best model your role can access, from a ranked list that includes Claude Sonnet and GPT 4.1; you do not pick it. Users need SNOWFLAKE.CORTEX_USER or the narrower SNOWFLAKE.CORTEX_ANALYST_USER database role, plus access to the semantic view and SELECT on its tables. Answers respect row access and masking policies as usual.

Real syntax

This is the semantic view for our project. Read each block as one page of the catalogue.

CREATE OR REPLACE SEMANTIC VIEW BANK_AI.COMPLAINTS.COMPLAINTS_SV
  TABLES (
    complaints AS BANK_AI.COMPLAINTS.ENRICHED
      PRIMARY KEY (COMPLAINT_ID)
      WITH SYNONYMS ('customer complaints', 'grievances')
      COMMENT = 'One row per customer complaint, enriched by Cortex AI functions'
  )
  FACTS (
    complaints.urgent_flag AS IFF(IS_URGENT, 1, 0)
      COMMENT = '1 when the complaint needs action within 24 hours',
    complaints.negative_flag AS IFF(LOWER(SENTIMENT) = 'negative', 1, 0)
      COMMENT = '1 when the overall sentiment is negative'
  )
  DIMENSIONS (
    complaints.product AS PRODUCT
      WITH SYNONYMS = ('banking product', 'product line')
      COMMENT = 'Product code: CREDIT_CARD, SAVINGS, HOME_LOAN, PERSONAL_LOAN, MOBILE_APP or UPI',
    complaints.category AS CATEGORY
      WITH SYNONYMS = ('topic', 'issue type'),
    complaints.channel AS CHANNEL
      WITH SYNONYMS = ('contact channel', 'source'),
    complaints.sentiment AS SENTIMENT
      WITH SYNONYMS = ('mood', 'tone'),
    complaints.submitted_date AS TO_DATE(SUBMITTED_AT)
      WITH SYNONYMS = ('complaint date', 'date received'),
    complaints.submitted_week AS DATE_TRUNC('WEEK', SUBMITTED_AT)
      COMMENT = 'Week the complaint arrived (weeks start on Monday)'
  )
  METRICS (
    complaints.complaint_count AS COUNT(COMPLAINT_ID)
      WITH SYNONYMS = ('number of complaints', 'volume'),
    complaints.urgent_count AS SUM(complaints.urgent_flag)
      COMMENT = 'Number of urgent complaints',
    complaints.share_negative AS AVG(complaints.negative_flag)
      COMMENT = 'Share of complaints with negative sentiment, from 0 to 1'
  )
  AI_SQL_GENERATION 'Round shares to 2 decimal places. Sort rankings from highest to lowest.'
  COMMENT = 'Complaint Intelligence: official complaint metrics';

You can query the semantic view yourself, without any AI. This is handy for checking that a metric is right:

SELECT * FROM SEMANTIC_VIEW(
  BANK_AI.COMPLAINTS.COMPLAINTS_SV
  DIMENSIONS complaints.product
  METRICS complaints.complaint_count, complaints.urgent_count, complaints.share_negative
)
ORDER BY complaint_count DESC;

If your table has more than one entity, add a RELATIONSHIPS block, for example complaints_to_customers AS complaints (CUSTOMER_ID) REFERENCES customers. Our project has one table, so it has none.

Verified queries. When you ask a question in the Snowsight playground and the SQL is right, you can save it as a verified query. In SQL they live in an AI_VERIFIED_QUERIES ( name AS ( QUESTION '…' SQL '…' ) ) block at the end of the statement. Analyst reuses them for the same or similar questions, which is the single best way to raise accuracy for questions your managers ask every week.

Accuracy tips that work

Name things like users talkA dimension called channel with synonyms “source” and “contact channel” beats a raw column called CHNL_CD.Synonyms
Describe every metricWrite what it means and its range in COMMENT. The model reads it.Comments
Define formulas oncePut the share calculation in a metric. Never rely on the model to invent it.Metrics
Save verified queriesAdd the 10 to 20 questions your users ask most, with approved SQL.Verified queries
Keep it smallOne semantic view per business area. A huge catalogue confuses the helper.Scope
Test like a QA analystKeep a list of questions with known answers and rerun it after every change.Lesson 4.2

Limits to remember: Analyst cannot see the results of earlier queries in the conversation, only answers what SQL can answer, and can lose track in very long conversations. If it gets confused, start a new conversation. When a question is unclear, it returns suggestions instead of SQL.

Lab: create the view and ask questions

Semantic view and the Cortex Analyst playground

About 20 minNeeds P1 to P4

  1. Check the columns the view uses exist in your table.

    USE WAREHOUSE LEARN_WH;
SELECT COMPLAINT_ID, PRODUCT, CATEGORY, CHANNEL, SENTIMENT, IS_URGENT, SUBMITTED_AT
FROM BANK_AI.COMPLAINTS.ENRICHED LIMIT 5;

    Expected: 5 rows. SENTIMENT holds lowercase labels (positive, negative, neutral, mixed) and IS_URGENT is BOOLEAN, exactly what the facts expect. PRODUCT and CHANNEL hold codes such as CREDIT_CARD and CALL_CENTER.

  2. Run the CREATE OR REPLACE SEMANTIC VIEW statement from the Syntax section.

    Expected: “Semantic view COMPLAINTS_SV successfully created.” Then SHOW SEMANTIC VIEWS IN SCHEMA BANK_AI.COMPLAINTS; lists it.

  3. Run the SEMANTIC_VIEW() query. Write down the top product and its count; you will compare with Analyst.

    Expected: one row per product, with complaint_count adding up to 60.

  4. In Snowsight open AI & ML » Cortex Analyst, select BANK_AI.COMPLAINTS.COMPLAINTS_SV and open the playground. Ask: “How many complaints per product?”

    Expected: the same numbers as step 3, plus the SQL it wrote.

  5. Ask a question with a synonym: “Which source has the worst mood?”. Then save a correct answer as a verified query with the button under the SQL.

Project step P6 · Complaint Intelligence

Goal: semantic view BANK_AI.COMPLAINTS.COMPLAINTS_SV over ENRICHED with dimensions PRODUCT, CATEGORY, CHANNEL, SENTIMENT and date, and metrics complaint_count, urgent_count and share_negative, proven with five plain-English questions.

Key takeaway

Remember

Cortex Analyst turns questions into SQL, and the semantic view is its official catalogue. Good dimensions, metrics, synonyms and verified queries are what make the numbers right.

Glossary

Cortex Analyst
Snowflake's text-to-SQL feature for structured data.
Semantic view
A schema object holding business meaning: tables, relationships, facts, dimensions and metrics.
Fact
A row-level value, usually used to build a metric.
Dimension
An attribute to group or filter by, such as product or date.
Metric
An aggregated measure with a fixed formula, such as complaint_count.
Synonym
Another word users say for a table, dimension or metric.
Verified query
A question paired with SQL a person has approved, reused to answer similar questions.
Semantic model (YAML)
The older file-based format on a stage. Still supported; semantic views are recommended.
