Cortex Agents

Combine numbers and text in one assistant: an agent that plans, decides whether to ask Cortex Analyst, Cortex Search or both, and writes one grounded answer.

Definition

Key definition

A Cortex Agent is a Snowflake object that takes a question, plans the steps, calls tools such as Cortex Analyst and Cortex Search, checks the results and returns one answer. It runs a loop of planning, tool use and reflection.

Analyst is great at numbers. Search is great at text. Real questions need both: “Urgent UPI complaints doubled; what are people saying?” needs a count and the reasons. An agent splits the question into parts, sends each part to the right tool, reads what comes back and writes one answer.

  • Tools: Cortex Analyst (semantic views), Cortex Search, custom tools (stored procedures and UDFs), data-to-chart, code execution, MCP connectors, web search and more.
  • Threads: a thread keeps the conversation, so follow-up questions work. Each request is a run.
  • Interfaces: Snowsight playground, Snowflake CoWork (lesson 3.4), the REST API, and SQL.

Think of it like the head librarian

You ask the head librarian a big question. She does not run to the shelves herself. She makes a plan: “First I need the count, so I will ask the catalogue helper. Then I need what readers wrote, so I will ask the super index.” She reads both answers, checks they fit together, and only then replies to you, saying where each part came from. If something is missing, she asks one more helper or asks you to clarify.

How an agent run works

StageWhat happensOur example
1. PlanBreaks the request into subtasks and picks tools“Need the count (Analyst) and the reasons (Search)”
2. Use toolsCalls each tool with a focused requestAnalyst writes SQL on COMPLAINTS_SV; Search returns 5 complaints
3. ReflectChecks the results; may call another tool or ask a clarifying question“Counts are by month; reasons match UPI. Enough.”
4. RespondWrites the answer with the SQL, citations and optional chart“6 urgent UPI complaints in September, mostly debited-but-failed payments [2][32]”

The specification is YAML inside CREATE AGENT … FROM SPECIFICATION $$ … $$ (limit 100,000 bytes). Its main keys:

KeyPurpose
models.orchestrationThe planning model. auto lets Snowflake choose; or name one, such as claude-sonnet-4-6.
orchestration.budgetCaps one run by seconds and tokens, a cost guardrail
instructions.responseHow to write answers (tone, length, citations)
instructions.orchestrationWhen to use which tool. This is where most quality comes from.
instructions.sample_questionsStarter questions shown to users
toolsEach tool_spec has a type (cortex_analyst_text_to_sql, cortex_search…), a name and a description
tool_resourcesPer tool name: the semantic_view and warehouse, or the search_service, max_results, id_column, title_column
Cost and access

You pay for orchestration tokens, plus each tool: Analyst by tokens when called from an agent, Search by its index, and warehouse time for SQL and custom tools. Track it in SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY. To create an agent you need CREATE AGENT on the schema. To use one, a role needs SNOWFLAKE.CORTEX_USER or SNOWFLAKE.CORTEX_AGENT_USER, USAGE on the agent, and access to every tool's objects. The agent runs with the caller's role, so a user never sees data their role cannot see.

Real syntax

1. Create the agent. The tool descriptions and orchestration instructions are the most important lines: the model reads them to decide which helper to call.

CREATE OR REPLACE AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT
  COMMENT = 'Complaint Intelligence: numbers and customer voice in one place'
  PROFILE = '{"display_name": "Complaint Intelligence"}'
  FROM SPECIFICATION
  $$
  models:
    orchestration: auto
  orchestration:
    budget:
      seconds: 60
      tokens: 16000
  instructions:
    response: "Answer in at most 6 sentences. Give numbers first, then reasons. Cite complaint IDs in square brackets. Say clearly when data is missing."
    orchestration: "Use ComplaintMetrics for counts, shares, trends and rankings. Use ComplaintSearch for what customers say, examples and reasons. If a question asks how many AND why, use both: first ComplaintMetrics, then ComplaintSearch."
    sample_questions:
      - question: "How many urgent complaints did each product get?"
      - question: "What are customers saying about UPI failures?"
      - question: "Which channel has the most negative complaints, and what are they about?"
  tools:
    - tool_spec:
        type: "cortex_analyst_text_to_sql"
        name: "ComplaintMetrics"
        description: "Counts and shares of bank complaints by product, category, channel, sentiment and date."
    - tool_spec:
        type: "cortex_search"
        name: "ComplaintSearch"
        description: "Searches the English text of customer complaints to find what customers say."
  tool_resources:
    ComplaintMetrics:
      semantic_view: "BANK_AI.COMPLAINTS.COMPLAINTS_SV"
      execution_environment:
        type: "warehouse"
        warehouse: "LEARN_WH"
    ComplaintSearch:
      search_service: "BANK_AI.COMPLAINTS.COMPLAINT_SEARCH"
      max_results: 5
      id_column: "COMPLAINT_ID"
      title_column: "PRODUCT"
  $$;

2. Ask it from SQL with SNOWFLAKE.CORTEX.DATA_AGENT_RUN. It returns a non-streaming JSON string, so wrap it in TRY_PARSE_JSON.

SELECT TRY_PARSE_JSON(SNOWFLAKE.CORTEX.DATA_AGENT_RUN(
  'BANK_AI.COMPLAINTS.COMPLAINT_AGENT',
  $${"messages": [{"role": "user", "content": [
      {"type": "text", "text": "How many urgent UPI complaints are there, and what are they about?"}]}]}$$
)) AS resp;

The answer is in resp:content, an array of items: thinking, tool_use, tool results and finally text. A top-level warnings array appears if, for example, your role cannot use one of the tools.

3. Over REST (apps): POST /api/v2/databases/BANK_AI/schemas/COMPLAINTS/agents/COMPLAINT_AGENT:run. The response streams by default as server-sent events (response.text.delta and so on, ending with a response event). For follow-ups, create a thread and send thread_id with parent_message_id (0 for the first message).

4. Manage it. SHOW AGENTS IN SCHEMA BANK_AI.COMPLAINTS;, DESCRIBE AGENT COMPLAINT_AGENT;, DROP AGENT …;. You can also build and edit agents in Snowsight under AI & ML » Agents.

In practice: a bank

Question from the businessTools the agent should pick
How many complaints per channel last month?Analyst only
What do customers say about card blocks abroad?Search only
Negative share for credit cards is rising. Why?Analyst (trend), then Search (reasons)
Draft a weekly complaints note for the COOBoth, plus a chart; review before sending

Banks test agents with a fixed list of questions like these, checking the tool choice as well as the answer. A right number from the wrong tool is luck, not quality.

Lab: create and test the agent

From CREATE AGENT to the Snowsight playground

About 20 minNeeds P5 and P6

  1. Check both tools exist.

    USE WAREHOUSE LEARN_WH;
SHOW CORTEX SEARCH SERVICES IN SCHEMA BANK_AI.COMPLAINTS;
SHOW SEMANTIC VIEWS IN SCHEMA BANK_AI.COMPLAINTS;

    Expected: COMPLAINT_SEARCH and COMPLAINTS_SV, one row each.

  2. Run the CREATE OR REPLACE AGENT statement from the Syntax section.

    Expected: “Agent COMPLAINT_AGENT successfully created.” A YAML indentation error means a space is off: keep two spaces per level.

  3. Run the DATA_AGENT_RUN query. Click the result cell to open the JSON.

    Expected: a content array with a ComplaintMetrics tool call (with SQL), a ComplaintSearch tool call (with complaint IDs) and a final text answer.

  4. Open AI & ML » Agents » COMPLAINT_AGENT and use the playground. Expand the steps under each answer to see the plan and tool calls. Ask a follow-up such as “only for the app channel” to see the thread keep context.

Project step P7: Combine both in a Cortex Agent

Project step P7 · Complaint Intelligence

Goal: agent BANK_AI.COMPLAINTS.COMPLAINT_AGENT with ComplaintMetrics (Analyst on COMPLAINTS_SV) and ComplaintSearch (COMPLAINT_SEARCH), tested with questions that need numbers, text and both.

  1. Create the agent (lab steps 1 and 2).

  2. Ask these six in the playground and write down, for each, the tools used and whether the answer is right:

    • Numbers: “How many urgent complaints per product?” and “Share of negative complaints by channel?” (expect ComplaintMetrics only)
    • Text: “What do customers say about refunds?” and “Give three example complaints about card blocks” (expect ComplaintSearch only)
    • Both: “Which product has the most urgent complaints, and what are they about?” and “Is the call centre worse than the app, and why?” (expect both)

    Expected: 6 of 6 with the right tools. If a text question goes to Analyst, sharpen the tool descriptions and orchestration instructions, re-run CREATE OR REPLACE AGENT and test again.

  3. Keep the agent. Lesson 3.4 puts it in CoWork, and P8 calls it from the Streamlit app.

Key takeaway

Remember

An agent is the head librarian: it plans, sends Analyst for numbers and Search for words, checks the results and writes one cited answer. Clear tool descriptions and orchestration instructions decide its quality.

Glossary

Cortex Agent
A Snowflake object that orchestrates tools to answer a request.
Orchestration
Planning which tools to call, in what order, and when to stop.
Tool
A capability the agent can call: Analyst, Search, a stored procedure and others.
Specification
The YAML that defines models, instructions, tools and tool resources.
Thread
A saved conversation, so follow-up questions keep context.
Run
One request to the agent and its response.
DATA_AGENT_RUN
SQL function that runs an agent and returns JSON, without streaming.
Budget (orchestration)
Seconds and tokens limits for a single run.
