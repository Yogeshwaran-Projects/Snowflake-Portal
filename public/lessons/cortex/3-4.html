Definition

Key definition

Snowflake CoWork is Snowflake's ready-to-use agentic chat application for business users. Its “data agents” are Cortex Agents, so people ask questions in plain English over structured and unstructured data and get answers, charts and actions.

Until June 2026 it was called Snowflake Intelligence, and many SQL commands still use that name (for example CREATE SNOWFLAKE INTELLIGENCE). Cortex Code was renamed CoCo at the same time. You will hear all four names on projects.

  • Users: managers, operations, relationship managers. People who will never open a SQL worksheet.
  • Builders: you. You build the agent (lesson 3.3), the semantic view and the search service. CoWork is the front door.
  • Where: https://ai.snowflake.com (or a private-link URL), the Snowsight “Preview in Snowflake CoWork” link, and an iOS app.

Think of it like the friendly front desk

Most visitors never walk into the back rooms of the sky library. They go to the front desk, ask a question and get a neat answer, sometimes with a chart. Behind the desk, the head librarian (the agent) does the work with her helpers. The desk only offers the helpers the library has approved, and every visitor still shows their ID badge, so nobody gets a book they are not allowed to read.

How agents reach CoWork

An account has one CoWork object, named SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT when created from the UI. If it exists, an agent shows up in CoWork only after you add it. That gives admins a curated list.

-- Create the object once per account (ACCOUNTADMIN has this right by default)
CREATE SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT;

-- Publish our agent to CoWork, or remove it
ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
  ADD AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT;
ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
  DROP AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT;

-- Let users see the CoWork agent list; MODIFY lets a role add or remove agents
GRANT USAGE ON SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT TO ROLE complaints_reader;
GRANT USAGE ON AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT TO ROLE complaints_reader;
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_AGENT_USER TO ROLE complaints_reader;

SHOW SNOWFLAKE INTELLIGENCES;
ControlWhat it does
Caller's roleCoWork starts each session with the user's default role and default warehouse. Queries run with the user's credentials, so row access and masking policies apply.
Tool accessThe user's role needs USAGE on the agent, the search service and the semantic view, and SELECT on the tables.
CORTEX_AGENT_USERGives access only to the Agents API, enough for CoWork without other Cortex features. Banks often revoke the broad CORTEX_USER from PUBLIC and grant this instead.
ALLOWED_INTERFACESALTER USER … SET ALLOWED_INTERFACES = (SNOWFLAKE_INTELLIGENCE); limits a user to CoWork only.
Cost limitsResource budgets and per-user credit quotas. Track spend in SNOWFLAKE.ACCOUNT_USAGE.SNOWFLAKE_COWORK_USAGE_HISTORY.
What users get

Charts, saved and shareable artifacts, scheduled reports by email, Deep Research for multi-step investigations, file upload (up to 5 files of 50 MB), and document generation when the agent has the code execution tool. Older projects stored agents in a SNOWFLAKE_INTELLIGENCE.AGENTS schema; that approach is deprecated in favour of the CoWork object.

In practice: a bank

A typical rollout: the data team builds three agents (Complaints, Card Fraud Operations, Branch Performance), adds only the reviewed ones to CoWork, and gives each business team a role that can use only its agent. A complaints manager opens CoWork in the morning, picks Complaint Intelligence and asks “What changed in urgent complaints since Friday?”. She never sees fraud data because her role cannot, even if she asks the wrong agent.

Before go-live, the bank's checklist usually covers: default role and warehouse set for every invited user, CORTEX_USER revoked from PUBLIC, per-user quotas on, and a named owner for each agent's instructions.

Lab: open your agent in CoWork

Publish COMPLAINT_AGENT and ask it a question

About 10 minNeeds P7

  1. Check whether your trial already has the CoWork object.

    USE ROLE ACCOUNTADMIN;
SHOW SNOWFLAKE INTELLIGENCES;

    Expected: zero or one row. If zero, run the CREATE statement from the section above.

  2. Add the agent and make sure your user has a default warehouse.

    ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
  ADD AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT;
ALTER USER my_user SET DEFAULT_WAREHOUSE = LEARN_WH;  -- replace my_user with your username

    Expected: “Statement executed successfully.” twice. Run SELECT CURRENT_USER(); if you forgot your username.

  3. Open ai.snowflake.com (or Snowsight » AI & ML » Agents » COMPLAINT_AGENT » Preview in Snowflake CoWork), sign in and pick Complaint Intelligence. Ask: “Show urgent complaints by product as a bar chart, and tell me what the top one is about.”

    Expected: a chart, a short answer with complaint IDs, and expandable steps showing both tools.

Key takeaway

Remember

CoWork (formerly Snowflake Intelligence) is the front desk; Cortex Agents are the staff behind it. You publish an agent with ADD AGENT, and every answer still respects the user's role.

Glossary

Snowflake CoWork
Snowflake's chat application for business users, powered by Cortex Agents. Formerly Snowflake Intelligence.
CoWork object
The single account-level object (SQL keyword SNOWFLAKE INTELLIGENCE) that lists the agents users can see.
CORTEX_AGENT_USER
Database role giving access only to Cortex Agents.
ALLOWED_INTERFACES
User property that can restrict a user to CoWork only.
Default role
The role CoWork uses when a session starts.
