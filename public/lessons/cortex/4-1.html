ML functions: forecast, anomaly, classify

Definition

Key definition

Snowflake ML functions are built-in machine learning models you train and use from SQL: FORECAST predicts future values of a time series, ANOMALY_DETECTION flags values that are far from what was expected, and CLASSIFICATION sorts rows into classes using their columns.

You already know these ideas as a data scientist. What is new is the packaging: no Python, no feature pipeline, no model server. One CREATE statement trains a model object in your schema, and one method call (!FORECAST, !DETECT_ANOMALIES, !PREDICT) uses it.

  • Not LLMs: these models learn from numbers and categories in your table. They do not read text and there are no tokens to pay for.
  • Cost: compute while training and predicting, plus a little storage for each model. Drop models you no longer use.
  • Immutable: a model cannot be updated in place. To retrain, create it again.
  • A fourth function, Top Insights, finds which dimensions explain a change in a metric.

Think of it like three new library staff

The sky library hires three specialists. The weather forecaster studies how many visitors came each day and says “tomorrow about 52, most likely between 44 and 60”. The smoke alarm knows what a normal day looks like and rings when something is far outside it. The sorting hat looks at each new letter and says which pile it belongs in, and how sure it is.

How each one works

FunctionYou give itYou get backBank example
FORECASTA timestamp column and a target number; optional series column and extra featuresSERIES, TS, FORECAST, LOWER_BOUND, UPPER_BOUNDDaily complaint volume for the next 14 days, for staffing
ANOMALY_DETECTIONHistory to learn from, then new rows to check; optional label column of known anomaliesTS, Y, FORECAST, bounds, IS_ANOMALY, PERCENTILE, DISTANCEA sudden jump in complaints or in card transactions for one merchant
CLASSIFICATIONRows with feature columns and a target class columnAn object with class and probability per classWill this complaint escalate to the ombudsman?
Under the hood

FORECAST by default uses an ensemble of Prophet, ARIMA, exponential smoothing and a gradient boosting machine; the 'fast' method uses only the gradient boosting machine with lags, rolling averages and calendar features. Each series needs at least 12 rows; with 2 to 11 rows you get a naive forecast that repeats the last value. The default prediction interval is 0.95 for FORECAST and 0.99 for anomaly detection (a higher value flags fewer anomalies). ANOMALY_DETECTION can only check timestamps after its training data. To create a model your role needs, for example, CREATE SNOWFLAKE.ML.FORECAST on the schema.

Real syntax

Forecast: train, predict 14 days, then check quality.

CREATE OR REPLACE SNOWFLAKE.ML.FORECAST BANK_AI.COMPLAINTS.VOLUME_FORECAST(
  INPUT_DATA       => TABLE(BANK_AI.COMPLAINTS.DAILY_VOLUME_TRAIN),
  TIMESTAMP_COLNAME => 'DAY_TS',
  TARGET_COLNAME    => 'VOLUME'
);

SELECT * FROM TABLE(BANK_AI.COMPLAINTS.VOLUME_FORECAST!FORECAST(
  FORECASTING_PERIODS => 14,
  CONFIG_OBJECT       => {'prediction_interval': 0.9}));

CALL BANK_AI.COMPLAINTS.VOLUME_FORECAST!SHOW_EVALUATION_METRICS();
CALL BANK_AI.COMPLAINTS.VOLUME_FORECAST!EXPLAIN_FEATURE_IMPORTANCE();

Many series at once (one per product)? Add SERIES_COLNAME => 'PRODUCT'. Extra columns in the input become features, and then you must supply their future values when forecasting.

Anomaly detection: learn normal, then check new days. LABEL_COLNAME => '' means unsupervised.

CREATE OR REPLACE SNOWFLAKE.ML.ANOMALY_DETECTION BANK_AI.COMPLAINTS.VOLUME_ALARM(
  INPUT_DATA        => TABLE(BANK_AI.COMPLAINTS.DAILY_VOLUME_TRAIN),
  TIMESTAMP_COLNAME => 'DAY_TS',
  TARGET_COLNAME    => 'VOLUME',
  LABEL_COLNAME     => '');

CALL BANK_AI.COMPLAINTS.VOLUME_ALARM!DETECT_ANOMALIES(
  INPUT_DATA        => TABLE(BANK_AI.COMPLAINTS.DAILY_VOLUME_TEST),
  TIMESTAMP_COLNAME => 'DAY_TS',
  TARGET_COLNAME    => 'VOLUME');

Classification: illustrative, for a table where past complaints carry a known ESCALATED label.

CREATE OR REPLACE SNOWFLAKE.ML.CLASSIFICATION ESCALATION_MODEL(
  INPUT_DATA     => SYSTEM$REFERENCE('VIEW', 'ESCALATION_TRAIN'),  -- PRODUCT, CHANNEL, SENTIMENT, IS_URGENT, DAYS_OPEN, ESCALATED
  TARGET_COLNAME => 'ESCALATED');

SELECT ESCALATION_MODEL!PREDICT(INPUT_DATA => {*}) AS prediction
FROM NEW_COMPLAINT_FEATURES;          -- same feature columns, no label

CALL ESCALATION_MODEL!SHOW_EVALUATION_METRICS();
CALL ESCALATION_MODEL!SHOW_CONFUSION_MATRIX();
CALL ESCALATION_MODEL!SHOW_FEATURE_IMPORTANCE();

Read a prediction with prediction:class and prediction:probability. Results come back in the same order as the input rows. Manage models with SHOW SNOWFLAKE.ML.FORECAST; and DROP SNOWFLAKE.ML.FORECAST name; (same pattern for the others).

Lab: forecast and catch a spike

Daily complaint volume in BANK_AI.COMPLAINTS

About 20 minUses LEARN_WH

  1. Our project has only 60 complaints, too few for a time series. Create 150 days of realistic synthetic volume, with quieter weekends, a slow upward trend and one injected spike.

    USE WAREHOUSE LEARN_WH;
USE SCHEMA BANK_AI.COMPLAINTS;
CREATE OR REPLACE TABLE DAILY_VOLUME AS
SELECT DATEADD('day', n, '2026-05-01'::DATE)::TIMESTAMP_NTZ AS DAY_TS,
       40 + IFF(DAYOFWEEK(DATEADD('day', n, '2026-05-01'::DATE)) IN (0, 6), -15, 0)
          + MOD(n * 7, 9) + FLOOR(n / 10) + IFF(n = 145, 90, 0) AS VOLUME
FROM (SELECT ROW_NUMBER() OVER (ORDER BY SEQ4()) - 1 AS n
      FROM TABLE(GENERATOR(ROWCOUNT => 150)));

CREATE OR REPLACE VIEW DAILY_VOLUME_TRAIN AS SELECT * FROM DAILY_VOLUME WHERE DAY_TS <  '2026-09-08';
CREATE OR REPLACE VIEW DAILY_VOLUME_TEST  AS SELECT * FROM DAILY_VOLUME WHERE DAY_TS >= '2026-09-08';

    Expected: DAILY_VOLUME with 150 rows; the train view has 130 rows, the test view 20.

  2. Run the three Forecast statements from the Syntax section (create, forecast, evaluation metrics), then feature importance.

    Expected: training takes under a minute on XSMALL. 14 forecast rows starting 2026-09-08, lower on weekends. Evaluation shows metrics such as MAE and MAPE. Feature importance lists items such as day of week and trend.

  3. Run the two Anomaly detection statements.

    Expected: 20 rows; 2026-09-23 has IS_ANOMALY = TRUE with Y far above UPPER_BOUND. The other days should be FALSE.

  4. Save the forecast for a dashboard, then clean up the models (they cost storage).

    CREATE OR REPLACE TABLE VOLUME_FORECAST_14D AS
SELECT * FROM TABLE(VOLUME_FORECAST!FORECAST(FORECASTING_PERIODS => 14));
DROP SNOWFLAKE.ML.ANOMALY_DETECTION VOLUME_ALARM;

    Expected: a 14-row table. Keep VOLUME_FORECAST for now if you want to explore.

Key takeaway

Remember

FORECAST is the weather forecaster, ANOMALY_DETECTION the smoke alarm and CLASSIFICATION the sorting hat. Train with CREATE, use with !FORECAST, !DETECT_ANOMALIES or !PREDICT, and always read the bounds and probabilities, not just the point value.

Glossary

Time series
Values measured at regular times, such as complaints per day.
Prediction interval
The range the true value should fall in, with a stated probability (for example 0.95).
Anomaly
A value outside the expected range for its time.
Supervised / unsupervised
With or without a column of known answers (labels) to learn from.
Feature importance
How much each input column helped the model's predictions.
Confusion matrix
A table of predicted versus actual classes, showing where a classifier is wrong.
Model instance
The trained object created by CREATE SNOWFLAKE.ML.…; immutable once trained.
