Definition

Key definition

AI governance in Snowflake is the set of controls that decide who can call which AI feature and model, what data may go into a prompt, which answers may come out, and how much it may cost. Guardrails are the controls that filter unsafe inputs or outputs.

The good news: Cortex runs inside Snowflake, so your existing roles, masking policies, row access policies and audit logs already apply. You add four AI-specific layers on top: feature access, model access, content safety and cost control.

Think of it like a polite bouncer

The sky library has a polite bouncer at the reading room. He checks your ID badge before you may talk to the smart readers, and only lets you talk to the readers your badge allows. He reads every answer before it leaves the room and stops anything harmful. He blacks out names and phone numbers on letters before they go in. And he keeps a tally of how many minutes each visitor uses, and closes the door when a team's monthly allowance runs out.

Layer 1 and 2: who may use what

Database roles cannot be granted to users directly: grant them to an account role, then the role to users. A bank usually revokes CORTEX_USER from PUBLIC and grants narrow roles per team.

Model access is a separate check: model RBAC. Every model is an object in SNOWFLAKE.MODELS with an application role such as CORTEX-MODEL-ROLE-LLAMA3.1-70B, plus CORTEX-MODEL-ROLE-ALL for every current and future model.

CORTEX_MODELS_ALLOWLIST is being retired

The old account parameter that listed allowed models is deprecated. Per Snowflake's release notes: from 5 August 2026 it can only be set to 'None'; allowlist-based access control was removed on 8 September 2026, leaving model RBAC as the only mechanism; full retirement is planned for 18 November 2026 (dates may change). You will still see the parameter in older project code and interview questions, so know both. Test grants with a role other than ACCOUNTADMIN, which can always use every model.

Cross-region inference (CORTEX_ENABLED_CROSS_REGION) is the other model-access decision: it lets a request be processed in another region. Banks often keep it off or limit it to one geography for data residency.

Layer 3: guardrails and personal data

Cortex GuardAdd 'guardrails': true to AI_COMPLETE's model parameters. Responses classified as unsafe are filtered before they reach you. Built with Meta's Llama Guard 3; billed on the input tokens it processes, on top of AI_COMPLETE. Off by default.Output safety
AI_REDACTReplaces PII in text with placeholders such as [NAME] and [PHONE_NUMBER], or returns the spans in detect mode. Best on English; best-effort, so review it. Limit 4,096 tokens in plus out.PII removal
Masking and row policiesStill apply to every AI query, agent and CoWork session, because they run with the caller's role.Existing controls
Prompt rulesDelimit user text (for example inside tags), tell the model it is data, not instructions, and never let a prompt grant access. Roles decide access, prompts do not.Prompt injection

AI_REDACT categories: NAME, EMAIL, PHONE_NUMBER, DATE_OF_BIRTH, GENDER, AGE, ADDRESS, NATIONAL_ID, PASSPORT, TAX_IDENTIFIER, PAYMENT_CARD_DATA, DRIVERS_LICENSE, IP_ADDRESS. Coverage is mainly US PII plus some UK and Canadian types, so test it on Indian formats (Aadhaar, PAN, UPI IDs) before relying on it, and keep masking policies as the first line.

Exact credit rates live in Snowflake's Service Consumption Table and change over time, so always quote the current table, never a number you remember. Older views CORTEX_FUNCTIONS_USAGE_HISTORY and CORTEX_FUNCTIONS_QUERY_USAGE_HISTORY are slated for deprecation (their data ends November 2025); use CORTEX_AI_FUNCTIONS_USAGE_HISTORY. Search's daily view includes embeddings, so do not add them twice.

Controls: a custom budget (SNOWFLAKE.CORE.BUDGET) with a monthly credit limit and notifications; resource budgets for agents via a tag, with actions such as revoking access at 100%; per-user quotas for individual credit limits; and the orchestration budget per agent run (lesson 3.3).

Real syntax

-- 1. Narrow access: no AI for everyone, agents only for the complaints team
REVOKE DATABASE ROLE SNOWFLAKE.CORTEX_USER FROM ROLE PUBLIC;
CREATE ROLE IF NOT EXISTS complaints_reader;
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_AGENT_USER TO ROLE complaints_reader;

-- 2. Model RBAC: list models and give one model to one role
SHOW MODELS IN SNOWFLAKE.MODELS;
SHOW APPLICATION ROLES LIKE 'CORTEX-MODEL%' IN APPLICATION SNOWFLAKE;
GRANT APPLICATION ROLE SNOWFLAKE."CORTEX-MODEL-ROLE-LLAMA3.1-70B" TO ROLE complaints_reader;

-- 3. Guardrails on a generation
SELECT AI_COMPLETE(
  model => 'llama3.1-70b',
  prompt => 'Draft a reply to this complaint: ' || TEXT_EN,
  model_parameters => {'guardrails': TRUE, 'max_tokens': 300})
FROM BANK_AI.COMPLAINTS.ENRICHED LIMIT 3;

-- 4. Remove PII before text goes anywhere else
SELECT AI_REDACT('I am Priya Menon, call me on 555-201-4477 about card 4111 1111 1111 1111');
SELECT AI_REDACT('Mail priya.menon@example.com', ['EMAIL']);

-- 5. What did AI cost, by function and model?
SELECT function_name, model_name, SUM(credits) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE start_time >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2 ORDER BY credits DESC;

-- 6. A monthly budget of 50 credits (in a schema you own)
CREATE SNOWFLAKE.CORE.BUDGET BANK_AI.COMPLAINTS.AI_BUDGET();
CALL BANK_AI.COMPLAINTS.AI_BUDGET!SET_SPENDING_LIMIT(50);

Lab: lock it down and read the bill

Roles, redaction, guardrails and usage on your trial

About 15 minACCOUNTADMIN on your own trial only

  1. See which models your account knows and their roles.

    USE ROLE ACCOUNTADMIN;
USE WAREHOUSE LEARN_WH;
SHOW MODELS IN SNOWFLAKE.MODELS;
SHOW APPLICATION ROLES LIKE 'CORTEX-MODEL%' IN APPLICATION SNOWFLAKE;

    Expected: one row per model, and one application role per model plus CORTEX-MODEL-ROLE-ALL. If the list is empty, run CALL SNOWFLAKE.MODELS.CORTEX_BASE_MODELS_REFRESH();.

  2. Run the two AI_REDACT queries from the Syntax section (step 4).

    Expected: the name, phone and card number replaced by placeholders such as [NAME], [PHONE_NUMBER] and [PAYMENT_CARD_DATA]; in the second query only the email is redacted.

  3. Run the guardrails query (step 3). Then try a harmful prompt of your own, such as asking for instructions to bypass card security.

    Expected: normal drafts for normal complaints; the harmful request is filtered instead of answered.

  4. Run the cost query (step 5).

    Expected: rows for AI_COMPLETE, AI_CLASSIFY and others you used in this course, with small credit amounts. Data can take a few hours to appear.

  5. Do not run the REVOKE in step 1 on a shared or client account. On your own trial it is safe, but grant CORTEX_USER back to your working role afterwards.

Key takeaway

Remember

The polite bouncer has four jobs: database roles for features, model RBAC for models (the allowlist is retired), Cortex Guard and AI_REDACT for content, and usage views plus budgets for cost.

Glossary

Database role
A role inside a database (here SNOWFLAKE) that bundles privileges; granted to account roles.
Model RBAC
Controlling which roles can use which models through model application roles.
CORTEX_MODELS_ALLOWLIST
Retired account parameter that once listed allowed models.
Cortex Guard
Safety filter for AI_COMPLETE output, switched on with guardrails: true.
AI_REDACT
AI function that replaces personal data in text with placeholders.
PII
Personally identifiable information, such as names, phone numbers and IDs.
Budget
A Snowflake object with a monthly credit limit and notifications or actions.
Per-user quota
A credit limit for one user, enforced within minutes.
