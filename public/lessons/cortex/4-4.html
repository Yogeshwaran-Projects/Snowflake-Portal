Definition

Key definition

Streamlit in Snowflake lets you build a data web app in Python that runs inside Snowflake as a STREAMLIT object. Users open it in Snowsight; it queries data through a Snowpark session, with no server to host and no data leaving the platform.

Streamlit turns a Python script into a web page: st.multiselect becomes a filter, st.bar_chart a chart, st.chat_input a chat box. Inside Snowflake you get the session for free with get_active_session().

Owner's rights: read this twice

A Streamlit in Snowflake app runs with the privileges of its owner role, not the viewer's. Every viewer sees what the owner can see, including through the agent. So own the app with a role that has only the data viewers may see, never ACCOUNTADMIN on a real project, and share the app only with the roles that should use it. Container-runtime apps can instead use restricted caller's rights (Streamlit 1.53.1 or later), where admins choose which of the viewer's privileges the app may use; the warehouse runtime does not support it. To create it you need CREATE STREAMLIT on the schema and USAGE on the query warehouse. The app is not live until you open it in Snowsight with the owning role (or run ALTER STREAMLIT … ADD LIVE VERSION FROM LAST).

Real syntax: the app

Paste this whole file into the Snowsight editor as streamlit_app.py. It uses only Streamlit, pandas and Snowpark, which the warehouse runtime already provides.

import json
import streamlit as st
from snowflake.snowpark.context import get_active_session

AGENT = "BANK_AI.COMPLAINTS.COMPLAINT_AGENT"
session = get_active_session()
st.title("Complaint Intelligence")

@st.cache_data(ttl=600)
def load():
    return session.sql("""
        SELECT COMPLAINT_ID, PRODUCT, CATEGORY, CHANNEL, SENTIMENT, IS_URGENT, SUBMITTED_AT
        FROM BANK_AI.COMPLAINTS.ENRICHED""").to_pandas()

df = load()
all_products = sorted(df["PRODUCT"].unique())
all_channels = sorted(df["CHANNEL"].unique())
products = st.multiselect("Product", all_products, default=all_products)
channels = st.multiselect("Channel", all_channels, default=all_channels)
view = df[df["PRODUCT"].isin(products) & df["CHANNEL"].isin(channels)]

c1, c2, c3 = st.columns(3)
c1.metric("Complaints", len(view))
c2.metric("Urgent", int(view["IS_URGENT"].astype(int).sum()))
neg = (view["SENTIMENT"].str.lower() == "negative").mean() if len(view) else 0
c3.metric("Share negative", f"{neg:.0%}")

st.subheader("Complaints by category")
st.bar_chart(view.groupby("CATEGORY").size())

st.subheader("Ask Complaint Intelligence")
if "history" not in st.session_state:
    st.session_state.history = []
for who, text in st.session_state.history:
    st.chat_message(who).markdown(text)

question = st.chat_input("For example: what are customers saying about UPI failures?")
if question:
    st.chat_message("user").markdown(question)
    body = json.dumps({"messages": [{"role": "user",
                       "content": [{"type": "text", "text": question}]}]})
    with st.spinner("Asking the agent..."):
        raw = session.sql("SELECT SNOWFLAKE.CORTEX.DATA_AGENT_RUN(?, ?)",
                          params=[AGENT, body]).collect()[0][0]
    resp = json.loads(raw)
    answer = "\n\n".join(c["text"] for c in resp.get("content", [])
                         if c.get("type") == "text") or "No answer returned."
    st.chat_message("assistant").markdown(answer)
    st.session_state.history += [("user", question), ("assistant", answer)]

Each chat question is a fresh agent run. For true follow-ups, create a thread and pass thread_id and parent_message_id in the body (lesson 3.3). If DATA_AGENT_RUN is not available in your account, replace the chat call with the RAG query from P5.

Prefer code over clicks? The same app as SQL, with the file uploaded to a stage first:

CREATE STAGE IF NOT EXISTS BANK_AI.COMPLAINTS.APP_STAGE;
-- upload streamlit_app.py to @APP_STAGE/complaint_app/ in Snowsight (Data » Add data » Load files into a stage)
CREATE OR REPLACE STREAMLIT BANK_AI.COMPLAINTS.COMPLAINT_APP
  FROM '@BANK_AI.COMPLAINTS.APP_STAGE/complaint_app'
  MAIN_FILE = 'streamlit_app.py'
  QUERY_WAREHOUSE = LEARN_WH
  TITLE = 'Complaint Intelligence';

In practice: a bank

A complaints dashboard like this usually goes through three gates before business users see it: security (owner role reviewed, app shared only with named roles, no PII on screen unless masked), quality (the golden-set scores from lesson 4.2 attached to the release), and cost (a budget on the project and a weekly cost check like the one below). Because the app runs inside Snowflake, there is no separate hosting, firewall or credential to approve, which shortens the security review a lot.

Project step P8: Ship the Streamlit app and review cost

Project step P8 · Complaint Intelligence

Goal: the Streamlit app BANK_AI.COMPLAINTS.COMPLAINT_APP with filters, KPI tiles, a chart and an agent chat box, then a cost review of everything P1 to P8 created, and a clean-up plan.

  1. In Snowsight open Projects » Streamlit and select + Streamlit App. Title: Complaint Intelligence; app location: BANK_AI.COMPLAINTS; warehouse: LEARN_WH; runtime: warehouse. Name the object COMPLAINT_APP (rename it later with ALTER STREAMLIT … RENAME TO if the UI chose another name).

    Expected: an editor with a sample app on the left and its preview on the right.

  2. Replace the sample with the app code above and select Run.

    Expected: three KPI tiles (Complaints 60 with all filters on), a bar chart by category and a chat box. Untick a product and every tile changes.

  3. Ask in the chat: “Which product has the most urgent complaints, and what are they about?”

    Expected: a number from the semantic view and reasons with complaint IDs, in 5 to 20 seconds.

  4. Cost review. Run these and write the totals in your notes:

    SELECT warehouse_name, SUM(credits_used) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.WAREHOUSE_METERING_HISTORY
WHERE warehouse_name = 'LEARN_WH' AND start_time >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1;

SELECT function_name, model_name, SUM(credits) AS credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
WHERE start_time >= DATEADD('day', -30, CURRENT_TIMESTAMP())
GROUP BY 1, 2 ORDER BY credits DESC;

SELECT * FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_SEARCH_DAILY_USAGE_HISTORY
ORDER BY usage_date DESC LIMIT 20;

SELECT * FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY
ORDER BY start_time DESC LIMIT 20;

    Expected: small numbers. The search service often shows a steady daily serving cost even when nobody queries it: that is the line to watch.

  5. Clean up when you finish the course. Keep data and drop or pause what bills while idle:

    ALTER WAREHOUSE LEARN_WH SET AUTO_SUSPEND = 60;
ALTER CORTEX SEARCH SERVICE BANK_AI.COMPLAINTS.COMPLAINT_SEARCH SUSPEND SERVING;   -- or DROP when done
-- When the course is over:
-- DROP STREAMLIT BANK_AI.COMPLAINTS.COMPLAINT_APP;
-- DROP AGENT BANK_AI.COMPLAINTS.COMPLAINT_AGENT;
-- DROP CORTEX SEARCH SERVICE BANK_AI.COMPLAINTS.COMPLAINT_SEARCH;

    Expected: “Statement executed successfully.” Resume serving with RESUME SERVING before you use P5 or P7 again.

Key takeaway

Remember

Streamlit in Snowflake is the reading room that brings filters, charts and the agent together, running with its owner's rights. Ship it only after a cost review, and pause or drop anything that bills while idle.

Glossary

Streamlit
An open-source Python library that turns scripts into web apps.
Streamlit in Snowflake
Streamlit apps stored and run as STREAMLIT objects inside Snowflake.
Owner's rights
The app runs with its owner role's privileges, whoever views it.
Snowpark session
The Python connection the app uses to run SQL in Snowflake.
Warehouse runtime
Default runtime; each viewer gets a personal instance on a warehouse.
Container runtime
Runtime on a compute pool where viewers share one instance.
Suspend serving
Pausing a Cortex Search service so it stops serving queries.
