How one question flows through it

A manager types into COMPLAINT_APP: “Which channel has the most negative complaints, and why?”

  1. The app calls COMPLAINT_AGENT with DATA_AGENT_RUN, running as the app owner's role.
  2. The agent plans: a number part and a reason part.
  3. ComplaintMetrics (Cortex Analyst) reads COMPLAINTS_SV, writes SQL using share_negative by channel, and runs it on LEARN_WH.
  4. ComplaintSearch (Cortex Search) queries COMPLAINT_SEARCH with a filter on that channel and returns 5 complaints.
  5. The agent reflects, then answers with the number first and reasons with complaint IDs.
  6. Usage lands in CORTEX_AGENT_USAGE_HISTORY and the warehouse meter, ready for the weekly cost review.

Interview Q&A

Open each question, answer it out loud first, then compare. Keep answers to about 30 seconds.

1. What is Snowflake Cortex?

Cortex is Snowflake's built-in AI layer. It includes AI SQL functions such as AI_COMPLETE, AI_CLASSIFY and AI_EXTRACT, plus managed services: Cortex Search for retrieval, Cortex Analyst for text-to-SQL, Cortex Agents for orchestration, and fine-tuning. Models run inside Snowflake, so data stays under the same governance.

2. What is the difference between CoCo and Cortex?

CoCo (formerly Cortex Code) is an AI coding assistant for builders: it helps you write SQL, Python and pipelines in Snowsight or a CLI. Cortex is the AI capability you put inside your data and apps: functions, Search, Analyst and Agents. CoCo helps you build; Cortex is what you build with.

3. How do CoWork and Cortex Agents relate?

Cortex Agents are the engine: objects with instructions and tools. Snowflake CoWork, formerly Snowflake Intelligence, is the ready-made chat application where business users talk to agents. You publish an agent to CoWork with ALTER SNOWFLAKE INTELLIGENCE … ADD AGENT.

4. What is RAG and why does a bank like it?

Retrieval-augmented generation: retrieve the most relevant documents first, then ask the LLM to answer only from them. Banks like it because answers are grounded in their own current data and can cite sources, which makes them auditable, without training a model on sensitive data.

5. How does Cortex Search rank results?

Hybrid search: vector similarity on embeddings for meaning, keyword matching for exact terms, then semantic reranking of the top results. Scoring can be tuned with boosts, time decay and weights.

6. What do TARGET_LAG and WAREHOUSE do in CREATE CORTEX SEARCH SERVICE?

TARGET_LAG sets how far the index may fall behind the source table. WAREHOUSE runs the source query and builds and refreshes the index. Refreshes cost nothing when no changes are found.

7. Can you change the embedding model of a search service later?

No. EMBEDDING_MODEL cannot be altered after creation; you recreate the service. The default is snowflake-arctic-embed-m-v1.5.

8. How would you chunk long documents for search?

Split them into chunks of no more than about 512 tokens (around 385 words), as Snowflake recommends, keep a document ID and title as attributes, and return the ID for citations. Smaller chunks usually improve retrieval precision.

9. How do you reduce hallucinations?

Ground answers with RAG, instruct the model to use only the provided context and to say when evidence is missing, require citations, keep temperature low, use structured output where possible, and measure groundedness on a golden set every release.

10. When do you use Cortex Analyst versus Cortex Search?

Analyst for questions answered by SQL over structured data: counts, sums, trends. Search for questions answered by reading text: what customers say, policy wording. When a question needs both, an agent uses both.

11. What is a semantic view? Facts versus dimensions versus metrics?

A schema object that stores business meaning for tables. Facts are row-level values, dimensions are attributes to group or filter by, and metrics are aggregations with a fixed formula. Relationships define joins; synonyms and comments help the model map words to fields.

12. How do you improve Cortex Analyst accuracy?

Business-friendly names, synonyms and comments; metrics defined once with the right aggregation; explicit relationships; custom SQL-generation instructions; verified queries for frequent questions; and a regression set of questions with known answers.

13. How does an agent choose its tools?

The orchestration model plans using the orchestration instructions and each tool's description, calls tools, reflects on results and may call more or ask a clarifying question. Clear descriptions and instructions are the main lever, and you test routing as well as answers.

14. Whose permissions apply in agents, CoWork and Streamlit apps?

Agents and CoWork run with the caller's role, so masking and row policies apply per user. Streamlit in Snowflake apps run with the owner's rights by default, so the owner role must be scoped to what viewers may see. Cortex Search services also run with owner's rights.

15. How do you control which LLMs can be used?

Model RBAC: each model has an application role in SNOWFLAKE, such as CORTEX-MODEL-ROLE-LLAMA3.1-70B, granted to account roles. The older CORTEX_MODELS_ALLOWLIST parameter is being retired in 2026. Feature access is separate, through database roles such as CORTEX_USER and CORTEX_AGENT_USER.

16. What about data residency?

Cortex processes requests in the account's region unless cross-region inference is enabled with CORTEX_ENABLED_CROSS_REGION. Banks often keep it off or limited to one geography, and choose models available in-region.

17. How do you handle PII?

Masking policies first, so roles never see raw PII. AI_REDACT to replace PII with placeholders before text goes into prompts or logs, tested on local formats. Minimise columns indexed in search services, and avoid PII in fine-tuning data.

18. What is Cortex Guard?

A safety filter for AI_COMPLETE, switched on with guardrails: true in model parameters. It filters responses classified as unsafe and is billed on input tokens. It complements, not replaces, access control and human review.

19. How do you evaluate a GenAI application?

A golden set of real questions with reference answers; metrics such as correctness, groundedness, context relevance, answer relevance and coherence; an LLM judge with a rubric plus human spot checks; and tracking per release. In Snowflake, AI Observability with TruLens stores traces and scores, shown under AI & ML » Evaluations.

20. When would you fine-tune instead of prompting or RAG?

For a narrow, repeated task with a fixed style where prompting is not enough, or to move a task from a large model to a cheaper small one at volume. Not to teach fresh facts: that is RAG. Cortex Fine-tuning uses FINETUNE with prompt and completion data.

21. How is Cortex billed and how do you monitor it?

AI functions by tokens at a per-model rate; Search by serving size, embeddings and refresh compute; Analyst per message; Agents by tokens plus tools; plus warehouses. Monitor with ACCOUNT_USAGE views such as CORTEX_AI_FUNCTIONS_USAGE_HISTORY and CORTEX_AGENT_USAGE_HISTORY, and cap with budgets and per-user quotas.

22. AI_SENTIMENT versus SNOWFLAKE.CORTEX.SENTIMENT?

AI_SENTIMENT is the current function and returns labels such as positive or negative, optionally per aspect. The legacy SNOWFLAKE.CORTEX.SENTIMENT returns a score from −1 to 1. New work should use the AI_ functions.

23. ML functions versus LLM functions?

ML functions (FORECAST, ANOMALY_DETECTION, CLASSIFICATION) learn from numbers and categories in your tables and cost compute, not tokens. LLM functions read and write language. They combine well: an anomaly says when complaints spiked, and search or summarisation says why.

24. How do you defend against prompt injection?

Treat user and document text as data: delimit it, tell the model not to follow instructions inside it, never let a prompt grant access (roles do that), restrict tools to least privilege, enable guardrails on outputs, and log runs for review.

25. Walk me through a GenAI project you built.

Complaint Intelligence: 60 bank complaints loaded into Snowflake, enriched with AI classification, sentiment, extraction and translation; a Cortex Search service for RAG with citations; a semantic view for Cortex Analyst; an agent combining both; a Streamlit app; evaluated with a golden set and LLM judge; governed with database roles, model RBAC and redaction; and reviewed for cost with usage views and budgets.
