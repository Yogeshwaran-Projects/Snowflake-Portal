SELECT and FROM

Your first SQL question: pick a table, pick the columns you want, and read the answer. Every query you ever write starts here.

20 min Beginner Practice: 6 questions

By the end of this lesson you can

  • Read a table as rows and columns
  • Write SELECT ... FROM ... to pull chosen columns
  • Rename a column with AS and do simple maths in a query
  • Use DISTINCT to list each different value once

Definition

Key definition

SELECT says which columns you want. FROM says which table to read them from. Together they are the smallest complete SQL question.

Data lives in tables. A table is a grid: each row is one thing (one customer, one account) and each column is one fact about it (name, city, balance). A query reads that grid and gives you back a smaller grid called the result.

You never change the table by reading it. SELECT only copies. That is why it is safe to try anything in this lesson.

Think of it like a library in the sky

Picture a huge library floating above the clouds. Every bookshelf has a name, such as customers. On that shelf, each book has one index card. Every card has the same fields: name, city, segment, joined on, age. You cannot walk in. Instead you fill out a request slip and hand it to the librarian. FROM customers tells her which shelf. SELECT cust_name, city tells her which fields to copy from every card. She comes back with a neat list.

In the libraryA bookshelfIn SQL: a table, such as customers
In the libraryOne index cardIn SQL: one row, such as customer 1, Asha Rao
In the libraryOne field on every cardIn SQL: one column, such as city

The request slip is your query. Write it clearly and the librarian never asks a question back.

How to write it, step by step

Step 1: name the shelf. Step 2: name the fields. Step 3: end with a semicolon (optional in the worksheet, polite everywhere).

SELECT cust_name, city
FROM customers;
KeywordWhat it meansTelling the librarian
SELECTThe columns to copy, separated by commas“Copy the name and the city…”
FROMThe table to read“…from every card on the customers shelf.”
*Every column“Copy the whole card.”
ASA new name for a column in the result“…and call that column ‘town’ on your list.”
DISTINCTEach different value once“Just list the different cities, no repeats.”

Order matters: SELECT always comes before FROM. Spaces and new lines do not matter. Capital letters for keywords are a habit, not a rule.

Common mistakes

Watch out

1. A missing comma: SELECT cust_name city does not fail. It returns the name under the heading city, because SQL reads it as cust_name AS city. Always check your commas.

2. A comma before FROM: SELECT cust_name, FROM customers is an error. The last column has no comma after it.

3. Wrong table or column name: the librarian cannot find a shelf called customer (singular). Open the Schema tab and copy names exactly.

4. Using * in real reports: it works, but on a table with 200 columns it is slow and nobody can read it. Name the columns you need.

On Snowflake

What is different on your project

Names are stored in upper case. You can type customers or CUSTOMERS; Snowflake treats both the same and shows them as CUSTOMERS. The only trap is a name created inside double quotes, such as "Customers". That one must always be typed in quotes, exactly as created.

Full names have three parts. On a real project the shelf lives in a room (schema) in a building (database): FROM bank_db.retail.customers. In this worksheet the short name is enough.

Try before you trust. Snowflake lets you preview a table with SELECT * FROM customers LIMIT 10. You learn LIMIT in lesson 1.3.

Key takeaway

Remember

FROM picks the shelf. SELECT picks the fields to copy. AS renames, maths is allowed, and DISTINCT removes repeats. Reading never changes the table.

Glossary

Table
Data in rows and columns. One bookshelf in the library.
Row
One record, such as one customer. One index card.
Column
One fact stored for every row, such as city. One field on every card.
Query
One SQL question. The request slip you hand to the librarian.
Result
The grid that comes back from a query.
Alias
A new name for a column in the result, given with AS.
DISTINCT
A SELECT option that returns each different value only once.
