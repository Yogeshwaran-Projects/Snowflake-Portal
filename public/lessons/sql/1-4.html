Text, number and date functions

Columns rarely come in the shape you need. Functions tidy text, round numbers and do date maths, one value at a time, inside your SELECT.

30 min Beginner Practice: 6 questions

By the end of this lesson you can

  • Clean text with UPPER, LOWER, TRIM, SUBSTR, LENGTH and ||
  • Shape numbers with ROUND, ABS and CAST
  • Pull a year or month out of a date with EXTRACT
  • Add time to a date and count days between two dates

Definition

Key definition

A function takes a value, does one job on it, and hands back a new value. You write it as a name followed by brackets: UPPER(cust_name).

A function runs on every row, one row at a time, and the table is never changed. The new value lives only in the result. You can use a function anywhere a column can go: in SELECT, in WHERE and in ORDER BY.

Functions nest. SUBSTR(LOWER(city), 1, 3) first lowers the city, then takes its first three letters. Read nested functions from the inside out.

Think of it like tools on the librarian's desk

The librarian copies a field from a card, then may use a tool before writing it on your list. A stamp turns letters into capitals. Scissors cut the first three letters. A ruler measures how long a name is. A calculator rounds a balance. A calendar flips forward one year or counts the days back to today. The card itself is never touched; only the copy on your list changes.

In the libraryStamp, scissors, rulerIn SQL: text functions such as UPPER, SUBSTR, LENGTH
In the libraryCalculatorIn SQL: number functions such as ROUND, ABS, CAST
In the libraryCalendarIn SQL: date functions such as EXTRACT, + INTERVAL, DATEDIFF

One tool per job. Two tools in a row is nesting: cut, then stamp.

Gluing a number onto text needs a conversion first: 'ID-' || CAST(cust_id AS VARCHAR). Some engines do it for you, but writing the CAST makes the query work everywhere.

Division keeps decimals on both engines: 7 / 2 is 3.5. Use ROUND when the report wants a tidy number, and round at the very end, never in the middle of a calculation.

Date functions

Why the CAST? Adding an INTERVAL in the worksheet engine gives a timestamp, a date with a time of 00:00:00 attached. CAST(... AS DATE) drops the time so the result reads as a plain date. On Snowflake, DATEADD on a DATE already gives a DATE.

Worked examples

Example 1: tidy names. Capitals for a mailing label and the length of each name.

SELECT cust_id, UPPER(cust_name) AS name_upper, LENGTH(cust_name) AS name_len
FROM customers;

Example 2: a city code. Three lower-case letters, a hyphen, the id. Nested functions, read from the inside out. A blank city gives a blank code.

SELECT cust_id, city,
       SUBSTR(LOWER(city), 1, 3) || '-' || CAST(cust_id AS VARCHAR) AS city_code
FROM customers;

Example 4: how long has each account been open? Days from opening to the report date 30 September 2026, then years to one decimal.

SELECT acct_id, opened_on,
       DATEDIFF('day', opened_on, DATE '2026-09-30') AS days_open,
       ROUND(DATEDIFF('day', opened_on, DATE '2026-09-30') / 365.25, 1) AS years_open
FROM accounts;

Common mistakes

Watch out

1. SUBSTR(city, 0, 3): positions start at 1, not 0. Start at 1 for the first letter.

2. ROUND(balance / 100000) with no second number rounds to a whole number. Say how many decimals you want.

3. 'Days: ' || 30 may fail. Glue only text to text: CAST(30 AS VARCHAR).

4. A function on a blank gives a blank. UPPER(NULL) is NULL, NULL + 10 is NULL. Lesson 1.5 shows how to fill blanks first.

5. Function names in WHERE are fine, but WHERE UPPER(city) = 'mumbai' matches nothing. Match capitals with capitals.

On Snowflake

What is different on your project

Date shorthands. Snowflake has DATEADD(day, 30, d), DATEDIFF(day, d1, d2), DATE_TRUNC(month, d), YEAR(d) and MONTH(d). The part name can be bare or in quotes: DATEDIFF('day', d1, d2) works on both engines, which is why this lesson uses it.

Converting text to dates. Snowflake's TO_DATE('30/09/2026', 'DD/MM/YYYY') reads odd formats; TO_CHAR(d, 'YYYY-MM') prints a date as text. The portable CAST(... AS DATE) only understands YYYY-MM-DD.

Same names, same results. UPPER, LOWER, TRIM, LENGTH (also LEN), SUBSTR, REPLACE, ||, ROUND, ABS and CAST all behave the same. Snowflake also offers x::DATE as a short CAST; DuckDB accepts it too.

Practice

Same bank tables. The report date for every date question is DATE '2026-09-30'. When a question says “as a date”, wrap the result in CAST(... AS DATE) so no time part sneaks in. Values are compared to two decimals, so round where the question says.

Key takeaway

Remember

A function changes one value on one row, in the result only. Nest from the inside out. Portable date maths is EXTRACT, + INTERVAL and DATEDIFF; Snowflake adds DATEADD, DATE_TRUNC and TO_DATE shorthands.

Glossary

Function
A named job on a value, written NAME(arguments).
Argument
A value passed into a function, inside the brackets.
Nesting
A function inside another function. The inner one runs first.
CAST
Convert a value to another type: text to date, number to text.
INTERVAL
A length of time, such as INTERVAL 30 DAY, that you add to a date.
Timestamp
A date plus a time of day. CAST(... AS DATE) drops the time.
Date part
One piece of a date: year, month, day. EXTRACT pulls one out.
