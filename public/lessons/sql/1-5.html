NULL and CASE

Real bank data has blanks: a missing age, a pending amount, a channel nobody recorded. NULL is how SQL stores a blank, and CASE is how you turn values into labels. The two meet constantly.

25 min Beginner Practice: 6 questions

By the end of this lesson you can

  • Find blanks with IS NULL and IS NOT NULL
  • Explain why = NULL never matches and why maths on a blank gives a blank
  • Fill a blank with COALESCE
  • Turn values into labels with CASE WHEN ... THEN ... ELSE ... END

Definition

Key definition

NULL means “no value here”. It is not zero, not an empty text, not false. It is a blank, and a blank is never equal to anything, not even another blank.

Because NULL is unknown, every comparison with it is unknown too. age = NULL, age <> NULL, even NULL = NULL: none of them is true, so WHERE drops the row. Maths and text work the same way: NULL + 10 is NULL and 'Ms ' || NULL is NULL.

CASE is a different idea: a list of tests, read top to bottom. The first test that passes decides the value. It is how you write “if the balance is above 5 lakh call it HIGH, otherwise LOW” inside a query.

Think of it like a blank field on the card

Some index cards have a field nobody filled in. The librarian cannot say whether that blank age is 34, so she will not put the card in the “age is 34” pile and she will not put it in the “age is not 34” pile either. She only sorts it when you ask “is the field blank?”. If you want her to treat a blank as something, you must tell her what: “if the segment is blank, write UNKNOWN”. That is COALESCE.

In the libraryA blank fieldIn SQL: NULL; test it with IS NULL
In the library“If blank, write UNKNOWN”In SQL: COALESCE(segment, 'UNKNOWN')
In the libraryA rulebook of labelsIn SQL: CASE WHEN ... THEN ... ELSE ... END

The rulebook is read top to bottom. The librarian stops at the first rule that fits, so the order of the rules matters.

How to write it, step by step

Step 1: test for blanks with IS NULL. Step 2: fill blanks with COALESCE. Step 3: write a CASE with one WHEN per rule, an ELSE for everything else, and END to close it.

SELECT acct_id, balance,
       CASE
         WHEN balance IS NULL  THEN 'UNKNOWN'
         WHEN balance >= 500000 THEN 'HIGH'
         WHEN balance >= 50000  THEN 'MEDIUM'
         ELSE 'LOW'
       END AS band
FROM accounts;

Two shapes of CASE exist. The searched form above takes any condition. The simple form compares one column to values: CASE txn_type WHEN 'DEPOSIT' THEN 'IN' ELSE 'OUT' END. Use the searched form when you need >, IS NULL or AND.

Worked examples

Example 1: find the blanks. One customer has no segment yet.

SELECT cust_id, cust_name, segment
FROM customers
WHERE segment IS NULL;

Example 3: the blank falls through. Account 119 has no balance. Neither >= 500000 nor >= 50000 is true for a blank, so it lands in ELSE and is called LOW. That is wrong for a report. The syntax block above fixes it by testing IS NULL first.

SELECT acct_id, balance,
       CASE WHEN balance >= 500000 THEN 'HIGH'
            WHEN balance >= 50000  THEN 'MEDIUM'
            ELSE 'LOW' END AS band
FROM accounts;

Example 4: a signed amount. Deposits count as plus, everything else as minus. The pending deposit (blank amount) stays blank, because minus a blank is still a blank.

SELECT txn_id, txn_type, amount,
       CASE WHEN txn_type = 'DEPOSIT' THEN amount ELSE -amount END AS signed_amount,
       COALESCE(channel, 'OTHER') AS channel_filled
FROM transactions;

Common mistakes

Watch out

1. WHERE age = NULL returns zero rows, always. Write age IS NULL.

2. WHERE segment <> 'RETAIL' silently drops the blank segment too. Eight customers are RETAIL, so you expect 8 others; you get 7. Add OR segment IS NULL if blanks should count.

3. Rules in the wrong order. WHEN balance >= 50000 THEN 'MEDIUM' WHEN balance >= 500000 THEN 'HIGH' never says HIGH, because the first rule already caught it. Put the strictest rule first.

4. Leaving out ELSE. A row that matches no rule gets NULL, not an error. Add an ELSE unless a blank is what you want.

5. Forgetting END. Every CASE needs END, and the alias goes after END.

On Snowflake

What is different on your project

More ways to fill a blank. Snowflake has NVL(a, b), IFNULL(a, b) and ZEROIFNULL(n). They do what COALESCE does with two values. COALESCE is the portable one and also takes a longer list.

IFF for a two-way choice. IFF(txn_type = 'DEPOSIT', amount, -amount) is Snowflake's one-line CASE. The worksheet engine spells it IF(...). CASE works the same on both, so prefer CASE in shared code.

NULLIF and EQUAL_NULL. NULLIF(a, b) gives NULL when a equals b (handy to avoid dividing by zero) and works on both engines. Snowflake's EQUAL_NULL(a, b) is true when both are blank; the portable form is a IS NOT DISTINCT FROM b.

Empty text is not NULL. On Snowflake and in the worksheet, '' is a real value with length 0. Some older databases treat it as NULL; Snowflake does not.

Practice

Same bank tables. Several rows hold blanks on purpose: one customer has no city, one has no segment, one has no age, one account has no balance, one transaction has no amount and one has no channel. Each question says how to treat them.

Key takeaway

Remember

NULL is a blank: test it with IS NULL, fill it with COALESCE, and remember that = and <> both drop it. CASE is a rulebook read top to bottom; put IS NULL and the strictest rule first, and always close with ELSE and END.

Glossary

NULL
A missing value. Not zero and not empty text.
IS NULL
The only test that is true for a blank.
Three-valued logic
A condition can be true, false or unknown. WHERE keeps only true.
COALESCE
Returns the first value in its list that is not blank.
CASE
An expression that picks a value by testing rules in order.
Searched CASE
CASE WHEN condition THEN ... with any condition.
Simple CASE
CASE column WHEN value THEN ... comparing one column to fixed values.
