Aggregates

So far every query gave back rows. Now you ask for one number about many rows: how many, how much in total, the average, the smallest, the biggest. These are aggregates, and every report is built on them.

25 min Beginner Practice: 6 questions

By the end of this lesson you can

  • Count rows with COUNT(*) and filled values with COUNT(col)
  • Add up and average with SUM and AVG
  • Find the smallest and biggest with MIN and MAX
  • Say exactly what every aggregate does with a blank

Definition

Key definition

An aggregate is a function that takes many rows and gives back one value. COUNT, SUM, AVG, MIN and MAX are the five you use every day.

The functions in lesson 1.4 worked on one row at a time: 16 rows in, 16 rows out. An aggregate squashes the rows: 16 rows in, one row out. If WHERE comes first, the aggregate only sees the rows that passed the filter.

One rule governs blanks: every aggregate skips NULL, except COUNT(*), which counts rows whether or not a field is filled. So AVG(balance) is the average of the 19 filled balances, not 20.

Think of it like asking for one number, not a list

Until now the librarian came back with a list of cards. Now you ask: “how many cards are on the accounts shelf?” or “add up every balance”. She still goes through every card, but she comes back with a single slip of paper holding one number. If a card has a blank balance, she skips it when adding, averaging or looking for the biggest. She only counts it when you ask “how many cards?” rather than “how many balances?”.

In the library“How many cards?”In SQL: COUNT(*), every row counts
In the library“How many cards have a balance?”In SQL: COUNT(balance), blanks skipped
In the library“Add them up” / “average them” / “biggest”In SQL: SUM, AVG, MAX (and MIN), blanks skipped

Ask for one number and you get one row back. Ask for three numbers in the same slip and you still get one row, with three columns.

How to write it, step by step

Step 1: decide the rows with FROM and WHERE. Step 2: put aggregates in the SELECT list. Step 3: give each a clear name with AS. The result is always exactly one row.

SELECT COUNT(*)            AS n_accounts,
       SUM(balance)        AS total_balance,
       ROUND(AVG(balance), 2) AS avg_balance,
       MIN(balance)        AS smallest,
       MAX(balance)        AS largest
FROM accounts
WHERE acct_status = 'ACTIVE';

Aggregates sit only in SELECT (and later in HAVING). They never go in WHERE, because WHERE runs row by row before any adding up has happened.

Worked examples

Example 1: how many accounts? One row, one number.

SELECT COUNT(*) AS n_accounts
FROM accounts;
n_accounts
20

Example 2: total deposits. WHERE first, then SUM over what is left. The pending deposit with a blank amount adds nothing.

SELECT SUM(amount) AS total_deposits
FROM transactions
WHERE txn_type = 'DEPOSIT';
total_deposits
793500

Example 3: three kinds of COUNT. 24 transactions; 23 have a channel; 4 different channels are used.

SELECT COUNT(*) AS all_rows,
       COUNT(channel) AS with_channel,
       COUNT(DISTINCT channel) AS different_channels
FROM transactions;
all_rowswith_channeldifferent_channels
24234

Example 4: average, smallest, biggest. For active savings accounts only. ROUND keeps the average tidy.

SELECT ROUND(AVG(balance), 2) AS avg_balance,
       MIN(balance) AS smallest,
       MAX(balance) AS largest
FROM accounts
WHERE acct_status = 'ACTIVE' AND acct_type = 'SAVINGS';

Common mistakes

Watch out

1. SELECT cust_name, COUNT(*) FROM customers is an error. You cannot mix a plain column with an aggregate unless you GROUP BY it (lesson 1.7).

2. WHERE SUM(amount) > 1000 is an error. WHERE runs before adding up. Filtering on a total is HAVING, also in lesson 1.7.

3. AVG(balance) is not SUM(balance) / COUNT(*) when blanks exist. AVG divides by the 19 filled balances; COUNT(*) is 20. Decide which you mean. SUM(COALESCE(balance, 0)) / COUNT(*) treats a blank as zero.

4. SUM(amount) over zero matching rows gives NULL, not 0. Wrap it: COALESCE(SUM(amount), 0).

5. COUNT(DISTINCT city) ignores the blank city. Seven cities appear, plus one customer with no city. If you need to count the blank as a group, that is GROUP BY territory.

On Snowflake

What is different on your project

Same five, same rules. COUNT, SUM, AVG, MIN and MAX behave exactly the same, including the skip-blanks rule and the one-row result.

Extra statistics. Snowflake adds MEDIAN(col), STDDEV(col), VARIANCE(col) and APPROX_COUNT_DISTINCT(col), which estimates a distinct count very fast on billions of rows. The worksheet engine has MEDIAN and STDDEV too. COUNT_IF(condition) counts rows that pass a test on both engines; the portable form is SUM(CASE WHEN condition THEN 1 ELSE 0 END).

Instant counts. SELECT COUNT(*) FROM big_table with no WHERE comes back instantly on Snowflake, because it keeps the row count in metadata. Add a WHERE and it has to read the data.

Practice

Key takeaway

Remember

Aggregates turn many rows into one value. WHERE picks the rows first. Every aggregate skips blanks except COUNT(*), so COUNT(col) and AVG(col) describe filled values only.

Glossary

Aggregate
A function that takes many rows and returns one value.
COUNT(*)
The number of rows, blanks included.
COUNT(col)
The number of rows where col is not blank.
DISTINCT inside COUNT
Count each different value once.
SUM
The total of the filled values.
AVG
The total divided by the number of filled values.
MIN / MAX
The smallest and biggest filled value; works for dates and text too.
