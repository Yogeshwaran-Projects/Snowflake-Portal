Inner joins

Real questions need two tables at once: the customer and her accounts, the account and its transactions. A join puts matching rows side by side.

30 min Intermediate Practice: 6 questions

By the end of this lesson you can

  • Explain what a join does, using index cards
  • Write an INNER JOIN with ON and table aliases
  • Chain three tables in one query and add WHERE and GROUP BY
  • Spot a join that multiplies rows before it ruins a total

Definition

Key definition

An inner join pairs each row of one table with the rows of another table that share the same value, and keeps only the pairs that match.

Banks never keep everything in one table. Customers live in one table, accounts in another, transactions in a third. Each table carries an id column that points to the other. A join follows that pointer.

  • Join key: the column both tables share, such as cust_id.
  • ON: where you tell SQL which columns must be equal.
  • Inner: rows with no partner on the other side are dropped. Lesson 2.2 shows how to keep them.

Think of it like two shelves of index cards

Picture two shelves. The left shelf holds one card per customer. The right shelf holds one card per account. Every account card has a small sticker with the customer number. To answer “which accounts does Bhavna hold?”, you pick up her customer card, read her number, and pull every account card with that same number. Then you lay the cards side by side. That is a join.

On the shelvesTwo shelves of cardsIn SQL: two tables, such as customers and accounts
On the shelvesThe number stickerIn SQL: the join key, cust_id, written in the ON clause
On the shelvesCards laid side by sideIn SQL: one wide result row with columns from both tables

An inner join is strict. A customer card with no account card is put back on the shelf and does not appear. An account card with a sticker that matches no customer is also dropped.

Syntax step by step

Step 1: name both tables and give each a short alias. Step 2: say how they connect in ON. Step 3: pick columns with the alias in front, so SQL knows which table each one comes from.

SELECT c.cust_name, a.acct_type, a.balance
FROM customers c
INNER JOIN accounts a
  ON a.cust_id = c.cust_id;

INNER JOIN and plain JOIN mean the same thing. Most people write JOIN. Here is which rows survive, using three customers and three accounts:

customers (left)accounts (right)In the result?
1 Anil Kapoor1001 SAVINGS, cust_id 1Yes, keys match

Notice the row count. Ten customers hold fourteen accounts, so the join returns fourteen rows, not ten. A join returns one row per matching pair.

Chaining three tables

Transactions point to accounts, and accounts point to customers. Join them in a chain, one JOIN … ON after another.

SELECT t.txn_id, c.cust_name, t.amount
FROM transactions t
JOIN accounts a  ON a.acct_id = t.acct_id
JOIN customers c ON c.cust_id = a.cust_id
WHERE t.amount > 100000;

The order of clauses stays the same as before: FROM and the joins first, then WHERE, GROUP BY, ORDER BY.

Worked examples

Example 1: a customer and her branch. Customers carry branch_id. Branches carry the name.

SELECT c.cust_name, b.branch_name, b.city
FROM customers c
JOIN branches b ON b.branch_id = c.branch_id
WHERE c.segment = 'PREMIUM';

Result: 3 rows. Bhavna Desai at Fort, Deepa Nair at Connaught Place, Gita Rao at Koramangala.

Example 2: total balance per customer. Join, then group. Group by the id as well as the name, because two different customers are both called Anil Kapoor.

SELECT c.cust_id, c.cust_name, SUM(a.balance) AS total_balance
FROM customers c
JOIN accounts a ON a.cust_id = c.cust_id
GROUP BY c.cust_id, c.cust_name
ORDER BY total_balance DESC;

Result: 10 rows. Deepa Nair leads with 13,10,000. Anil Kapoor (id 1) shows 3,25,000 and Anil Kapoor (id 11) shows 7,800, on separate rows.

Example 3: ATM withdrawals per branch. Four tables in a chain, then a count.

SELECT b.branch_name, COUNT(*) AS atm_txns
FROM transactions t
JOIN accounts a  ON a.acct_id = t.acct_id
JOIN customers c ON c.cust_id = a.cust_id
JOIN branches b  ON b.branch_id = c.branch_id
WHERE t.channel = 'ATM'
GROUP BY b.branch_name;

Result: Fort 2, Connaught Place 2, Koramangala 1. Branches with no ATM withdrawals do not appear, because the join is inner.

Example 4: the USING shortcut. When the key has the same name in both tables, USING (cust_id) replaces the ON clause. It works in DuckDB and Snowflake. ON is clearer when you are learning, so this course keeps ON.

Common mistakes

Row explosion

If a customer has 2 accounts and 3 loans, joining customers to accounts and to loans gives 2 × 3 = 6 rows for that one customer. A SUM(balance) on that result counts each balance three times. Rule: before you join two “many” tables to the same parent, total each one separately first (Lesson 2.5 shows how with CTEs). Always compare COUNT(*) before and after a join.

Ambiguous column

Both tables have cust_id. Writing SELECT cust_id without an alias gives the error “ambiguous column”. Always prefix: c.cust_id.

Silent drops

An inner join hides rows with no match. Kavya Iyer has no account, so a report of “all customers and their balances” built with an inner join forgets her. If the question says “all”, you need a LEFT JOIN (next lesson).

On Snowflake

Same syntax, two cautions

Everything above runs unchanged on Snowflake. Two things to know. First, NATURAL JOIN joins on every column with the same name, so a shared column like city silently becomes part of the key. Avoid it and write ON. Second, on huge bank tables Snowflake picks the join order for you, so write joins for clarity, not for speed. Keys of the same type join fastest; joining a NUMBER to a VARCHAR forces a cast on every row.

Key takeaway

Remember

JOIN … ON pairs rows that share a key and returns one row per matching pair. No match, no row. Alias every table and check the row count after every join.

Glossary

Join
Combining rows from two tables that share a value.
Inner join
A join that keeps only rows with a match on both sides.
Join key
The column (or columns) the two tables share, such as cust_id.
ON clause
The condition that says which rows pair up.
Alias
A short nickname for a table, such as customers c.
Primary key
The column that identifies one row, such as acct_id in accounts.
Foreign key
A column that points to another table’s primary key, such as cust_id in accounts.
Row explosion
A join that returns more rows than expected because one key matches many rows on both sides.
