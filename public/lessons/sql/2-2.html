Outer joins and anti-joins

“All customers, even the ones with no account.” “Which branches have no customers?” Outer joins keep the rows an inner join throws away, and anti-joins find the rows with no partner.

30 min Intermediate Practice: 6 questions

By the end of this lesson you can

  • Choose between INNER, LEFT, RIGHT and FULL joins
  • Find rows with no match (an anti-join) using LEFT JOIN … IS NULL
  • Count children per parent and show 0, not a missing row
  • Put a filter in ON or in WHERE on purpose, not by accident

Definition

Key definition

An outer join keeps every row from one side (or both sides) even when there is no match, and fills the missing side with NULL.

  • LEFT JOIN: keep every row from the left table. Right-side columns are NULL where nothing matched.
  • RIGHT JOIN: the mirror image. Keep every row from the right table.
  • FULL JOIN: keep every row from both sides.
  • Anti-join: a LEFT JOIN followed by WHERE right.key IS NULL. It returns the left rows that have no partner.

Almost everyone writes LEFT JOIN and never RIGHT JOIN. You can always swap the table order to turn a RIGHT into a LEFT.

Think of it like keeping every card from the left shelf

Back to the two shelves of index cards. With an inner join, a customer card with no account card goes back on the shelf. With a LEFT JOIN you keep that customer card anyway and lay a blank card next to it. The blank card is NULL. Now you can also ask the opposite question: “show me only the customers who got a blank card”. That is the anti-join.

The anti-join

Add a WHERE that keeps only the blank cards. Test a column that can never be NULL in a real match, such as the right table’s primary key.

SELECT c.cust_name
FROM customers c
LEFT JOIN accounts a ON a.cust_id = c.cust_id
WHERE a.acct_id IS NULL;

Result: Jay Mehta and Kavya Iyer. The same question can be written with NOT EXISTS (Lesson 2.4). Both are correct. Pick the one your team reads most easily.

FULL JOIN

Use FULL JOIN to reconcile two lists: rows in A only, rows in B only, and rows in both. Banks use it to compare yesterday’s file with today’s.

SELECT b.branch_name, c.cust_name
FROM branches b
FULL JOIN customers c ON c.branch_id = b.branch_id;

Salt Lake appears with a NULL customer. Jay Mehta appears with a NULL branch. Everyone else pairs up.

Worked examples

Example 1: accounts per customer, with zeros. Count the right table’s key, not *. COUNT(a.acct_id) ignores the NULL blank card, so Jay and Kavya show 0. COUNT(*) would wrongly give them 1.

SELECT c.cust_name, COUNT(a.acct_id) AS accounts_held
FROM customers c
LEFT JOIN accounts a ON a.cust_id = c.cust_id
GROUP BY c.cust_id, c.cust_name;

Example 2: filter in ON, not WHERE. “Every branch and its ACTIVE balance, 0 when none.” If you put acct_status = 'ACTIVE' in WHERE, the NULL blank cards fail the test and Salt Lake vanishes. Put the filter in ON so it only decides which cards match.

SELECT b.branch_name, COALESCE(SUM(a.balance), 0) AS active_balance
FROM branches b
LEFT JOIN customers c ON c.branch_id = b.branch_id
LEFT JOIN accounts a  ON a.cust_id = c.cust_id
                     AND a.acct_status = 'ACTIVE'
GROUP BY b.branch_id, b.branch_name;

Result: 6 rows. Salt Lake shows 0. COALESCE turns the NULL sum into 0.

Example 3: loan customers with no account. Start from loans, join to customers, LEFT JOIN accounts, keep the blanks.

SELECT c.cust_name, l.loan_type
FROM loans l
JOIN customers c ON c.cust_id = l.cust_id
LEFT JOIN accounts a ON a.cust_id = c.cust_id
WHERE a.acct_id IS NULL;

Result: Jay Mehta, PERSONAL. A bank calls this “a lending-only relationship”, and it is a classic cross-sell list.

Common mistakes

A WHERE on the right table turns LEFT into INNER

LEFT JOIN accounts a … WHERE a.balance > 0 drops every blank card, because NULL > 0 is not true. You asked for all customers and silently got only those with accounts. If the filter belongs to the right table, write it in ON. If you really want to filter the result, add OR a.acct_id IS NULL on purpose.

COUNT(*) on a LEFT JOIN never returns 0

The blank card is still a row. Count a right-side column, COUNT(a.acct_id), so blanks count as 0.

Anti-join on the wrong column

Test a column that cannot be NULL in a real match. WHERE a.balance IS NULL would also catch a real account whose balance happens to be NULL. Use the key: a.acct_id IS NULL.

On Snowflake

Portable, with one legacy trap

LEFT, RIGHT and FULL OUTER JOIN work the same on Snowflake. You will meet old code with (+) in the WHERE clause, such as WHERE a.cust_id(+) = c.cust_id. That is Oracle-style outer join syntax, and Snowflake still accepts it. Read it as a LEFT JOIN and rewrite it with ON when you touch the query. Snowflake also lets you write LEFT OUTER JOIN; the word OUTER is optional.

Practice

Tables: customers, accounts, loans and branches. Two customers have no account, one branch has no customers, and one loan customer has no account. Those gaps are the point of this lesson.

Key takeaway

Remember

LEFT JOIN keeps every left row and fills gaps with NULL. Filters on the right table go in ON. “Who has none?” is LEFT JOIN plus WHERE right.key IS NULL.

Glossary

Outer join
A join that keeps unmatched rows from one or both sides.
LEFT JOIN
Keep every row of the first (left) table.
RIGHT JOIN
Keep every row of the second (right) table. Rarely used; swap the tables and use LEFT instead.
FULL JOIN
Keep every row of both tables.
Anti-join
Rows from one table that have no match in the other.
COALESCE
Returns the first non-NULL value in its list, such as COALESCE(SUM(x), 0).
Blank card
This course’s nickname for the NULL-filled right side of an unmatched row.
