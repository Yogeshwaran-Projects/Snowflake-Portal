Self and cross joins

Who is each employee’s manager? Which two customers share a name? Which branch must sell which product? These questions join a table to itself, or pair every row with every row.

25 min Intermediate Practice: 6 questions

By the end of this lesson you can

  • Join a table to itself with two aliases
  • Walk an employee-to-manager hierarchy one level up
  • Find pairs of rows without listing each pair twice
  • Use CROSS JOIN to build every combination on purpose

Definition

Key definition

A self join joins a table to a second copy of itself. A cross join pairs every row of one table with every row of another, with no key at all.

  • Self join: same table, two aliases, usually because a row points to another row in the same table (employee to manager).
  • Cross join: no ON. Rows × rows. 6 branches × 3 products = 18 rows. Useful for checklists and calendars, dangerous by accident.

Think of it like comparing cards on the same shelf

So far you matched cards from two shelves. Now take two photocopies of the same shelf. On copy A you read an employee’s card. Her card has a sticker: “my manager is 101”. On copy B you find card 101. Same shelf, two copies, one join. For a cross join, forget stickers. Lay every card from shelf A next to every card from shelf B, all combinations. That is how a bank builds “every branch must report on every product” before any numbers exist.

On the shelves“My manager is 101” stickerIn SQL: ON m.emp_id = e.manager_id
On the shelvesEvery card next to every cardIn SQL: CROSS JOIN, rows multiplied

Syntax step by step

Step 1: write the table twice with different aliases. Name them by role: e for employee, m for manager. Step 2: in ON, connect the pointer column of one copy to the id column of the other.

SELECT e.emp_name, m.emp_name AS manager_name
FROM employees e
JOIN employees m ON m.emp_id = e.manager_id;

Pairs without duplicates

To find two customers with the same name, join customers to customers on the name. Without care you get each pair twice (1 with 11, and 11 with 1) and each row paired with itself. The fix is one extra condition: a.cust_id < b.cust_id.

SELECT a.cust_id AS first_id, b.cust_id AS second_id, a.cust_name
FROM customers a
JOIN customers b
  ON b.cust_name = a.cust_name
 AND a.cust_id < b.cust_id;

Cross join

SELECT b.branch_name, p.product_name
FROM branches b
CROSS JOIN products p;

18 rows, every branch with every product. LEFT JOIN this skeleton to real sales later and the zero-sales cells are no longer missing, they are NULL rows you can see.

Worked examples

Example 1: everyone and their manager, bosses included.

SELECT e.emp_name, e.job_title, m.emp_name AS manager_name
FROM employees e
LEFT JOIN employees m ON m.emp_id = e.manager_id
ORDER BY e.emp_id;

Result: 12 rows. Suresh Menon and Farah Khan have manager_name NULL. Note that Farah is not a boss; her branch simply has no manager yet. NULL means “none recorded”, not “top of the tree”.

Example 2: employees who sit in a different branch from their manager. Compare two columns of the two copies.

SELECT e.emp_name, e.branch_id AS emp_branch, m.branch_id AS mgr_branch
FROM employees e
JOIN employees m ON m.emp_id = e.manager_id
WHERE e.branch_id <> m.branch_id;

Result: Vikram Shah, Meera Iyer, Priya Menon. All three report to Suresh Menon in Mumbai from other cities.

Example 3: direct reports per manager. Group the manager copy.

SELECT m.emp_name AS manager_name, COUNT(*) AS reports
FROM employees e
JOIN employees m ON m.emp_id = e.manager_id
GROUP BY m.emp_id, m.emp_name;

Result: Suresh Menon 4, Asha Rao 2, Vikram Shah 2, Meera Iyer 1, Priya Menon 1.

Example 4: branch manager by name. Branches point to employees through manager_id. That is a normal join, not a self join, but it looks similar: the pointer lives in one table and the id in another.

Common mistakes

Accidental cross join

Forget the ON clause in old comma-style syntax, FROM accounts a, transactions t, and you get 14 × 24 = 336 rows. On a real bank table that is billions. If a query returns far more rows than the biggest table, look for a missing join condition first.

Which copy is which

In m.emp_id = e.manager_id, the pointer (manager_id) belongs to the employee copy and the id belongs to the manager copy. Swap them and every manager is shown as the report of their own team members. Name aliases by role, never a and b, when the table points to itself.

Pairs counted twice

Pair-finding self joins need a.id < b.id. With <> you get each pair twice; with nothing you also pair each row with itself.

On Snowflake

Same syntax, plus two helpers

Self joins and CROSS JOIN are identical on Snowflake. A self join walks only one level of a hierarchy; for the whole tree (manager of the manager of …) Snowflake has CONNECT BY and recursive CTEs, which Lesson 3.4 covers. For generating rows without a table, Snowflake has TABLE(GENERATOR(ROWCOUNT => 30)), often cross-joined to build a calendar. DuckDB uses range(30) for the same job. Both are engine-specific, so the portable way is a small dates table.

Practice

Tables: employees (with manager_id pointing back into the same table), branches, customers and a small products list. Two employees share the name Rahul Nair and two customers share the name Anil Kapoor. The top boss and one new joiner have no manager.

Key takeaway

Remember

A self join is two aliases of one table joined on a pointer column. Name the aliases by role. A cross join has no ON and multiplies rows; use it on purpose for checklists, and suspect it whenever a result is far too big.

Glossary

Self join
A join between two aliases of the same table.
Cross join
Every row of one table paired with every row of another; also called a Cartesian product.
Hierarchy
Rows that point to other rows in the same table, such as employee to manager.
Pointer column
A column holding another row’s id, such as manager_id.
Pair
Two different rows that satisfy a condition; use a.id < b.id to list each pair once.
Skeleton
A cross join of dimensions (branch × product, branch × month) used to show every cell, even empty ones.
