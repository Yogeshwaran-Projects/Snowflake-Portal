UNION, INTERSECT, EXCEPT

Joins put tables side by side. Set operators stack them top to bottom: combine two lists, keep what is in both, or keep what is in one but not the other.

25 min Intermediate Practice: 6 questions

By the end of this lesson you can

  • Stack two queries with UNION ALL and know when UNION is needed
  • Find what two lists share with INTERSECT
  • Find what one list has and the other lacks with EXCEPT
  • Add a label column so you can tell which pile a row came from

Definition

Key definition

Set operators combine the rows of two SELECTs that have the same number of columns in the same order. UNION adds the piles, INTERSECT keeps the shared rows, EXCEPT subtracts one pile from the other.

OperatorKeepsDuplicatesBanking example
UNION ALLEvery row from bothKeptStack this month’s and last month’s transaction files
UNIONEvery row from bothRemovedOne list of cities that have a branch or a customer
INTERSECTRows in bothRemovedCustomers who have an account AND a loan
EXCEPTRows in the first but not the secondRemovedCustomers with an account but no loan

Think of it like stacking two piles of cards

Two teachers each hand you a pile of name cards. UNION ALL: put one pile on top of the other and hand back the stack, duplicates and all. UNION: same stack, but first pull out any name that appears twice. INTERSECT: keep only the names that are in both piles. EXCEPT: start with pile one and throw away every card whose name is also in pile two.

With the card pilesStack themIn SQL: UNION ALL (fast, keeps everything)
With the card pilesNames in both pilesIn SQL: INTERSECT
With the card pilesPile one minus pile twoIn SQL: EXCEPT (Snowflake also says MINUS)

The rule for every operator: both piles must have the same number of columns, and matching columns must hold the same kind of value. The column names come from the first SELECT.

Syntax step by step

Write a full SELECT, the operator, and a second full SELECT. ORDER BY goes once, at the very end, and applies to the combined result.

SELECT city FROM customers
UNION
SELECT city FROM branches
ORDER BY city;
Customer citiesBranch citiesUNIONINTERSECTEXCEPT (customers minus branches)
Mumbai, Delhi, Chennai, Bengaluru, Hyderabad, PuneMumbai, Delhi, Chennai, Bengaluru, Hyderabad, Kolkata7 cities5 citiesPune

Label the piles. Add a literal column so each row says where it came from. Types must line up: VARCHAR with VARCHAR, NUMBER with NUMBER.

SELECT 'CUSTOMER' AS person_kind, cust_name AS person_name, city FROM customers
UNION ALL
SELECT 'EMPLOYEE', emp_name, NULL FROM employees;

Employees have no city column, so the third slot is filled with NULL to keep the counts equal.

Worked examples

Example 1: customers with both an account and a loan.

SELECT cust_id FROM accounts
INTERSECT
SELECT cust_id FROM loans;

Result: 1, 2, 3, 4, 6, 8, 9. Seven customers. Anil Kapoor (id 1) has two accounts and two loans, but INTERSECT returns him once.

Example 2: account holders with no loan.

SELECT cust_id FROM accounts
EXCEPT
SELECT cust_id FROM loans;

Result: 5, 7, 11. Order matters: swap the two SELECTs and you get loan holders with no account, which is only 10 (Jay Mehta).

Example 3: one timeline of money in. Deposits and loan disbursements are different tables with different column names. UNION ALL lines them up as long as the slots match.

SELECT 'TXN' AS source_kind, txn_id AS ref_id, amount
FROM transactions
WHERE txn_type = 'DEPOSIT'
UNION ALL
SELECT 'LOAN', loan_id, principal
FROM loans;

Result: 14 deposit rows plus 9 loan rows = 23 rows.

Example 4: three-way classification. Combine all three operators to label every customer who has either product.

SELECT cust_id, 'BOTH' AS relation
FROM (SELECT cust_id FROM accounts INTERSECT SELECT cust_id FROM loans)
UNION ALL
SELECT cust_id, 'ACCOUNT_ONLY'
FROM (SELECT cust_id FROM accounts EXCEPT SELECT cust_id FROM loans)
UNION ALL
SELECT cust_id, 'LOAN_ONLY'
FROM (SELECT cust_id FROM loans EXCEPT SELECT cust_id FROM accounts);

Result: 7 BOTH, 3 ACCOUNT_ONLY, 1 LOAN_ONLY. The three groups never overlap, so UNION ALL is correct and cheaper than UNION.

Common mistakes

UNION when you meant UNION ALL

UNION removes duplicate rows. Stack two months of transactions with UNION and two identical deposits of 25,000 on the same account and date collapse into one. Money disappears from the report. Default to UNION ALL. Use UNION only when you want a distinct list and you have thought about it.

Columns matched by position, not name

SELECT cust_name, city UNION SELECT city, cust_name runs without error and puts cities under the name column. Line the slots up by hand and check the first few rows.

ORDER BY inside a branch

Only the final ORDER BY applies. An ORDER BY inside one of the SELECTs is an error on most engines, or ignored. Sort once, at the end.

On Snowflake

MINUS = EXCEPT

Snowflake accepts both EXCEPT and MINUS; they are the same operator. Code migrated from Oracle will say MINUS. Write EXCEPT in new code because it is the standard and DuckDB understands it. Snowflake supports INTERSECT and UNION [ALL] as shown. One more: when operators are mixed without brackets, Snowflake evaluates INTERSECT first, then UNION and EXCEPT left to right. Always use brackets when you combine operators, as in Example 4, so the order is obvious to every reader.

Practice

Tables: customers, employees, branches, accounts, loans and transactions. Some names appear in more than one pile on purpose.

Key takeaway

Remember

Set operators stack piles with the same columns in the same order. UNION ALL keeps everything, UNION de-duplicates, INTERSECT keeps the shared rows, EXCEPT subtracts. Default to UNION ALL and sort once at the end.

Glossary

Set operator
UNION, INTERSECT or EXCEPT: combines two result sets row-wise.
UNION ALL
All rows from both queries, duplicates kept.
UNION
All rows from both queries, duplicate rows removed.
INTERSECT
Only rows that appear in both queries.
EXCEPT
Rows in the first query that are not in the second. Snowflake also calls it MINUS.
Union-compatible
Two queries with the same number of columns and matching types, position by position.
Label column
A literal such as 'LOAN' added to each pile so rows can be told apart.
