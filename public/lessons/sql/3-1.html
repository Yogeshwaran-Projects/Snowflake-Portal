Ranking windows

Give every row a position (1st, 2nd, 3rd) without squashing the rows together. ROW_NUMBER, RANK, DENSE_RANK and NTILE, with PARTITION BY to restart the race for each group.

30 min Advanced Practice: 6 questions

By the end of this lesson you can

  • Explain what a window function is and how it differs from GROUP BY
  • Choose between ROW_NUMBER, RANK and DENSE_RANK when there are ties
  • Restart the ranking for each group with PARTITION BY
  • Answer "top N per group" questions, the most common interview task

Definition

Key definition

A window function looks at a group of related rows (the "window") to compute a value for each row, but it keeps every row. A ranking window gives each row its position inside that window.

Compare this with GROUP BY. GROUP BY squashes many rows into one summary row. A window function keeps all rows and adds a new column next to each one. That is the whole trick.

  • GROUP BY: "How many accounts per type?" gives 2 rows.
  • Window: "What is the rank of each account inside its type?" gives all 14 rows, each with a rank.

Think of it like a queue where everyone keeps their own card

Picture customers waiting in a bank queue. Each person holds a card with their own details. A window function lets every person peek at the cards of the people around them in the queue, and then write one extra note on their own card: "I am 3rd" or "the person before me has 5,000". Nobody leaves the queue and no cards are merged. Ranking is the race-position version: the queue is sorted by some value, and each person writes down their place.

In the queueThe people in lineIn SQL: the rows. All of them stay; none are squashed together.
In the queueSeparate lines per counterIn SQL: PARTITION BY. Each group gets its own race and its own 1st place.
In the queueThe order people stand inIn SQL: ORDER BY inside OVER(). It decides who is 1st, 2nd, 3rd.

Ties are like two runners crossing the line at the same moment. The three ranking functions handle that moment differently, and that is the only real difference between them.

Syntax, step by step

Every window function has the same shape: a function, then OVER (...), and inside the brackets an optional PARTITION BY and an ORDER BY.

SELECT acct_id, balance,
       ROW_NUMBER() OVER (ORDER BY balance DESC, acct_id) AS rn
FROM accounts;

Read it as: "for each account, look at all accounts sorted by balance from high to low, and write down my position". The acct_id after the comma is the tie-breaker: if two balances are equal, the lower id goes first. Always add one, so the answer is the same every time you run it.

FunctionWith a tie at 2nd placeUse it when
ROW_NUMBER()1, 2, 3, 4 (never repeats)You need exactly one row per group, such as "the latest transaction"
RANK()1, 2, 2, 4 (skips 3)You want sports-style places: two silver medals, no bronze
DENSE_RANK()1, 2, 2, 3 (no gap)You want "the 3rd highest balance" even when there are ties
NTILE(4)Splits rows into 4 equal buckets: 1, 1, 2, 2, 3, 3, 4, 4Quartiles and deciles for segmentation

Add PARTITION BY to restart the count for each group:

SELECT acct_type, acct_id, balance,
       RANK() OVER (PARTITION BY acct_type ORDER BY balance DESC) AS rank_in_type
FROM accounts;

Worked examples

Example 1: the three functions side by side. Accounts 101 and 114 both hold 125,000, so they tie.

SELECT acct_id, balance,
       ROW_NUMBER() OVER (ORDER BY balance DESC, acct_id) AS rn,
       RANK()       OVER (ORDER BY balance DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY balance DESC) AS drnk
FROM accounts
ORDER BY balance DESC, acct_id;

Example 2: top 2 accounts per account type. The window column cannot go straight into WHERE, so wrap it in a subquery and filter outside.

SELECT acct_type, acct_id, balance
FROM (
  SELECT acct_type, acct_id, balance,
         ROW_NUMBER() OVER (PARTITION BY acct_type ORDER BY balance DESC, acct_id) AS rn
  FROM accounts
) ranked
WHERE rn <= 2;

Common mistakes

Watch out

Using a window column in WHERE. WHERE rn = 1 fails because WHERE runs before the window is computed. Use a subquery or CTE, or QUALIFY (next lesson).

Forgetting the tie-breaker. ROW_NUMBER() OVER (ORDER BY amount DESC) can give a different "winner" on each run when two amounts are equal. Add a unique column such as txn_id.

Mixing up RANK and DENSE_RANK. If a question says "the 3rd highest", DENSE_RANK is usually what is meant. If it says "3rd place", RANK fits.

Expecting fewer rows. A window function never reduces the row count. If you want one row per group, you must filter on the rank afterwards.

Key takeaway

Remember

A window function adds a column, never removes rows. ROW_NUMBER never ties, RANK ties and skips, DENSE_RANK ties and does not skip. PARTITION BY restarts the race per group. Filter on the rank in an outer query.

Glossary

Window function
A function that computes a value for each row using other rows around it, without merging rows.
OVER()
The clause that turns a function into a window function and defines the window.
PARTITION BY
Splits rows into groups; the window restarts in each group.
ROW_NUMBER
1, 2, 3 with no repeats, even for ties.
RANK
Ties share a number and the next number is skipped.
DENSE_RANK
Ties share a number and nothing is skipped.
NTILE(n)
Splits the ordered rows into n buckets of almost equal size.
Tie-breaker
An extra ORDER BY column (usually an id) that makes the order unique.
