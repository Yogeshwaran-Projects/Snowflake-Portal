LAG, LEAD, running totals and frames

Look at the row before you, the row after you, and add up everything so far. These windows power balance histories, month-over-month changes and moving averages.

35 min Advanced Practice: 6 questions

By the end of this lesson you can

  • Fetch the previous or next row's value with LAG and LEAD
  • Build a running total and a running balance per account
  • Write a window frame (ROWS BETWEEN) for moving averages
  • Avoid the LAST_VALUE trap that catches almost everyone once

Definition

Key definition

LAG and LEAD read a value from a neighbouring row. A running total is SUM over a window that grows one row at a time. A frame tells the window how many rows to look back or forward.

Last lesson every row wrote down its position. Now every row can also copy a value from its neighbours, or add up the values of everyone in front of it. The shape is the same: a function, OVER (...), and an ORDER BY that says what "before" and "after" mean.

Think of it like a queue, a piggy bank and a look-back rule

Back in the bank queue. LAG is turning around to read the card of the person right behind you. LEAD is reading the card of the person in front. A running total is a piggy bank: each person drops their coins in and writes the new total on their own card, so the number grows as the line moves. A frame is a rule about how far you may look: "only the last three people" or "everyone from the start of the line to me".

In the queuePeek behind or aheadIn SQL: LAG(col) and LEAD(col). You get NULL if nobody is there.
In the queueThe piggy bank totalIn SQL: SUM(col) OVER (ORDER BY ...). Each row sees the total so far.
In the queueThe look-back ruleIn SQL: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW. How far the window reaches.

Syntax, step by step

Step 1: LAG and LEAD. The first argument is the column, the second is how many rows away (default 1), the third is the value to use when there is no neighbour (default NULL).

SELECT txn_id, txn_date, amount,
       LAG(amount)        OVER (ORDER BY txn_date, txn_id) AS prev_amount,
       LEAD(amount, 1, 0) OVER (ORDER BY txn_date, txn_id) AS next_amount
FROM transactions
WHERE acct_id = 101;

Step 2: running total. Add an ORDER BY to SUM and it stops being a grand total. It becomes "the total up to and including this row".

SELECT txn_id, txn_date, amount,
       SUM(amount) OVER (PARTITION BY acct_id ORDER BY txn_date, txn_id
                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM transactions;

Step 3: the frame. The part starting with ROWS BETWEEN is the frame. Three frames cover almost every need:

FrameMeaningTypical use
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROWFrom the first row to meRunning total, running balance
ROWS BETWEEN 2 PRECEDING AND CURRENT ROWMe and the two before me3-period moving average
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWINGThe whole partitionFIRST_VALUE and LAST_VALUE

If you write ORDER BY but no frame, the engine uses a default frame: RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. RANGE treats rows with the same ORDER BY value as one block, which is why you should write ROWS and a tie-breaker yourself.

FROM transactions

Example 3: 3-transaction moving average. The frame "2 PRECEDING AND CURRENT ROW" holds at most 3 rows. The first row averages only itself, the second averages two rows.

SELECT txn_id, amount,
       ROUND(AVG(amount) OVER (ORDER BY txn_date, txn_id
                              ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS moving_avg
FROM transactions
WHERE acct_id = 101;

Example 4: the LAST_VALUE trap. With the default frame, LAST_VALUE only sees rows up to the current one, so it just returns the current row. Give it the full frame and it returns the real last row.

SELECT DISTINCT acct_id,
       FIRST_VALUE(amount) OVER (PARTITION BY acct_id ORDER BY txn_date, txn_id
                                ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS first_amount,
       LAST_VALUE(amount)  OVER (PARTITION BY acct_id ORDER BY txn_date, txn_id
                                ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) AS last_amount
FROM transactions;

Common mistakes

Watch out

No ORDER BY in the running total. SUM(amount) OVER (PARTITION BY acct_id) gives the grand total of the account on every row, not a running total.

Forgetting PARTITION BY. Without it, the running total of account 103 includes account 101's money.

LAG with ties. If two transactions share a date, LAG can pick either one. Always add txn_id to the ORDER BY.

Doing maths on NULL. amount - LAG(amount) is NULL on the first row. Use LAG(amount, 1, 0) or COALESCE if you need a number.

On Snowflake

Same syntax, two small notes

LAG, LEAD, FIRST_VALUE, LAST_VALUE and ROWS BETWEEN frames are identical in Snowflake and in the practice editor (DuckDB). date1 - date2 returns whole days on both.

Snowflake also accepts the shorter ROWS UNBOUNDED PRECEDING, and if you omit the frame after ORDER BY it uses the same RANGE default. On a real project, write the full ROWS frame every time; reviewers will thank you.

Snowflake has CONDITIONAL_CHANGE_EVENT and RATIO_TO_REPORT as extras. The editor does not have those, so they are not used in practice.

Practice

Same bank: accounts and transactions. Order every window by txn_date, txn_id so ties never change the answer. Grading compares values only.

Key takeaway

Remember

LAG looks back, LEAD looks forward. SUM with ORDER BY is a piggy bank that grows row by row. The frame says how far to look; write ROWS BETWEEN yourself, and give LAST_VALUE the whole partition.

Glossary

LAG(col, n, default)
Value of col from n rows before this one; default when none exists.
LEAD(col, n, default)
Value of col from n rows after this one.
Running total
SUM over all rows from the start of the partition to the current row.
Frame
The ROWS BETWEEN part of a window; which rows the function may see.
UNBOUNDED PRECEDING
The first row of the partition.
CURRENT ROW
The row the function is computing a value for.
Moving average
AVG over a frame of fixed size, such as the last 3 rows.
FIRST_VALUE / LAST_VALUE
The first or last value inside the frame, not the partition, unless the frame covers everything.
