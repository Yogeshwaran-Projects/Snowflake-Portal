QUALIFY and de-duplication

Filter on a window result in one clean step, and use it to remove duplicate rows the way real data pipelines do every day.

25 min Advanced Practice: 6 questions

By the end of this lesson you can

  • Say where QUALIFY sits in the order of SQL clauses
  • Replace a ranking subquery with one QUALIFY line
  • Keep the latest version of each record and drop the rest
  • Find duplicates before they break a report

Definition

Key definition

QUALIFY is a filter that runs after window functions are computed. It does for windows what HAVING does for GROUP BY.

The clauses of a query run in a fixed order: FROM, WHERE, GROUP BY, HAVING, window functions, QUALIFY, SELECT list, ORDER BY, LIMIT. WHERE runs too early to see a window result. QUALIFY runs right after the windows, so it can.

  • WHERE filters raw rows.
  • HAVING filters groups.
  • QUALIFY filters on window results.

Think of it like a filter after the race results are in

In a race, you cannot pick "the top three" before anyone has run. First everyone runs (the window computes). Then the judge looks at the finishing board and says "only the first three go on the podium". QUALIFY is that judge. WHERE would be a judge who tries to pick the winners before the starting gun, which makes no sense.

At the raceEveryone runsIn SQL: the window function computes a value for every row.
At the raceThe finishing boardIn SQL: the ROW_NUMBER, RANK or COUNT value each row now carries.
At the raceThe judge picks the podiumIn SQL: QUALIFY rn = 1 keeps only the rows you want.

Syntax, step by step

Step 1: the long way (what you learned in 3.1). The window goes in a subquery and the filter goes outside.

SELECT acct_id, txn_id, txn_date
FROM (
  SELECT acct_id, txn_id, txn_date,
         ROW_NUMBER() OVER (PARTITION BY acct_id ORDER BY txn_date DESC, txn_id DESC) AS rn
  FROM transactions
) t
WHERE rn = 1;

Step 2: the short way. Same result, no subquery. The window can live directly in QUALIFY.

SELECT acct_id, txn_id, txn_date
FROM transactions
QUALIFY ROW_NUMBER() OVER (PARTITION BY acct_id ORDER BY txn_date DESC, txn_id DESC) = 1;

Step 3: the de-duplication pattern. Memorise this shape. It appears in almost every data pipeline: "for each key, keep the newest row".

SELECT *
FROM some_table
QUALIFY ROW_NUMBER() OVER (PARTITION BY business_key ORDER BY loaded_on DESC) = 1;

QUALIFY can also use a window that is already named in the SELECT list, and it can combine conditions with AND and OR like WHERE.

Worked examples

Example 4: compare each row with its group. QUALIFY is not only for ranks. Here it keeps accounts whose balance is above the average of their type.

SELECT acct_id, acct_type, balance
FROM accounts
QUALIFY balance > AVG(balance) OVER (PARTITION BY acct_type);

Common mistakes

Watch out

Using RANK for de-duplication. If two loads share the same loaded_on, RANK gives both 1 and you keep two rows. ROW_NUMBER always keeps exactly one.

Wrong direction. ORDER BY loaded_on (ascending) keeps the oldest row. For "latest", write DESC.

Mixing WHERE and QUALIFY jobs. A plain filter such as txn_type = 'DEPOSIT' belongs in WHERE, so the window only ranks deposits. Putting it in QUALIFY ranks everything first and then filters, which gives a different answer.

SELECT DISTINCT is not de-duplication by key. DISTINCT removes rows that are identical in every column. Two loads of the same customer with different cities are not identical, so DISTINCT keeps both.

On Snowflake

QUALIFY is a Snowflake word

QUALIFY started in Teradata and Snowflake made it popular. It is not in standard SQL, and older engines such as MySQL, PostgreSQL and SQL Server do not have it; there you use the subquery form from Step 1. DuckDB, which runs the practice editor, supports QUALIFY with exactly the Snowflake syntax, so everything below works on both.

On Snowflake you will see this de-duplication pattern in almost every staging model, often written in dbt. Learn to read it at a glance: QUALIFY ROW_NUMBER() OVER (PARTITION BY key ORDER BY updated_at DESC) = 1.

Practice

Tables: accounts, transactions and a messy feed called customer_loads where the same customer can appear on several load dates. Use QUALIFY in every answer. Grading compares values only.

Key takeaway

Remember

QUALIFY filters after the windows run, like a judge reading the finishing board. The de-duplication pattern is ROW_NUMBER over the key, ordered by newest first, QUALIFY = 1. Use ROW_NUMBER, never RANK, when you need exactly one row.

Glossary

QUALIFY
A clause that filters rows using window function results.
De-duplication
Keeping one row per key and dropping the other copies.
Business key
The column(s) that identify a real-world thing, such as cust_id.
Latest record
The row with the newest timestamp for a key.
Order of evaluation
FROM, WHERE, GROUP BY, HAVING, windows, QUALIFY, SELECT, ORDER BY, LIMIT.
Staging table
A raw landing table that often holds duplicates before cleaning.
