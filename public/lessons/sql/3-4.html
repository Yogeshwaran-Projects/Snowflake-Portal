Recursive CTEs, gaps and islands

Climb an org chart one step at a time, build a calendar out of nothing, and find streaks and missing days in a balance history.

35 min Advanced Practice: 6 questions

By the end of this lesson you can

  • Write a recursive CTE with an anchor and a step
  • Walk a manager tree to any depth and find everyone under one person
  • Generate a calendar and find the dates that are missing
  • Use the "date minus row number" trick to find streaks (islands)

Definition

Key definition

A recursive CTE is a WITH query that refers to itself. It starts from an anchor row set and repeats a step that adds more rows, until the step adds nothing. "Gaps and islands" is the task of finding missing values (gaps) and unbroken runs (islands) in a sequence.

You met ordinary CTEs in Lesson 2.5. A recursive one has two parts joined by UNION ALL: the anchor (where to start) and the recursive step (how to get from the rows you have to the next rows). The engine repeats the step until it returns no new rows.

Think of it like climbing a family tree one step at a time

To list all of your ancestors you do not need to know them all at once. You start with your parents (the anchor). Then you ask "who are their parents?" (the step). Then you ask it again for those people, and again, until someone has no parent recorded. A recursive CTE does exactly this with rows. Gaps and islands is a different game: you look at a calendar of days you went to the gym and circle each streak of consecutive days (islands) and each break (gaps).

Syntax, step by step

Step 1: the smallest recursive CTE. Count from 1 to 5. The anchor gives 1. The step takes the previous row and adds one, while the number is below 5.

WITH RECURSIVE n AS (
  SELECT 1 AS num                      -- anchor
  UNION ALL
  SELECT num + 1 FROM n WHERE num < 5  -- step, with a stop condition
)
SELECT num FROM n;

The stop condition matters. Without WHERE num < 5 the query would run forever (engines stop it with an error after a limit).

Step 2: walk a tree. The anchor is the top manager (no manager_id). The step joins employees to the rows found so far, matching each employee's manager to a known person, and adds 1 to the level.

WITH RECURSIVE org AS (
  SELECT emp_id, emp_name, 1 AS lvl
  FROM employees WHERE manager_id IS NULL
  UNION ALL
  SELECT e.emp_id, e.emp_name, o.lvl + 1
  FROM employees e JOIN org o ON e.manager_id = o.emp_id
)
SELECT emp_id, emp_name, lvl FROM org;

Step 3: islands with the row-number trick. Sort the dates and number them 1, 2, 3. In an unbroken run, the date goes up by one and the row number goes up by one, so date minus row number stays the same. When a day is missing the date jumps but the row number does not, so the difference changes. Group by that difference and each group is one island.

WITH marked AS (
  SELECT acct_id, bal_date,
         DATEDIFF('day', DATE '2000-01-01', bal_date)
           - ROW_NUMBER() OVER (PARTITION BY acct_id ORDER BY bal_date) AS grp
  FROM daily_balances
)
SELECT acct_id, MIN(bal_date) AS island_start, MAX(bal_date) AS island_end, COUNT(*) AS days
FROM marked
GROUP BY acct_id, grp;

DATEDIFF turns the date into a plain day number so we can subtract the row number from it. The fixed start date does not matter; any date works.

Worked examples

Example 1: everyone under Suresh Babu (emp_id 2), at any depth. The anchor is "people whose manager is 2". The step keeps adding their reports.

WITH RECURSIVE team AS (
  SELECT emp_id, emp_name FROM employees WHERE manager_id = 2
  UNION ALL
  SELECT e.emp_id, e.emp_name FROM employees e JOIN team t ON e.manager_id = t.emp_id
)
SELECT emp_id, emp_name FROM team;

WITH RECURSIVE cal AS (
  SELECT DATE '2026-03-01' AS d
  UNION ALL
  SELECT d + 1 FROM cal WHERE d < DATE '2026-03-12'
)
SELECT d AS missing_date
FROM cal

Common mistakes

Watch out

No stop condition. A step without a WHERE (or a tree with a cycle) runs until the engine kills it.

UNION instead of UNION ALL. UNION removes duplicates on every pass and is much slower. Use UNION ALL unless you really need duplicates removed.

Different column lists. The anchor and the step must return the same number of columns in the same order with matching types.

Numbering rows across accounts. For islands per account, the ROW_NUMBER must have PARTITION BY acct_id, or account 103's rows continue account 101's count and the trick breaks.

On Snowflake

Two spellings, same idea

Snowflake accepts both WITH RECURSIVE and plain WITH for a recursive CTE. The practice editor (DuckDB) requires the word RECURSIVE, so the lessons always write it; that form works on both.

Snowflake also offers CONNECT BY for trees and a built-in GENERATOR table function for making rows from nothing (TABLE(GENERATOR(ROWCOUNT => 31))). Both are Snowflake-only; the recursive CTE works everywhere. Snowflake stops runaway recursion after 100 iterations by default; DuckDB keeps going until memory is exhausted, so always write a stop condition.

DATEDIFF('day', a, b) and date + 1 behave the same on both engines.

Practice

Tables: employees (a manager tree with 9 people) and daily_balances (two accounts, some days missing). Grading compares values only. Island questions want one row per island.

Key takeaway

Remember

Recursive CTE = anchor UNION ALL step, with a stop condition. It climbs trees and builds calendars. For streaks, number the sorted rows and group by date minus row number: equal differences mean an unbroken island.

Glossary

Recursive CTE
A WITH query that refers to its own name to repeat a step.
Anchor
The first SELECT: the starting rows.
Recursive step
The SELECT after UNION ALL that builds the next rows from the current ones.
Stop condition
The WHERE in the step that eventually returns zero rows.
Gap
A value that should be in a sequence but is missing.
Island
An unbroken run of consecutive values.
Calendar table
One row per date, used to find missing days.
DATEDIFF
Number of units (days, months) between two dates.
