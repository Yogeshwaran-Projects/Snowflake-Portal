JSON and semi-structured data

App events, API payloads and logs arrive as JSON. Learn to reach inside the curly braces, pull out fields, cast them to real types and turn arrays into rows.

30 min Advanced Practice: 6 questions

By the end of this lesson you can

  • Read a JSON document: objects, keys, nested objects and arrays
  • Pull one field out with a path, including nested fields
  • Cast JSON text to numbers so you can add and compare
  • Flatten an array into rows, in Snowflake and in the editor

Definition

Key definition

JSON is text that stores data as key: value pairs inside curly braces, with lists in square brackets. Semi-structured data is data like this: it has structure, but not fixed columns.

One event from a banking app might look like this:

{"type":"payment","amount":2500,"merchant":"GroceryMart",
 "tags":["grocery","upi"],"device":{"os":"iOS","app_ver":"5.2"}}
  • Key and value: "type":"payment". Keys are always text.
  • Nested object: "device":{...} is an object inside the object. Its path is device.os.
  • Array: "tags":[...] is a list. Items are numbered from 0.
  • Not every event has every key. A login has no amount. That is the "semi" in semi-structured.

Think of it like a card with a little pocket of extra notes

Every row in a table is a card with fixed boxes: id, customer, date. JSON is a small pocket glued to the card. Inside the pocket are sticky notes: "merchant: GroceryMart", "device: iOS". Some pockets hold a note with its own smaller pocket (nested), and some hold a list of notes (array). SQL cannot read a pocket as a box, so you need a way to say "open the pocket and read the note called merchant". That is a path.

On the cardThe pocketIn SQL: the JSON column (event_json here, a VARIANT on Snowflake).
On the cardA note in the pocketIn SQL: a path such as device.os that names one value.
On the cardA list of notesIn SQL: an array; FLATTEN or UNNEST turns each item into its own row.

Syntax, step by step

This is the one lesson where Snowflake and the practice editor (DuckDB) spell things differently. The ideas are identical. Learn both, and use the editor form in the practice below.

Step 1: pull a field. ->> returns the value as text. On Snowflake the colon does the same job, and ::STRING turns the VARIANT into text.

-- practice editor
SELECT event_id, event_json ->> 'type' AS event_type FROM app_events;
-- Snowflake
SELECT event_id, event_json:type::STRING AS event_type FROM app_events;

Step 2: go deeper with a path. $.device.os means "start at the root, open device, read os".

SELECT event_id, json_extract_string(event_json, '$.device.os') AS os FROM app_events;

Step 3: cast before you calculate. Everything comes out as text. Cast it to a number, or SUM will fail or sort "9" after "10000".

SELECT SUM(CAST(event_json ->> 'amount' AS DOUBLE)) AS total_paid
FROM app_events
WHERE event_json ->> 'type' = 'payment';

Step 4: arrays to rows. Each tag becomes its own row, so you can GROUP BY tag.

-- practice editor
SELECT event_id, UNNEST(json_extract_string(event_json, '$.tags[*]')) AS tag
FROM app_events WHERE event_json ->> 'type' = 'payment';
-- Snowflake
SELECT e.event_id, f.value::STRING AS tag
FROM app_events e, LATERAL FLATTEN(input => e.event_json:tags) f
WHERE e.event_json:type::STRING = 'payment';

Worked examples

Example 1: payments with amount and merchant.

SELECT event_id, cust_id,
       CAST(event_json ->> 'amount' AS DOUBLE) AS amount,
       event_json ->> 'merchant' AS merchant
FROM app_events
WHERE event_json ->> 'type' = 'payment';

Example 3: logins away from home. Join the JSON city to the customer's city. This is a simple fraud signal.

SELECT e.event_id, e.cust_id, c.city AS home_city,
       json_extract_string(e.event_json, '$.geo.city') AS login_city
FROM app_events e JOIN customers c ON c.cust_id = e.cust_id
WHERE e.event_json ->> 'type' = 'login'
  AND json_extract_string(e.event_json, '$.geo.city') <> c.city;

A missing key returns NULL, and NULL is never "not equal" to anything, so events without a geo block drop out on their own.

Common mistakes

Watch out

Wrong case in the key. JSON keys are case-sensitive. $.Device.os returns NULL, not an error, so the mistake is silent.

Forgetting to cast. event_json ->> 'amount' > 5000 compares text with a number. Cast first.

Using ->> 'device.os' for nesting. In the editor a plain key with a dot is looked up as one key named "device.os". Use the $.device.os path form for nested fields.

Treating NULL as missing data only. A key can be absent, or present with a JSON null. Both come back as SQL NULL. Ask the data owner which one it is before you report it.

On Snowflake

VARIANT, colon paths and FLATTEN

Snowflake stores JSON in a VARIANT column. You read fields with a colon and a path, then cast with two colons: event_json:device.os::STRING, event_json:amount::NUMBER, event_json:tags[0]::STRING. Keys with odd characters go in double quotes: event_json:"first-name".

Arrays become rows with LATERAL FLATTEN(input => event_json:tags); each item appears as value, with index for its position. If the JSON is loaded as text, wrap it once: PARSE_JSON(text_col). Useful helpers: TYPEOF(v), ARRAY_SIZE(v), OBJECT_KEYS(v), GET_PATH(v, 'device.os').

The practice editor uses DuckDB's JSON functions on a VARCHAR column: ->>, json_extract_string(col, '$.path') and UNNEST(... '$.tags[*]'). Same questions, different spelling. Each practice answer uses the editor form; the Snowflake form is shown above it.

Key takeaway

Remember

JSON is a pocket of notes on the card. Name the note with a path, cast it to a real type, and flatten arrays into rows. Snowflake: colon path, ::TYPE, LATERAL FLATTEN. Editor: ->>, json_extract_string, UNNEST.

Glossary

JSON
JavaScript Object Notation: text with key: value pairs in braces and lists in brackets.
Semi-structured
Data with structure but no fixed set of columns; keys can differ per row.
VARIANT
Snowflake's column type for JSON and similar data.
Path
The route to a value, such as $.device.os or device.os.
Nested object
An object stored as a value inside another object.
Array
An ordered list of values; positions start at 0.
FLATTEN / UNNEST
Turning each item of an array into its own row.
PARSE_JSON
Snowflake function that turns JSON text into a VARIANT.
