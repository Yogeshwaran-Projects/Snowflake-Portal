Definition

Key definition

Statistical SQL is using aggregate and window functions to describe, compare and reshape data inside the database, so only the small result travels to your notebook.

Pulling 50 million rows into pandas to compute a mean is slow and often impossible. The database can compute the mean, the median, the standard deviation and the correlation in seconds and hand you one row. Do the heavy lifting in SQL, then take the small table into Python for modelling and plots.

Think of it like quick statistics without leaving the library

You could carry every book home and count the pages yourself. Or you could ask the librarians, who already know the shelves, to tell you the average page count, the middle one, and how much the counts vary. They answer in seconds and you carry home a single index card. The library in the sky has librarians for every statistic you learned in your first stats course.

Step 1: describe a column. This is pandas describe() in one row.

SELECT COUNT(*) AS n, ROUND(AVG(balance), 2) AS mean_bal, MEDIAN(balance) AS median_bal,
       ROUND(STDDEV(balance), 2) AS sd_bal, MIN(balance) AS min_bal, MAX(balance) AS max_bal
FROM accounts;

Step 2: percentiles. PERCENTILE_CONT(0.9) is the value below which 90 percent of rows fall, interpolating between rows. WITHIN GROUP (ORDER BY x) says which column.

Step 3: z-scores with windows. A z-score is (value minus mean) divided by standard deviation. Use AVG() OVER () and STDDEV() OVER () with an empty OVER so every row sees the whole table.

SELECT cust_id, total_balance,
       ROUND((total_balance - AVG(total_balance) OVER ()) / STDDEV(total_balance) OVER (), 2) AS z
FROM (SELECT cust_id, SUM(balance) AS total_balance FROM accounts GROUP BY cust_id) t;

Step 4: buckets with CASE. Turn a score into bands for a report or a categorical feature.

SELECT CASE WHEN churn_score < 0.3 THEN 'LOW'
            WHEN churn_score < 0.6 THEN 'MEDIUM'
            ELSE 'HIGH' END AS risk_band,
       COUNT(*) AS customers
FROM scores
GROUP BY risk_band;

Worked examples

Example 1: median churn score per segment. Median resists outliers, which is why you report it next to the mean.

SELECT segment, ROUND(AVG(churn_score), 3) AS mean_score, MEDIAN(churn_score) AS median_score
FROM scores
GROUP BY segment;

Example 2: does wealth relate to churn? Join total balance to the score and ask CORR. A value near +1 means they rise together; near -1 means opposite; near 0 means no straight-line relationship.

SELECT ROUND(CORR(t.total_balance, s.churn_score), 3) AS corr_balance_churn
FROM (SELECT cust_id, SUM(balance) AS total_balance FROM accounts GROUP BY cust_id) t
JOIN scores s ON s.cust_id = t.cust_id;
corr_balance_churn
0.793

In this tiny sample, richer customers have higher churn scores. With 10 rows that is a hint, not a finding.

Example 3: pivot deposits by channel. One row per account type, one column per channel. The CASE form is portable; Snowflake's PIVOT is shorter.

-- works on Snowflake and in the editor
SELECT a.acct_type,
       SUM(CASE WHEN t.channel = 'APP'    THEN t.amount ELSE 0 END) AS app_total,
       SUM(CASE WHEN t.channel = 'BRANCH' THEN t.amount ELSE 0 END) AS branch_total,
       SUM(CASE WHEN t.channel = 'UPI'    THEN t.amount ELSE 0 END) AS upi_total
FROM transactions t JOIN accounts a ON a.acct_id = t.acct_id
WHERE t.txn_type = 'DEPOSIT'
GROUP BY a.acct_type;

-- Snowflake PIVOT
SELECT * FROM (SELECT a.acct_type, t.channel, t.amount
              FROM transactions t JOIN accounts a ON a.acct_id = t.acct_id
              WHERE t.txn_type = 'DEPOSIT')
PIVOT(SUM(amount) FOR channel IN ('APP', 'BRANCH', 'UPI'));

Common mistakes

Watch out

Integer division. 7 / 2 is 3 on Snowflake when both are integers. Multiply by 1.0 or cast to get 3.5. The editor returns 3.5 directly, so test ratios on Snowflake too.

NULL in aggregates. AVG and STDDEV skip NULLs silently, so the n they used may be smaller than COUNT(*). Report COUNT(col) next to the mean.

Correlation is not causation. CORR tells you two columns move together, not why.

Sampling before filtering. SAMPLE then WHERE gives a sample of the wrong thing. Filter first, then sample.

On Snowflake

Same functions, a few Snowflake extras

MEDIAN, PERCENTILE_CONT, STDDEV, CORR, MODE and APPROX_COUNT_DISTINCT are spelled the same on Snowflake and in the editor. Sampling differs: Snowflake writes FROM transactions SAMPLE (10) (percent) or SAMPLE (1000 ROWS); the editor writes USING SAMPLE 10 PERCENT. Samples are random, so the practice does not grade them.

Snowflake's PIVOT needs the list of values in IN (...) (newer accounts accept IN (ANY)). The editor has its own PIVOT syntax; the practice uses the SUM(CASE ...) form, which runs on both. APPROX_PERCENTILE(x, 0.9) is a fast estimate for huge tables, and HLL(x) is another name for APPROX_COUNT_DISTINCT.

When the summary is done, move on with Snowpark for Python or a notebook in Snowsight: session.sql("...").to_pandas() brings the small result to your laptop.

Glossary

Median
The middle value; half the rows are below it.
Percentile
The value below which a given share of rows fall; the 90th is PERCENTILE_CONT(0.9).
Standard deviation
How spread out values are around the mean.
Correlation
A number from -1 to 1 saying how strongly two columns move together in a straight line.
Z-score
(value minus mean) divided by standard deviation; how unusual a value is.
Pivot
Turning values of one column into separate columns.
Approximate function
A fast estimate such as APPROX_COUNT_DISTINCT, accurate within a small error.
Sample
A random subset of rows used to explore a huge table quickly.
